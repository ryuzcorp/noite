### Fixed

- **Merging a pull request with `deleteBranch` no longer waits for the deleted branch's preview environment to be wiped.** The ref move now returns as soon as the manifest flip and mirror update land, and the environment teardown (fleet stop, settle, S3 prefix sweep, credential revoke, row delete) runs in its own task. It used to run inside the merge/push request, where a fleet's graceful SIGTERM drain could hold the runner call past the control plane's 5 s bound; the abort then dropped the half-done wipe after the fleet entry had already left the process map, so nothing finished the stop or removed the row. The same ref-driven path also stopped holding the app's git push lock across the drain.
- **The queued wipe is keyed by the environment's immutable id, not by its reusable `(slug, label)`.** It re-reads the row and its app under the app's git push guard before wiping, so it follows a rename to the row's current slug and is a clean no-op when a purge or an earlier teardown already removed the row (the admin delete and the ref deletion now share it). A re-created branch environment is resolved by the newest row, never the one being torn down.
- **A boot sweep removes branch environments whose ref is no longer in the durable manifest.** A runner crash or shutdown between the ref move and the queued wipe used to leave the row behind, and the reconcile loop respawned a fleet for a deleted branch; the sweep runs before the loop and logs-and-continues on failure.
