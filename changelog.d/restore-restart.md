### Fixed

- `make restore` always brings the stack back. The restart now runs in an `EXIT` trap instead of inline, so a mid-restore abort after the stop (a bad archive, a tar error, a missing volume) still restarts the edge instead of leaving the stack stopped until a manual `up -d`. A restart that reports failure is verified against the running containers before it counts, and a genuinely failed restart exits nonzero without printing "restored" over a dead edge. Restarting stays right even when the volumes were already partially overwritten: the alternative is a stopped stack plus a half-restored one, and the operator can re-run the restore once the archive is fixed.
- The restore restart converges the same compose files the Makefile drives: on a multi install the restart keeps the `compose.multi.yaml` overlay instead of recreating the edge from the base file alone. A direct `sh docker/restore.sh` run computes the overlay with the same single/multi rule; under `make` the Makefile's file set is reused as is. The caller's `PROJECT`/`NOITE_TENANCY`/`BASE_DOMAIN` now win over `.env`, mirroring `make backup`.
- `make restore` with a spaced `FROM` no longer word-splits the directory, a tarball whose name is not a plain volume name is refused instead of being interpolated into the helper shell, and a backup directory with a `MANIFEST` but no `.tar` files fails before the stack is stopped instead of printing "restored" over an untouched install.
