### Fixed

- **A parked app can no longer come back as "running" with no fleet.** A health confirm that passed its gate while the sleep sweep was parking the same app could write `status='running'` onto the row the park had just marked `asleep_since`: the API and the UI then showed a running badge for an app that was parked and served nothing, and the sleep sweep refused to park it again. The confirm now claims the fleet's probe under the fleet state and re-checks it under the app's own lock, so a park that won the race always wins the write too.
- **A wake that fails now leaves the app asleep instead of "awake" with a dead route.** Waking used to clear the asleep flag before spawning the fleet; when the spawn or the health gate failed (no wake slot, a spawn error, a slow cold start) the next reconcile tick pushed a route straight at a port nothing listened on, and every request hit the retrying "Starting" page until the next tick happened to bring the fleet up. The flag is now cleared only once the fleet answers its health gate, so a failed wake changes nothing and the next request retries the wake hop.
- **A crash-looping or OOM-looping fleet backs off again instead of restarting every five seconds.** An exited-but-unreaped child used to count as "there is a process", so the reconcile loop skipped the restart path; making the fleet state explicit also means the crash and OOM chains now live in it, and a bug in the new machine had them reset to the first step on every retry. A fleet that keeps dying waits 5, 10, 20, 40 then 60 s (OOM kills up to 300 s), as designed.
- **A stop that lands while a fleet is spawning no longer resurrects that fleet.** The spawn adopted its new child unconditionally, so a stop or a park that ran during the spawn left a running child behind a row that said stopped or asleep — nobody supervised it, and for a parked app the sweep never retried. The child is now killed and the stale spawn dropped.
- **A fleet's health confirm can no longer be lost forever.** The in-flight confirm set leaked its key when a confirm task was cancelled, and a fleet that hit that leak could never be confirmed again: its status stuck at `building` for good. The probe is now a fleet state with its own deadline, reclaimed by the next tick after it expires.
- **`/ready` reports an isolation failure that happens after boot.** `/ready` used to print the boot snapshot's isolation verdict while reading the live cgroup probe, so a fleet whose cgroup limits were refused later, or an nft table flushed out from under the runner, still read healthy. The check now re-reads both probes on every answer.
- **`/ready`'s snapshot age no longer grows while the bucket is current.** An unchanged `VACUUM INTO` output skips the upload by design, but the "last upload" clock was not advanced by the skip, so the reported age grew without bound on an idle install even though the bucket was verified every 15 s.
- **A half-rehydrated deploy mirror is retried instead of looking present forever.** The rehydrate step is `git init --bare` followed by a `git fetch`; a crash between the two left a bare repo whose `HEAD` existed and no objects, and the "mirror exists" check then reported it ready for good, so every read failed with "unknown revision". A mirror is now ready only once it holds its `main` ref (or the marker written after a successful fetch).
- **A platform child is stopped promptly even when the stop lands mid-spawn.** A stop that arrived between the supervisor's loop check and its spawn sent SIGTERM to a child that did not exist yet, so the caller waited out the whole stop budget before the SIGKILL. The child is now signalled as soon as it appears, and its restart backoff is an explicit state instead of a `pid = 0` that also meant "stopped".

- **An app that crashes during a scale-to-zero wake no longer spawns once per request.** A failed wake used to stop the just-started fleet through the deliberate-stop path, which cleared its crash/OOM backoff, so a board that crashes on boot was respawned by every held request and never backed off. The exit is now observed (OOM verdict included) and the hold survives the park; a wake on a fleet that is still held answers the wake-failure status instead of spawning.
- **A spawn that nobody wanted any more can no longer kill another fleet.** When a stop or a park landed while a fleet was spawning, the failed spawn killed "the fleet with that key" — which by then belonged to whoever stopped it. It now kills only the child it created, its own process group, and cleans that spawn's cgroup leaf and OOM baseline.
- **`multi` refuses to spawn a fleet it cannot contain.** A fleet whose cgroup leaf could not be created was logged as a warning and run in the shared group, uncapped, while `/ready` kept saying containment was live. It now fails the spawn in `multi` (as a refused `cgroup.procs` move already did), and every leaf failure trips the install-wide containment status.
- **A fleet that dies before it is adopted still takes its crash backoff**, instead of being respawned on the next tick.
- **A deploy wake now wakes the fleet state too**, so the deploy's own spawn is not refused by a fleet still marked asleep.
- **A stop with no child still clears the fleet's cgroup leaf and OOM baseline**, so a parked or crash-held app that is deleted leaves nothing behind.

- **A parked app keeps its crash backoff across the park.** Parking a fleet now records the backoff it had (the state rests asleep _with_ its hold) and starts a new spawn generation, so a fleet that was crash-looping before it was parked is not respawned by the first request, and a spawn that was still in flight when the park landed cannot adopt its child or turn the park into a crash hold.
- **A parked app's wake spawns its fleet again.** The spawn claim that keeps two reconciles from spawning one fleet treated a `Waking` fleet as a claim already in flight, so a wake waited out the claim's five-minute TTL and the held request timed out (503/starting page). A wake, a park and a stopped fleet are all spawnable; only a live claim and an unexpired crash/OOM hold wait.
- **Two concurrent reconciles can no longer spawn one fleet twice.** A spawn is now claimed under the fleet's own lock (an epoch on its state entry), so a second caller waits instead of starting a second celld for the same fleet; a spawn that loses its claim kills only the child it started, and one that fails releases the claim instead of blocking retries.

- **A stop during a platform child's restart backoff now ends it at once.** The supervision task slept out the whole backoff (up to 30 s) before noticing the stop, so shutdown waited its full budget with no pid to kill.
- **A failed wake stops the fleet it started gracefully**, not with SIGKILL: celld releases the leases its cells hold on SIGTERM, and a killed cold start left the next wake waiting out the lease TTL.
- **A half-hydrated deploy mirror is retried at checkout**, not just at boot: a mirror whose hydrate was interrupted before its fetch looked readable and failed every read with "unknown revision".
- **A spawn that loses its claim no longer deletes the generation that owns the fleet** (its cgroup leaf, OOM baseline and engine proxy), and spawn epochs are process-wide, so a stopped and respawned fleet never reuses the number an in-flight older spawn holds.

- **A fleet's scaffolding (cgroup leaf, engine proxy, pid registration, OOM baseline) is cleaned by exactly one owner.** Cleanup now follows one rule everywhere: the generation that holds the key, or nobody, or a non-live owner (a park or stop that ran before the spawn created anything) may clean it; a newer live generation keeps its own. A spawn refused under a park no longer leaves its leaf, socket, registration and baseline behind, and a spawn that lost its claim no longer tears down the generation that won it.
- **A deploy's health-gate waiter no longer reads a crash-held or still-spawning fleet as "gone"**, which used to record the deploy as successful without the gate (and skip its migrations).
- **A late health probe can no longer resurrect a stopped fleet's entry**, which had made the cleanup skip that fleet's resources.

### Changed

- Runner fleet supervision, platform children, the state snapshot uploader, deploy-mirror rehydration and the isolation self-check now each have one explicit state type with a documented transition table and a single transition function, instead of inferring their state from map presence, `pid = 0`, a `dirty` flag, a `HEAD` file or four independent booleans. Wire values (REST JSON, DB strings, route table) are unchanged; `AllocError` now distinguishes an exhausted fleet port range from a database error instead of reusing `RowNotFound`, so the 409 message can say which it is.
