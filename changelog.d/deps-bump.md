### Operator action required

- **Re-pull the image to pick these up.** Every pin below is baked into `ghcr.io/ryuzcorp/noite`; a Compose install upgrades with `docker compose pull` (or the installer), and the bundled `rustfs` sidecar moves with `docker/compose.yaml`.
- **RustFS 1.0.3 → 1.0.5 reads existing data in place.** The upgrade was exercised on a private stack: a bucket written by 1.0.3 (a `git/` bundle and a telemetry Parquet object) lists, reads, writes and deletes unchanged under 1.0.5 on the same volume. RustFS's 1.0.5 notes require every node to finish the upgrade before pool changes; a single-node install has nothing to sequence, but do not add or remove disks mid-upgrade. RustFS 1.0.4/1.0.5 nodes only answer a `DELETE` with `503` while older nodes are still up, so if you run more than one node, finish the upgrade before deleting apps.
- **DuckDB 1.5.6 → 2.0.0 changes the CLI asset name, not the queries.** The image now installs `duckdb-cli-linux-<arch>.tar.gz` (1.x shipped `duckdb_cli-linux-<arch>.zip`); the telemetry SQL was re-run against 2.0.0 (settings, `read_parquet`, `strftime` on `TIMESTAMPTZ`, `COPY … zstd`, `SET VARIABLE`), so no operator step. DuckDB 2.0 writes a newer database format, but Noite never opens a database file — every pass is in-memory.

### Changed

- **Every npm dependency, Rust crate, Go module and baked-image pin moves to its latest release.** UI: `void` 1.3.0 → 1.8.0, `@ilha/void` 0.1.5 → 0.1.6, `effect` 4.1.0 → 4.1.4, `better-auth`/`@better-auth/*` 1.7.14 → 1.7.22, `@pierre/diffs` 1.5.2 → 1.6.4, `@pierre/trees` 1.0.0-beta.6 → 1.0.0, `vite` 8.3.5 → 8.3.8, `tailwindcss`/`@tailwindcss/vite` 4.3.3 → 4.3.5, `@playwright/test` 1.64.1 → 1.65.0, `@cloudflare/workers-types` and `@types/bun` to their current releases; lint tooling `oxlint` 1.90 → 1.93, `oxfmt` 0.75 → 0.78, `ultracite` 8.0.1 → 8.2.0. Void sandbox: `void` 1.5.0 → 1.8.0 (with `VOID_VERSION` and its lockfile). CLI: `@effect/platform-node`/`effect` 4.1.0 → 4.1.4, `@types/node` 26.6.5 → 26.6.6. Website: `blume` 2.2.6 → 2.2.7.
- **Runner crates move to their latest releases** (`cargo update` plus `rusty-s3` 0.10.2 → 0.11.0, which made every `ListObjectsV2` `Contents` field optional). A listing now fails with `s3 LIST object <key> has no <field>` when a store omits a required `LastModified`, `Size` or `ETag`, instead of fabricating a version (`git_store` keys objects by ETag) or a zero size.
- **The edge module builds against Caddy 2.11.9** (from 2.11.7), matching the image's `CADDY_VERSION`, with its Go module graph refreshed.
- **Image pins:** Node 24.22.0 → 24.22.3, jup 0.6.5 → 0.6.6, npm 12.2.1 → 12.2.2, pnpm 12.15.0 → 12.18.0, Docker CLI 29.9.2 → 29.9.3, RustFS 1.0.3 → 1.0.5, DuckDB 1.5.6 → 2.0.0 (esbuild stays 0.28.2; celld 0.6.3-ryuzcorp.8 is the newest fork tag; the bun base images stay on the floating `1.4` line). The runner's `BUNDLED_NPM_VERSION`/`BUNDLED_PNPM_VERSION` name the same npm/pnpm releases the image seeds.
- **The control bundle's deploy-root `wrangler.json` is written by a build step, not a Vite hook.** void 1.8 closes its environments in an order that ran the old `closeBundle` plugin before `dist/ssr/wrangler.json` existed, so it returned early and the image shipped without `dist/wrangler.json`; the runner then refused the baked bundle (`no wrangler config under /opt/noite/control/dist`) and `/ready` never passed. `bun run build` now runs `scripts/emit-celld-config.ts` after `vite build` returns, and a missing SSR manifest fails the build instead of shipping an undeployable control plane.
- **`oxlint` 1.93's new `promise/prefer-catch` rule** covers the two-argument `then(onFulfilled, onRejected)` form the Void sandbox's completion listeners and serialization tails use deliberately; their existing `oxlint-disable-next-line` markers now name both rules, and the control server's best-effort rollback/cleanup reads as a `try`/`catch`.
