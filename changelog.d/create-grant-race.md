### Fixed

- Creating an app no longer fails (or deletes the app it just created, cancelling a template import) when the sidebar's grant-less-creator heal writes the creator's admin grant at the same moment. The grant write's insert is now conflict-safe on the unique `(appId, userId)` row — the loser reads the winner's row instead of throwing — and a create whose grant fails but leaves the caller an admin keeps the app. A demotion through that path still applies the same last-admin guard the update path does.
- A database failure no longer echoes the SQL text, the bound parameters or the schema objects it names into a user-facing 422, an MCP tool error or a runner-failure message: a wrapped query error reads "Database query failed" (the create path answers "Could not record your access to the app", the invite and role paths say the collaborator was removed meanwhile), and the create/MCP boundaries unwrap it through the same helper. The server log keeps the cause chain, but a query wrapper's own stack — the statement plus every bound parameter, which an auth-table write would put credentials in — is replaced with "<name>: query failed". The same helper now backs every log sink on these paths: better-auth's own logger (its internal catches — the session lookup, key verification, passkeys — logged the raw statement and a session token) and a non-API failure, which is rethrown past the router's raw log to `handleAuth`, which answers a generic 500; the recovery-code mint; the git-auth, ingest, MCP and source key lookups and role verdicts; the apps SSE poll; `requireAdmin`; the ban/unban key sweeps; and the telemetry fact count.
