### Changed

- **The image no longer ships the DuckDB CLI, and the runner no longer has a DuckDB-shaped configuration.** `docker/install-sidecars.sh` installs only esbuild (its pin guard and the arm64 image leg follow), and `RUNNER_DUCKDB_MEMORY_MB`, `RUNNER_DUCKDB_THREADS` and `RUNNER_DUCKDB_TEMP_MB` are gone from the runner's config, `.env.example`, the compose file and the docs: telemetry Parquet is read and folded in-process with a bounded working set (one 256 MiB object at a time), so there is no per-pass memory cap or spill directory left to size.
- **The dead telemetry tables are dropped on boot.** `metrics.sqlite` no longer defines `app_metric` (minute buckets), `app_device_stat`, `app_path_stat`, `app_ref_stat` (access-log analytics) or `app_span_stat` (hourly span stats), and their writers and prunes are removed with them. Nothing has read those tables since the hourly counters replaced them; attaching the database now runs an idempotent `DROP TABLE IF EXISTS` for each, so an upgraded install stops carrying them on its first boot and a fresh install never creates them. The pages go to SQLite's freelist and are reused by later metrics writes — the file itself does not shrink (nothing vacuums `metrics.sqlite`). `app_hour`, `app_hour_lat`, `app_log`, the watermarks, the compaction marks, the error tables and `metric_version` are unchanged.
- The docs, `SPEC.md`, `README.md`, `AGENTS.md` and the environment-variable tables describe the in-runner reader; the `make usage` counter section and the runner's `duckdb` spawn counter, which the previous layer already stopped feeding, are gone from the docs.

### Operator action required

- Remove `RUNNER_DUCKDB_MEMORY_MB`, `RUNNER_DUCKDB_THREADS` and `RUNNER_DUCKDB_TEMP_MB` from your `.env`/compose environment. They are ignored rather than fatal (the runner reads only the variables it knows and compose no longer forwards them), so an unchanged environment file does not break the upgrade — but the settings no longer do anything.
- The first boot after the upgrade drops the five retired telemetry tables from `metrics.sqlite`. No other table is touched and nothing needs to be done by hand. Their pages move to SQLite's freelist and are reused by later metrics writes; the file does not shrink on disk.
