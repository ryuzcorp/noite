### Fixed

- **`make dev`/`make dev-host` build the Void sandbox controller bundle, so sandbox apps deploy on a dev stack.** The dev overlay pointed `VOID_SANDBOX_BUNDLE_DIR` at the mounted `apps/void-sandbox/dist` and left building it to the developer, so a fresh or updated checkout (and the owner's `https://noite.local` stack) failed every app that declares a sandbox at `celld deploy` with `sandbox controller bundle incomplete at /opt/noite/void-sandbox-src/dist: /opt/noite/void-sandbox-src/dist/worker.js is missing`. `docker/dev-sandbox.sh` now compiles the bundle inside the container before the runner starts and again whenever `apps/void-sandbox` changes, publishing it at the image's own `/opt/noite/void-sandbox` through an atomically swapped symlink, so a mid-session edit reaches the next deploy; a failed rebuild withdraws the bundle instead of leaving an older controller to be deployed, and a `package.json` that drifts past its lockfile re-runs the frozen install and fails loudly. The package is mounted read-only: the source copy, its `node_modules` and the build stay in the container, and nothing is written back into the checkout. The deploy error now names the recovery for each case — re-run the installer for a release image, `make dev`/`make dev-host` for a dev stack — instead of a manual `bun run build`.
