### Operator action required

- Fleet nodes are now non-dumpable (celld `0053`): no core dump comes out of a node, a non-root debugger or profiler can no longer attach to one (root tools are unaffected), and anything reading a node's `/proc/<pid>/environ`, `mem` or `maps` as the fleet uid now gets `EACCES`. The runner's CPU sampler reads only `/proc/<pid>/stat` and `/proc/<pid>/task/<pid>/children`, which stay readable — verified against a non-dumpable process in a container with the image's exact capabilities — so the app CPU metrics keep populating. Nothing to do unless you collect core dumps from tenant fleets or attach to them as a non-root user.
- The bucket credential needs `s3:DeleteObject` on `cells/`: an eviction that publishes a handoff snapshot now deletes the per-cell L0/L1 objects it supersedes in the background, one single-key `DeleteObject` per key (celld `0057`). The read-write state grant already covers it; only an install with a custom least-privilege bucket policy that allow-lists actions may need to add it. A refused delete only leaves superseded objects behind for epoch GC — it never fails the eviction.

### Changed

- The image ships celld `0.6.3-ryuzcorp.12` from the [ryuzcorp/celld](https://github.com/ryuzcorp/celld) fork. That is upstream celld 0.6.3 plus the fork's patches, built with celld's full upstream test suite, pinned by digest and published with SLSA provenance attestations. Upstream celld ships only security fixes from 0.6.x on, so the fork carries the patches. Nodes on `.9` through `.12` share a bucket with no migration: there is no API or CLI change, and the bucket format `.11` and `.12` publish (3) is readable by older nodes.
- Fewer bucket requests and smaller stored state, no action: a bucket-posture eviction skips the visibility LISTs for prefixes this residency uploaded itself (`0054`); a lone fleet-posture node backs its `nodes/` scan off to the 30 s maintenance tick instead of retrying every second, so a node that starts next to it is recruited within ~30 s (`0055`); concurrent bucket-posture writes on one cell share one `cells/<cell>/own.json` read per cell epoch instead of one per write (`0056`); and the handoff-snapshot eviction deletes the superseded per-cell L0/L1 objects (2.47 MB → 0.57 MB stored on 200 short-lived Durable Objects) (`0057`).
- An eviction skips the full-database handoff snapshot when the Durable Object's whole history fits in a short chain of objects written during this activation (celld `0078`, modelled on ClickHouse MergeTree's lazy merges). The next activation restores that chain instead. Billed write requests fell by about 10% on the fork's 200-agent benchmark (1934 → 1734) with unchanged write latency, and a short-lived Durable Object no longer re-uploads its whole database when it is evicted. Durable Objects restored from an earlier activation keep the snapshot.
- Lower memory, no action needed:
  - a node returns freed C heap to the OS sooner after evictions (`0065`); post-drain RSS fell by about 10–15 MiB in the fork's benchmark;
  - a deployment generation projects its `/bundle` tree once instead of once per isolate (`0067`).
- An eviction proves a journaled epoch with one HEAD request instead of a prefix LIST (`0061`).
- New opt-in knobs; Noite sets none of them:
  - `CELLD_BUCKET_BUNDLES=1` groups concurrent bucket-posture writes into shared bundle objects. It cuts billed write requests by ~40% on many-agent workloads, but roughly doubles write-ack latency (p50 210 → 445 ms at R2-like latency), so it stays off.
  - `CELLD_SQLITE_CACHE_KB` caps the per-connection SQLite page cache.
  - `CELLD_C_TRIM_MB` tunes the heap-trim threshold.
- Deployment artifact reads can optionally use their own credential (celld `0052`): with the `CELLD_DEPLOY_AWS_*` trio set, a node serves `deploy/` and `deploy-blobs/` through a second S3 client, so a read-only deployment grant plus a read-write state grant keeps a copied credential from publishing. Noite leaves the trio unset and keeps one credential for everything, exactly as before; a managed or control-plane node must not set it.
