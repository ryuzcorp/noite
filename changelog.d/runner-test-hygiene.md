### Fixed

- Runner tests no longer leak scratch directories into `/tmp`: every test helper that builds a temp dir now returns the new `testutil::TempDir` guard, which removes itself on drop — including on a failing assert. Previously each `void_migrate` run leaked its fixtures (`cap-total` alone drops 70 MB per run; gigabytes had piled up and broken unrelated tests through the `/tmp` quota), and the `api`, `prs`, `forge`, `limits`, `domains`, `errors`, `apps`, `source`, `import`, `package_manager`, `metrics`, `build_output`, `generated_config`, `worker_vars`, `void_deploy`, `void_sandbox` and `void_cohost` harnesses all leaked on at least the panic path. A full suite run now leaves `/tmp` exactly as it found it.
- `host::exec::tests::run_cmd_timeout_kills_grandchildren` no longer fails when an earlier aborted run orphaned its `sleep 31337377` marker: the marker is unique per test-process run now, and a `KillMarkerOnDrop` guard kills this run's marker processes on every exit path. Root cause was the test, not the group kill — `run_cmd`'s `killpg` cannot miss a grandchild that stayed in the step's process group (no `setsid`/`setpgid` in the script, no spawn/kill race across the 2 s timeout, the pid is pinned by the pending wait), but a killed test binary never reaches the kill, and the fixed marker then poisoned every later run's `/proc` scan until someone killed the stale sleeper by hand. The two supervisor group-kill tests got the same treatment.
