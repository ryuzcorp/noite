### Operator action required

- **AWS installs using scoped keys (`NOITE_CREDENTIAL_PROVIDER=aws`) grant one more IAM permission, and minted users move under an install tag.** The runner now reconciles the store against its `scoped_credential` rows and revokes orphaned users, which needs `iam:ListUsers` on the runner's keys (IAM allows no narrower resource for this call: add a statement with `"Action": ["iam:ListUsers"]` and `"Resource": "*"`, as shown in [Storage](apps/website/docs/self-hosting/storage.mdx#scoped-bucket-keys-per-store)) plus `iam:GetUser` on the names it mints (when a user name collides, the runner reads it back and only clears a user under its own path). Every minted user now carries this install's tag — a short hash of the bucket and region shown as `install_tag` in `/ready` — in its IAM path (`/noite/<tag>/`, instead of the old default `/`) and its name (`noite-<tag>-…`). Users minted before this change stay under `/` with untagged names and are never touched by the new sweep; revoke, rename and delete keep working for them by handle. Without `ListUsers` the sweep logs a warning and revokes nothing; everything else keeps working.

### Added

- **The store is reconciled against the credential rows.** At boot and every ten minutes the runner lists the principals it manages (`list-users` on RustFS/MinIO, paginated `ListUsers` on AWS, nothing on R2/`root`) and revokes any with no `scoped_credential` row, live or revoking — the orphans a crash inside the snapshot loss window leaves behind. Every install mints under its own tag (a short hash of the endpoint plus bucket, or bucket plus region on AWS, computed at boot so it survives DB loss), stamped into MinIO canned-policy names and AWS user names and paths; the sweep requires the tag back, so two installs sharing a store or account never revoke each other's live keys, and restoring an older snapshot revokes keys minted after it (restart fleets after a restore). `/ready` gains an additive `credential_sweep` object (install tag, seconds since the last run, total revoked, last listing error truncated to 300 chars) and `make doctor` reports it.

### Fixed

- **A lost `scoped_credential` row no longer leaves its key live forever.** When a mint's row never landed (a crash inside the snapshot loss window, then a restore), the old revoke path — which only acts on rows — could never reach the key, and the next mint for the scope handed out a second key while the first stayed valid. The new orphan reconcile above revokes those keys. Only principals carrying this install's tag can ever be revoked (MinIO keys whose attached policy is exactly the tagged per-key name, AWS users named `noite-<tag>-…` under exactly `/noite/<tag>/`); foreign users, other installs' keys, pre-tag keys and the operator's keys are never touched. A mint that hits an existing user name reads it back first and only clears a half-minted user under its own path — anything else fails loudly instead of deleting a foreign user. The listing runs without the mint lock (each candidate is fenced instead), and a listing failure revokes nothing.
