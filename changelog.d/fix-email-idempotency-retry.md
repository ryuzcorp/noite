### Fixed

- **A failed `/email/send` no longer becomes permanent for its idempotency key.** Every outcome was recorded for 24 h, so a transient SMTP failure (a relay refusal, a timeout, or an `outcome_unknown` after the message data left) replayed for the whole TTL: retrying with the same key could never actually retry. Only an attempt where a delivery was observed accepted is recorded now — a full accept and a partial accept replay byte-identically and send nothing, which is what keeps a retry from re-sending to the recipients the relay already accepted; a failed, outcome-unknown or rejected-only attempt records nothing, so the retry really retries. An `outcome_unknown` retry can duplicate a message the relay already queued (the per-recipient error already says to check the relay log first), which is the same at-least-once limit the endpoint documents for concurrent sends. Records written before the upgrade still replay their failure until they expire (at most 24 h). The `/email/send` request and response JSON is unchanged.
