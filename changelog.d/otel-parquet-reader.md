### Changed

- **The runner reads celld telemetry Parquet itself.** Errors and Logs no longer come from a DuckDB CLI query: the ingest lists each chunk's hour directories through the S3 client, decodes only the columns it needs with the `parquet` crate (no `arrow`; zstd, snappy, gzip and lz4 are all readable), and keeps the same newest-5000-log-lines and top-200-failed-span-group rules. Failed-span groups are aggregated one event hour at a time with compact 16-byte trace ids and a 1,000,000-distinct-trace ceiling per group and hour (one warning), so a hot error loop can no longer grow the runner's heap without bound; a corrupt or foreign object is skipped with a warning instead of holding the fleet's watermark. Watermarks, chunk planning, per-fleet fault isolation, replace semantics and the replay CLI are unchanged.
- **Hourly Parquet compaction is written by the runner.** The scheduled fold that keeps an hour to one object (and deletes the sources only after the copy is proved) now unions the inputs with the Parquet writer instead of `COPY` through DuckDB, preserving every input column by name and the unsigned annotations celld writes (`kind` UTINYINT, `http_status` USMALLINT). An hour whose fold would produce an object the ingest refuses (inputs over a 160 MiB budget, or an output over the 256 MiB cap) is left raw — sources kept and readable — and never blocks later hours. DuckDB is no longer invoked by the ingest or the compaction; the binary stays in the image until the follow-up removal.
- `make usage` no longer prints the `[duckdb]` counter section (the runner never runs DuckDB now).
