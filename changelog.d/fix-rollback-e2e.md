### Fixed

- **The header Deploy menu no longer closes (and loses its rollback) when the app detail lands.** A page load paints the header from the last snapshot first ("Not deployed", actions `Visit · Deploy`); the fresh detail then inserts the Stop/Start control _before_ the Deploy dropdown, and ilha's positional morph paired that new button with the dropdown's `div` and replaced the subtree — which closed an already-open menu and dropped the rows the menu had loaded. The action row is keyed now, so the morph moves the live nodes instead of replacing them, and the rows behind "Roll back to …" live in a shared resource (`deployHistory`, refetched as the menu opens) rather than in one component instance, so no render can lose them. This is the `rollback.spec.ts` e2e flake.
- **A rollback is no longer undone by the git-tip sweep.** The fallback sweep (`RUNNER_TIP_SWEEP_S`, 60 s) deployed the branch tip whenever `last_deploy_sha` differed from it, so rolling back to an earlier release silently served the tip again within a minute — the same e2e flip-flopped the menu's target, and the "restored" revision stopped serving. The sweep now only deploys a tip whose sha has never been deployed successfully in that target: an already-built release the live sha moved off is the operator's choice, while pushes and explicit redeploys deploy on their own trigger.
