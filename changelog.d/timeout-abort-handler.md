### Fixed

- **The route timeout now aborts the downstream work, not just the response.** The 15 s action bound (`/mcp`: 65 s) used to answer its JSON 504 while the stuck handler kept running, so a slow write or action continued after the caller saw an error and a retry could double-apply it. Each bounded request now runs under its own `AsyncLocalStorage` signal, aborted with a typed reason when the bound fires, and the runner calls fold that signal in — after the 504 no further outbound runner call starts for that request and in-flight ones reject. The store is strictly per request, so overlapping requests can never observe or abort each other's bound. D1 needs no rollback: the control plane runs no interactive transactions, so every control write is one statement or one `db.batch`, which D1 applies atomically. Exempt routes (streams, downloads, static) are unaffected, and a client disconnect aborts through the same controller with its own typed reason, ending quietly instead of logging an "Internal error".
- **Retrying an admin app delete after the runner row is already gone no longer strands grants.** A 404 from the runner delete is treated as already gone: the grants and pending invitations still drop, and the delete answers ok instead of stranding rows a retry would 404 on again.
