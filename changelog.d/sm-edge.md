### Fixed

- **A Caddy config reload no longer rolls the edge's routes back to the table file.** The edge loads its route table from a file at boot and the runner pushes updates to it. A reload re-read the file, so a table the runner had pushed since that file was written was replaced by the older one, and the older routes served until the next push. Both writers now install through the same generation ordering, so the newest table keeps serving.
- **The edge no longer serves a table it has already released.** When the last edge instance shut down (a Caddy reload or stop), the installed table and the "loaded" flag stayed while the rate limiter was released. Requests were refused as if the edge were still booting, and a later provision served the stale table. The shared state is now an explicit `booting`/`loaded`/`draining` phase that owns its table, limiter and prober together; a draining edge has nothing left to route with.
- **A table pushed under a generation that is already live now applies when its content differs.** The runner only re-pushes identical bytes under a generation, so an equal generation with different routes is a correction; it used to be dropped as a no-op and the old routes kept serving.
- **The edge refuses route combinations its static config cannot act on.** A gate on a tenant or custom host, a wake on the control plane, a rewrite outside git and the fallback page, or rate limits on a deny route now fail the push with 400 instead of being silently ignored (which would leave the route doing something other than what its table says). Every table the runner emits today still validates.

### Changed

- **Explicit state machines in the edge module.** Route behavior is derived once into a closed `Mode` (deny, proxy, fleet, environment, parked, preview, fallback, plus wake/gate/hold) instead of being re-inferred from the kind string in each handler; upstream readiness is a three-way `Health` (untracked/down/up) and a readiness hold reports `Ready`/`Abandoned`/`Timed out`; table installation reports `Applied`/`Stale`/`Identical`/`Invalid`. The route-table JSON the runner pushes, the `{http.vars.*}` values the static config reads, and every response status and body are unchanged.
