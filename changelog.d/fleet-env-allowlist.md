### Changed

- Fleet spawns (tenant fleets and the control node) now start from `env_clear()` plus an explicit allowlist (`host::fleet_env`) instead of inheriting the runner's environment: `PATH`, a writable `HOME`, `TMPDIR`, the fleet's store credentials, the `CELLD_*` knobs the runner sets, the fleet's operator token, `RUST_LOG`, the fleet's own `DOCKER_HOST` socket when sandboxing is on (a dead socket otherwise, so celld never probes well-known daemon paths), and two operator settings passed through when set: the custom-CA trust files (`SSL_CERT_FILE`, `SSL_CERT_DIR`) and the proxy settings (`HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY`, both cases), which celld's store, peer and control clients keep honoring. The tenant's own vars are applied first, so the platform wins every key it sets, including `PATH`, `HOME` and `RUST_LOG`, which a tenant setting used to override. `RUNNER_TOKEN`, the ambient credential chain and operator-global `CELLD_*` no longer reach fleets, and the `env_remove` lists are gone.
- `S3_ENDPOINT` userinfo is stripped once at runner start and a warning is logged: every store client signs with the access keys, so URL credentials never authenticated anything, but they used to travel on into fleet argv and env, `celld` CLI env, release-command env and the control Worker.
- Tenant settings named `SSL_CERT_FILE`/`SSL_CERT_DIR` or any proxy var (both cases) are now reserved: like every reserved name they are dropped (with a server-side warning) from the fleet, build and release process env, while Worker `vars` are unaffected. A tenant build that relied on its own `HTTP_PROXY` for `bun install` no longer gets it.
- The runner logs a warning at boot naming any `CELLD_*` in its own env that no fleet will see (`CELLD_BIN` and `CELLD_ADVERTISE`, which the runner reads itself, excepted).
- Build steps and every `celld` CLI subprocess were audited for the same treatment: both already start from `env_clear()` (`exec::run_sandboxed`, `exec::run_cmd`/`run_cmd_stdin`), so no change was needed there.

### Operator action required

- Operator-global `CELLD_*` (and any other runner-env value a fleet used to inherit, such as a global `RUST_LOG` or `DOCKER_HOST`) no longer reach fleets. Fleets are configured through the `RUNNER_FLEET_*` knobs only now; the boot warning names any `CELLD_*` that is ignored. The only inherited values left are the custom-CA trust files and the proxy settings.
- Platform store credentials must be static long-term keys: fleets no longer inherit an ambient credential chain (`AWS_SESSION_TOKEN`, web identity, EC2 instance role). celld's store client never used a profile, and tenant fleets always ran on the static scoped keys, so only a control node relying on such a chain is affected.
- Credentials in `S3_ENDPOINT` userinfo are ignored (they never authenticated); remove them from the URL to silence the warning. The scoped-key install tag hashes the endpoint, so an install whose `S3_ENDPOINT` carried userinfo re-tags once, like any endpoint change: its earlier scoped keys read as foreign and are not revoked by the sweep, so delete them at the store by hand.
