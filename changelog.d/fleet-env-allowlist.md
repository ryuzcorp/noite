### Changed

- Fleet spawns (tenant fleets and the control node) now start from `env_clear()` plus an explicit allowlist (`host::fleet_env`) instead of inheriting the runner's environment: `PATH`, a writable `HOME`, `TMPDIR`, the fleet's store credentials (the endpoint without userinfo), the `CELLD_*` knobs the runner sets, the fleet's operator token, `RUST_LOG`, the fleet's own `DOCKER_HOST` socket when sandboxing is on (a dead socket otherwise, so celld never probes well-known daemon paths), and the custom-CA passthrough (`SSL_CERT_FILE`, `SSL_CERT_DIR`) when set — plus the tenant's own vars, applied first so the platform wins every key it sets. `RUNNER_TOKEN`, the ambient credential chain and operator-global `CELLD_*` no longer reach fleets, and the `env_remove` denylists are gone. The control node now gets its store credentials and log filter explicitly (both used to arrive by inheritance), and tenant `PATH`/`HOME`/`TMPDIR` values no longer take effect on the fleet process.
- Tenant settings named `SSL_CERT_FILE`/`SSL_CERT_DIR` or any proxy var (`HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY`, both cases) are now refused as reserved: the platform sets TLS trust only when the operator configured it and never passes proxy env, so ordering alone could not win those names.
- Build steps and every `celld` CLI subprocess were audited for the same treatment: both already start from `env_clear()` (`exec::run_sandboxed`, `exec::run_cmd`/`run_cmd_stdin`), so no change was needed there.

### Operator action required

- Operator-global `CELLD_*` (and any other runner-env value a fleet used to inherit, such as a global `RUST_LOG` or `DOCKER_HOST`) no longer reach fleets. Fleets are configured through the `RUNNER_FLEET_*` knobs only now; a `CELLD_*` value set directly on the container is silently ignored by every fleet. The only inherited values left are the custom-CA trust files (`SSL_CERT_FILE`, `SSL_CERT_DIR`), so a BYO store behind a private CA keeps working.
- Proxy env (`HTTP_PROXY` and friends) no longer propagates to fleets: store and Worker traffic goes direct. An install whose store egress requires a proxy needs an explicit platform knob for that (not shipped here).
- Platform store credentials must be static long-term keys: fleets no longer inherit an ambient credential chain (`AWS_SESSION_TOKEN`, web identity, EC2 instance role), and the `celld` CLI subprocesses never carried a session token either.
- Credentials embedded in `S3_ENDPOINT` userinfo no longer reach fleets (the endpoint is passed without userinfo); move them into the configured access keys.
