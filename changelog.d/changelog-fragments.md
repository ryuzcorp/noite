### Added

- **Release notes live in `changelog.d/` fragments, one file per PR.** Concurrent PRs no longer rebase-conflict on `## [Unreleased]` (which stays empty): each PR adds `changelog.d/<unique-topic>.md` using the CHANGELOG's own `### <Section>` headings with `- ` bullets. `bun docker/check-changelog.ts` rejects unknown sections, bullet-less fragments, and any `[Unreleased]` entries; the release PR runs `bun docker/changelog-release.ts <version> [date]` to assemble the dated section (canonical order, `### Operator action required` always present) and delete the fragments.
- **`bun docker/pr-ready.ts` runs every local gate before pushing.** It detects changed areas against `origin/main`, runs `bun run check`, the runner/UI gates, `check-changelog`/`check-versions`, and a `merge-tree` conflict check (conflicting PRs get no CI), then prints a summary table. `--skip-build` skips the UI bundle build for fast iterations; a missing `changelog.d/` file on runtime changes warns without failing.
