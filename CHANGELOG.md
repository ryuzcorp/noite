# Changelog

Noite installs follow releases, not `main`. Pick a channel with `NOITE_IMAGE` (or `NOITE_VERSION` for the installer): `alpha` gets every promoted release, `stable` only final ones, and a version tag (`0.1.0-alpha.1`) holds an install in place. A release starts as a GitHub pre-release that only `run.sh | bash -s install --pre` installs; marking it as a full release moves the channels. `edge` and short-SHA tags are for CI and rollbacks.

Every release has an **Operator action required** section, even when it is "None". Read it before upgrading: an upgrade restarts the runner and every tenant fleet cold-boots, so batch upgrades.

Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [0.1.0-alpha.27] - 2026-11-08

### Operator action required

- The first push to each repository after upgrading rewrites its `git/{slug}/MANIFEST.json` as manifest v2. This build reads v1 and v2; an older build reads only v1. Do not roll back to an image older than this release after pushing: git pushes to already-upgraded repositories fail until the `git/` prefix is restored from a backup. No manual step is needed to upgrade.

### Changed

- The git storage/mirror/manifest engine is now the published `ryuz_git` 0.2 crate (crates.io, same repo family) instead of runner-local modules: all manifest/mirror/publish operations go through `Wal<RefsCodec>` (manifest CAS, immutable tip bundles, mirror rebuilt from the manifest), and `host/git_manifest.rs` is deleted. Role/collaborator auth and branch protection (`git_policy.rs`), smart-HTTP routes, tip-bundle layout, deploy hooks, paths, errors and logs are unchanged.
- Manifests are v2 on the first push after this change (forward-only): `RefsCodec` reads the existing v1 manifests and writes v2 (same refs plus sequence/revision metadata). No migration step; old mirrors rehydrate from the manifest as before.
- S3 access for git goes through a new `host::git_store::ObjectStore` adapter over the native S3 client (rusty-s3 signing + one reqwest pool): conditional writes (`If-None-Match: *` create, `If-Match` CAS update), conditional/freshness/range reads, and versioned deletes. 404 maps to missing while transport errors, timeouts and 5xx stay retryable, so an unreachable store is never mistaken for "no manifest".
- Noite CI (`noite.ci.yaml`) now runs on the shared `ryuz_workflow` crate (ryuzcorp/crates) instead of a runner-local module. The accepted workflow surface grows: `strategy.matrix` with `max-parallel`/`fail-fast`, `runs-on` (kept as a routing hint), job-level `env` and `defaults.run`, `shell: bash|sh`, `container:` as an `image:` alias, and `uses: checkout|cache|upload-artifact` with `with`. Matrix values reach steps as `RYUZ_MATRIX_<KEY>` env vars; an explicit `env` of the same name wins.
- The engine brings its safety properties to deploys: per-step and per-job timeouts kill the container, exit 137 is reported as out-of-memory, containers carry a `ryuz_workflow.pid` label and are swept at start (and removed on cancellation), env values never reach argv and are masked in the log, and artifacts stage outside the worktree and install without following symlinks. Jobs still run one at a time (`max_parallel: 1`) and a workflow must still leave `dist/` for the deploy.
- Workflow, job and step `env` may not set names reserved for the host container CLI (`PATH`, `HOME`, `TMPDIR`, `LD_*`, `DOCKER_*`, `CONTAINER_*`, `PODMAN_*`, `XDG_*`, proxy/TLS variables); export those inside `run` instead.

## [0.1.0-alpha.26] - 2026-11-07

### Operator action required

- Apps with a `noite.ci.yaml` now run it instead of the built-in install/build. Standard installs need nothing: the runner already has the Docker socket and pulls the default image on first use. CI containers consume the host's memory and CPU like the built-in build, so a 2 GB box still cannot build the 1.3 GiB template; use a bigger box or a prebuilt dist.
- Scheduled apps no longer auto-sleep without an explicit override: if an install relied on idle-sleep for cron/queue workers, set Sleep after per app (Settings → Limits) or leave them awake.
- Small hosts derive a shorter threshold (`1` h at ≤ 2 GiB, `6` h at ≤ 4 GiB): set `RUNNER_SLEEP_AFTER_H` explicitly to keep the previous `24` h behavior.

### Added

- Deploys now prove the new generation before serving it: after staging, the deploy asks the staged generation for `HEAD <path>` (`RUNNER_DEPLOY_PROBE_PATH`, default `/`) through `celld invoke` — the staged pins plus the app as `--target`, like the staged migrations — before the one `celld activate` moves the pointer, on every deploy (a Void redeploy after its staged migrate, any other deploy right after its stage). An answered status below 500 activates; a 5xx or a missing answer fails the deploy with nothing activated, so the previous generation keeps serving until the new one is proven live. The one unprobed activation is a deploy with no live old generation (a first deploy, a stopped app or a parked fleet): celld answers `no node leases`, there is nothing to fail over from, and the deploy activates instead of failing. `RUNNER_DEPLOY_PROBE_TIMEOUT_S` (default 30) bounds the probe; empty path disables it (a celld without `invoke`).
- Noite CI: a repo-root `noite.ci.yaml` (a light GitHub-Actions subset: `jobs`, `steps`, `run`, `env`, `working-directory`, `timeout-minutes`, optional `image`) runs in a container per job instead of the built-in install/build. The workflow's `dist/` is the deploy root; a failure fails the deploy before release/activate, so the live version keeps serving. Containers are cap-dropped, no-new-privileges, memory/CPU/pids-capped, no host binds, no Docker socket inside, and the checkout is copied in/out with `docker cp`; `HOME` and package caches persist in a per-app named volume. Images are an exact allowlist (`RUNNER_CI_IMAGE`, `RUNNER_CI_IMAGES`), network `bridge` or `none`, kill switch `RUNNER_CI=0`. Bounded: 64 KiB config, 32 jobs/steps, 32 KiB scripts, 120 min/step.

### Changed

- Scale-to-zero policy: Settings → Limits gains a per-app Sleep after threshold in seconds (`0` = never, valid range `60`–`2592000`); empty inherits the install default. Preview environments use their owning app's override, re-checked under the transition lock.
- `RUNNER_SLEEP_AFTER_H` unset now derives from detected memory (≤ 2 GiB: `1` h, ≤ 4 GiB: `6` h, else `24` h); an explicit value (including `0` = never) still wins.
- Apps running scheduled work (a non-empty `triggers.crons` or `queues.consumers` in the last deployed Wrangler config) no longer auto-sleep unless the owner set an explicit Sleep after override. Memory-pressure parking still parks them; the next request wakes them.
- A failed wake now records a tenant-visible `wake failed` fleet event and bumps the `wake_failed` sleep counter in `GET /v1/admin/stats`.

## [0.1.0-alpha.25] - 2026-11-07

### Operator action required

- A 2 GB install builds the Void debug app (measured 810 MB peak); the ~1.3 GiB Void/Ilha template still needs a bigger box or a prebuilt dist.

### Fixed

- A tenant build can no longer make the host unresponsive. The build cgroup leaf now gets a hard `cpu.max` quota of one core less than the box, split across concurrent build slots (a 2 vCPU VPS keeps a core for the runner, RustFS, Caddy, the fleets and SSH) and a low `io.weight`, alongside the existing memory cap. The derived memory budget now leaves a 1 GiB resident floor (RustFS, runner, fleets): a 2 GB box gives one build ~933 MiB, enough for the measured 810 MB peak of the failed `void-debug` build, instead of half the box with no headroom. The RustFS scanner and healer are slowed to daily/one-at-a-time so they do not compete with a build for CPU and disk, and the per-step timeout is 1800 s (was 300) so a build on one core can finish in the background, and the telemetry tick is skipped while a deploy is building (spans stay in the bucket; the next tick catches up) so DuckDB does not compete for the build's CPU and disk. A 1.3 GiB template build still dies in its leaf with the named budget; that is the prebuilt/CI path.
- The installer now creates a 1-2 GB `/noite.swap` swapfile on a host under 4 GB that has no swap (swappiness 10), so a transient peak cannot OOM-kill RustFS or Caddy; build and fleet leaves keep zero swap, so a capped workload still dies alone. It is idempotent, skips a host with less than the file plus 3 GB free, and `NOITE_SWAP=0` turns it off; the uninstaller removes it. Re-run the installer to get it on an existing install.

## [0.1.0-alpha.24] - 2026-11-07

### Operator action required

- None.

### Fixed

- Creating an app on a slug with a large deleted history no longer fails with "operation aborted due to timeout". The prefix purge now lists and deletes one page at a time (a canceled caller leaves progress instead of re-walking the whole prefix on every retry), and the create runs as its own task: the control plane's 14 s abort drops only the waiter, the row lands, and the GitHub import spawns. ## [0.1.0-alpha.23] - 2026-11-07

### Operator action required

- None.

### Changed

- The persistent per-app build cache cap is now 1024 MiB (was 512). A cold `bun install` of the shipped Void/Ilha template writes ~872 MB, so the old cap pruned the cache it had just filled at the end of every deploy and the next one downloaded it again; the cache survives deploys and is still pruned largest-first and deleted with the app. Worst-case disk is 1 GiB per app (the default install has 39 GB free on a 2 GB VPS).
- The bundled RustFS service now sets `RUSTFS_ALLOCATOR_RECLAIM_ENABLED` and `RUSTFS_ALLOCATOR_RECLAIM_FORCE` explicitly, so freed allocator pages return to the OS between idle periods instead of accumulating: prod measured 752 MB anonymous in the store's own container after four days, outside the noite container's memory accounting. The console stays disabled (it is admin UI, not storage).

### Fixed

- Deleting an app now frees its slug as soon as the app row is gone: the stop of any re-spawned fleet, then the push guard and deploy claim, run before the post-delete cleanup (edge route push, provider key revoke, operator-token cleanup). A slow or hung cleanup step used to keep the slug taken after the app had disappeared from the list, so create or rename onto that slug waited on the guard past the control plane's 5 s and failed with "operation aborted due to timeout". The remaining cleanup is bounded to 30 s and logged when it outlives that, so a hung provider call can no longer outlive the delete task.
- Create, rename and delete runner calls in the control UI now allow 14 s (the route's own bound is 15 s) instead of the 5 s default (the runner still answers delete within 3 s): clearing a deleted slug's leftovers or moving a large S3 prefix no longer shows as an abort while the runner is still working.
- The memory-pressure parking sweep now measures what the kernel OOM killer does on an unbounded install: the host's used memory (`MemTotal - MemAvailable`) instead of this container's own `memory.current`. The bundled RustFS runs in its own container and the runner's cgroup is unbounded on the default compose, so the old check read ~20% while the box sat near 75%; the last guard before the OOM killer never fired and idle apps were never parked. Bounded installs (a container `mem_limit`) keep measuring their own cgroup. `/ready` and `/v1/admin/stats` now carry `memory.scope` (`container` or `host`) alongside the existing bytes and percent.
- MinIO/RustFS admin and AWS IAM calls now time out after 10 s instead of hanging forever. A hung admin call stalled key mint/revoke and the orphan-key sweep, and (before the delete fix) could hold a deleted app's slug. A timeout during the MinIO `auto` probe is now a detection failure that fails the boot, instead of being read as "no admin API" and silently downgrading the install to root keys; a stalled IAM response body is now an error instead of an empty string that parsed as a successful empty listing and hid orphaned keys.
- Renaming an app now runs as its own task, like delete: the control plane aborting the call (14 s lifecycle bound) only drops the waiter, and the move completes instead of leaving the row on the old slug with local dirs or S3 prefixes half moved. A slug that still belongs to another app answers `409` immediately; a slug freed by a delete has no leftovers (its purge completed before the row went away) and can be taken. Regression tests cover a taken target, a deleted target, and a dropped caller (the last fails without the detached task: the move is canceled and the row stays on the old slug).

## [0.1.0-alpha.22] - 2026-11-06

### Operator action required

- A tenant build now runs in its own capped cgroup (`RUNNER_BUILD_MEMORY_MB`; unset derives half the detected memory split across build slots). A build that used to thrash a small host now fails with a deploy-log message naming the cap; raise the knob where the RAM allows it, or deploy a prebuilt dist from CI. The Void/Ilha template's build peaked at ~610 MB on the 2 GB test box, inside the derived ~978 MiB, so installs whose builds fit need no change.

### Fixed

- A tenant install/build/release step now runs in its own per-deploy `build` cgroup leaf (production and each preview separately) with a hard `memory.max` (`RUNNER_BUILD_MEMORY_MB`; unset derives half the detected memory split across the build slots, clamped 512–4096 MiB), `memory.oom.group`, `pids.max`, swap capped at zero (a build cannot grow past its budget into host swap) and a low CPU share. A build that outgrows the budget — a Vite/Rolldown build of a Void app peaks around 1.3 GiB on two cores — is OOM-killed inside its own leaf, so the runner, Caddy and every fleet keep serving, and the deploy log names the cap and the ways out (raise it on a box with the RAM, or deploy a prebuilt dist from CI). The step moves itself into the leaf in `pre_exec` before the build uid is dropped, and the uid/gid drop moved into that same window (`setgroups(0)`, `setgid`, `setuid`). `/ready` reports the budget and every live leaf's charge, peak and OOM count. Cgroups unavailable still means an uncapped build, but that is logged at boot and named in `/ready`, as before.

## [0.1.0-alpha.20] - 2026-11-06

### Operator action required

- None.

### Added

- Memory-pressure parking: when the container is at or above `RUNNER_PRESSURE_PCT` (85%) of its detected limit, the runner parks the least-recently-active app or preview environment idle for `RUNNER_PRESSURE_IDLE_S` (300 s), stopping 10 points below the trigger. It wakes transparently on its next request and records a `fleet parked` event; anything with an in-flight deploy is never chosen. `0` disables it. `/ready` and `/v1/admin/stats` now report container `current_bytes`/`limit_bytes`/`used_percent`, and stats lists each fleet's cgroup charge under `fleet_memory`.

### Changed

- A small host now sizes the resident set from its own memory: per-fleet celld caches are capped (`RUNNER_FLEET_LOCAL_CACHE_MB`, a sixteenth of the box clamped 64–512 MiB; celld's own default was 2 GiB per node), the control fleet gets its own capped cgroup leaf (`RUNNER_CONTROL_MEMORY_MB`, a quarter of the box) instead of running uncapped, and fleets without cgroup leaves get a derived container-wide shed threshold (75% of the box) so celld answers 503 before the kernel OOM-kills the container.
- Cold boots ramp instead of stacking: `RUNNER_FLEET_SPAWN_BATCH` starts at most one cold fleet per reconcile pass on two cores or fewer, and `RUNNER_BUILD_CONCURRENCY` serializes tenant deploys. Restarts of an already-running fleet are never delayed by either.

### Fixed

- A fleet that exits without an OOM kill no longer respawns every reconcile tick forever: it backs off 5, 10, 20, 40 s and caps at 60 s, resetting after five minutes of uptime. OOM kills keep their longer cgroup backoff, and a deliberate stop clears the chain.
- The per-fleet log ring is a `VecDeque`: appending no longer shifted the whole 500-line buffer per line. `/ready` reuses one HTTP client instead of building a new pool every 10 s probe.
- Telemetry ingest and compaction no longer run DuckDB at its own defaults (80% of RAM, every core): every invocation now carries a memory cap, a thread count and a capped spill directory, so a 24-hour catch-up or compaction scan spills instead of growing past the box. Unset derives the cap from the memory this container may use (10%, clamped 128–1024 MiB) and its cores (capped 4); `RUNNER_DUCKDB_MEMORY_MB`, `RUNNER_DUCKDB_THREADS` and `RUNNER_DUCKDB_TEMP_MB` override them. Measured on one 24-hour chunk (24 M spans, 581 MB Parquet): 1.55 GB peak RSS before versus 271 MB at the cap a 2 GB box derives. The limits use DuckDB's `MiB` unit, so a configured MiB value is exactly that many MiB.
- A killed DuckDB pass leaves its spill behind, and stale bytes count against the spill cap, which would wedge every later pass. Boot clears the directory outright (no query can be running); a failed pass sweeps entries older than an hour, so a live query's files are never touched.

### Security

- Telemetry DuckDB now receives its SQL on stdin instead of `-c` on the command line. That SQL carries the platform store keys, and `/proc/<pid>/cmdline` is world-readable while tenant build processes share the container's PID namespace, so a build script that sampled the runner's children could have captured them. Every interpolated store field and every object key in the compaction and glob SQL is now a quoted DuckDB literal with doubled quotes, so a credential containing a quote can no longer end a statement. Logged DuckDB errors are scrubbed of both raw and SQL-escaped store keys.

## [0.1.0-alpha.18] - 2026-11-05

### Operator action required

- Requires celld `v0.6.3-ryuzcorp.8`: every app deploy names its checkout as a read root (`--read-root`), stages through `deploy --no-activate`, and serves with `celld activate` — do not deploy this runner against an older celld, which refuses the read root and fails every deploy.
- The runner database migrates to schema 15 automatically (new `fleet_operator_token` table); downgrading past this release is refused, as usual.
- Anything outside the runner that calls a fleet's internal API directly (for example a script that POSTs `/reload`) must now send `Authorization: Bearer <fleet token>`; the runner's own calls already do. The control fleet's token for `celld diagnose`-style tooling is published root-only at `<work-dir>/control-operator-token` inside the container.
- Operator-global `CELLD_*` (and any other runner-env value a fleet used to inherit, such as a global `RUST_LOG` or `DOCKER_HOST`) no longer reach fleets. Fleets are configured through the `RUNNER_FLEET_*` knobs only now; the boot warning names any `CELLD_*` that is ignored. The only inherited values left are the custom-CA trust files and the proxy settings.
- Platform store credentials must be static long-term keys: fleets no longer inherit an ambient credential chain (`AWS_SESSION_TOKEN`, web identity, EC2 instance role). celld's store client never used a profile, and tenant fleets always ran on the static scoped keys, so only a control node relying on such a chain is affected.
- Credentials in `S3_ENDPOINT` userinfo are ignored (they never authenticated); remove them from the URL to silence the warning. The tag and store identity hash the endpoint as configured, so the install keeps its tag across the upgrade and its existing keys stay revocable — but changing the endpoint re-tags the install, and keys under the old tag read as foreign: the sweep drops their rows without revoking them, so delete the old keys at the store by hand.
- Requires celld `v0.6.3-ryuzcorp.7` for the not_found object; against an older celld a missing key surfaces as a step error instead of 404.
- A Void-app deploy that fails naming `ISR_CACHE`, `noite-void-proxy` or `__VOID_PROXY` needs that name freed for the platform. If you set a `BETTER_AUTH_SECRET` value yourself it keeps winning; a generated one appears in Settings → Environment (production) or the environment's Variable overrides (previews) like any other setting (value hidden as usual) and can be replaced there.
- Requires celld `v0.6.3-ryuzcorp.7` (staged invocation): do not deploy this runner against an older celld, which has no `invoke` subcommand or `--header-env`; a staged migrate against it fails the deploy (nothing activates) with an error naming the celld requirement.
- Migrations are forward-only: rolling back the code never un-applies them, so a deploy that fails at `migrate` leaves applied migrations in place — fix the migration and redeploy, which skips what is already applied. Keep migrations backward-compatible with the previous release. On a first deploy (or a fleet with no live node, which migrates after adoption), stopping the app mid-deploy skips its migrations; redeploy to run them. A redeploy's staged migrate runs regardless of a stop, so stopping can never skip it.
- Like `release`, a failed staged `migrate` keeps the old deployment serving (traffic switches only at activation). Only the first-deploy and fallback paths still migrate after activation: there a failed `migrate` leaves the new Worker serving a half-migrated schema while the deploy reads Failed. The step is bounded: worker responses past 4 MiB fail the deploy, warning/name lists log the first 20 plus a count, and per-request timeouts cap the worst case at ~15 min staged (~18 on the legacy endpoint).
- If a multi-tenancy install points `NOITE_VOID_SMTP_HOST` or an AI endpoint at internal infrastructure (a private IP, `localhost`, a `.local`/`.internal` name), move it to a publicly reachable address before upgrading — the new boot check refuses the old value naming the var.
- If an allowlist relied on `@domain` matching subdomains, list each subdomain explicitly (`@example.com` no longer admits `sub.example.com`); if an AI model endpoint uses `http`, it must be a loopback sidecar with `NOITE_VOID_AI_ALLOW_PLAINTEXT=1`, else the boot fails naming the var.
- Settings values are now readable by Worker code via `env` (plaintext `vars` in the deployed config — celld has no secret store). If you kept a value in Settings specifically because Workers could not see it, move it out: there is no process-only tier anymore. A deploy that fails naming a reserved variable needs that variable renamed.

### Added

- celld patches `0005` and `0006`:
  - A service-binding RPC method can return or accept a Durable Object stub, as on Cloudflare.
  - Container `exec` can allocate a terminal (`pty`, `isPty`, `resize(cols, rows)`).
- Container exec can now allocate a PTY: `exec()` takes `pty: true` (or `{ cols, rows }` for an initial size), the process reports `isPty`, and `process.resize(cols, rows)` resizes the terminal. The engine proxy accepts `Tty` execs and `POST /exec/{id}/resize` for a fleet's own execs only.
- Every fleet node (tenant fleets and the control node) now runs with a random per-fleet `CELLD_OPERATOR_TOKEN`: celld requires it as `Authorization: Bearer` on every internal-listener route, and the runner sends it back on its own internal calls (`POST /reload`, the DO `?read=1` probe, the `celld` CLI subprocesses). Tokens are minted once per fleet, stored AES-encrypted like the scoped bucket keys, and never reach tenant code (Worker envs come from declared vars only; `CELLD_*` stays reserved out of fleet process env). Liveness probes use the public health endpoint, which the token does not guard.
- Void apps with D1 migrations now migrate on every deploy: before the deploy is marked success, a `migrate` step collects the pushed tree's `db/migrations/*.sql` (Void's rule: sorted, `seed.sql` excluded) and drives the Worker's in-worker migration endpoints with the fleet's `__VOID_PROXY_TOKEN` — protocol v2 where advertised (capabilities negotiated against the tree's dialect, classifier version and list hash, then app migrations with reconcile-on-unknown, then auth migrations), legacy `POST /__void/migrate` for older sqlite runtimes. On a redeploy the endpoints run against the staged generation through `celld invoke` before the activate; on a first deploy — or when the fleet has no live node — they run against the new Worker over the fleet's own listen port after reload adoption and the health gate, as before. Execution stays in-worker, so `_void_migrations` and the v2 attempt/lock/fence tables match Void exactly. The log reports `migrate: applied N, skipped M` with the quoted file names; a redeploy skips applied migrations, and a failed migration fails the deploy with `migration <name> failed: <error>`. A failed staged `migrate` runs no activate, so the previous generation keeps serving. Prebuilt CLI trees with no `db/migrations` run the worker's bundled migrations without the list-hash check and say so. Each preview migrates its own D1. Non-Void apps deploy exactly as before.
- Postgres/MySQL Void apps are refused loudly at the `migrate` step instead of deploying with an empty database: their in-worker handlers need a Hyperdrive binding Noite does not provide. Move the app to D1 (`database.dialect: "sqlite"` in `void.json`).
- Void apps now get a working `__VOID_PROXY` service binding: each Void deploy cohosts the runner-owned `noite-void-proxy` script (ISR revalidation, email, AI) in the fleet next to the app. The deploy runs cohosted scripts first — each skipped when its content hash (embedded sources plus rendered config, with secret values substituted by their hashes) matches the stored one — then the app last, then the one `/reload` whose outcome fails the deploy on a refused adoption. The app deploy retries once on infra errors (S3/CAS failures, timeouts); tenant failures (bundling, config shape) fail at once with no retry. Previews render their own proxy into their own fleet bucket. The cohosting is one reusable mechanism (`host/void_cohost.rs`): a later runner-owned script only adds its sources and its render.
- Operator config for the proxy (`NOITE_VOID_*`, validated at boot with the var named on every error): the sender domain (`NOITE_VOID_EMAIL_DOMAIN` → `__VOID_EMAIL_DOMAIN`, also injected into Void apps so the email client defaults `from`), the SMTP relay (`NOITE_VOID_SMTP_HOST` — email is enabled iff set — plus optional port, `starttls`/`implicit`/`plain` mode and the plaintext allowance), the admission allowlist (`NOITE_VOID_EMAIL_ALLOWLIST`, empty fails closed), and AI (`NOITE_VOID_AI_ENABLED` plus the `NOITE_VOID_AI_MODELS` map of `@cf/…` ids to OpenAI-compatible endpoints). Unset means email sends and AI calls answer 501; `/revalidate` needs no operator config.
- Per-app proxy-only credentials as ordinary Settings rows: `VOID_PROXY_SMTP_USERNAME`, `VOID_PROXY_SMTP_PASSWORD` (this app's SMTP login) and `VOID_PROXY_AI_API_KEY` (this app's key for the operator AI endpoint). They list, inherit into previews, override per environment and mask in the UI like any other setting, take effect on the next deploy — and they only ever reach the proxy render: the deploy splits them out before the app merges, they never reach build/release/fleet process env, and any other `VOID_PROXY_*` use on a Void app fails the deploy naming it. No operator-wide secret ever lands in proxy vars.
- Void sandbox controller bundle: `apps/void-sandbox` compiles the fixed `noite-void-sandbox` controller (`SandboxController` DO + fleet-local `NoiteSandboxAdmission` DO) from the pinned `void` 1.5.0 npm version, and the image ships it at `/opt/noite/void-sandbox/{worker.js,meta.json}`. The runner cohosts the rendered controller in each sandbox app's fleet (controller first, proxy second, app last), so `getSandbox()` serves a live cell stub.
- Void apps with a managed sandbox now get a working `__VOID_SANDBOX` service binding: each sandbox deploy cohosts the runner-owned `noite-void-sandbox` controller script in the fleet next to the app — controller first, proxy second, app last — so `getSandbox()` returns a live cell stub instead of throwing `SandboxUnavailableError`. It used to throw `Cannot clone a streaming response before consumption`, so a Worker that caches a copy of a streamed response (Void's ISR on server-rendered pages) answered 500. `Request.clone()` and `Response.clone()` now also refuse a body that was partly read through its reader, as on Cloudflare, instead of cloning the remainder.

- A tenant config can no longer alias the proxy's mail-idempotency store (`MAIL_IDEMPOTENCY` binding or `noite-void-proxy-mail` id), aim a second service binding at the proxy script, or use the mail binding name as a var — each fails the deploy naming it.
- `/ai/run` with `stream:true` returns upstream errors with their status instead of masking them as 200 SSE.
- Cohosted deploys render to owner-only temp projects removed on every path (failed deploys leave nothing on runner disk); the fleet token is ensured once per deploy and threaded into app and proxy alike, so a mid-deploy rotation cannot split them.
- Boot validation refuses `http` AI endpoints except loopback sidecars with `NOITE_VOID_AI_ALLOW_PLAINTEXT=1` (the per-app key would otherwise travel unencrypted), and rejects CR bytes in the mail domain, relay host and allowlist entries.
- The sandbox controller no longer redeploys on every deploy: per-deploy container-image paths are excluded from its content hash (the pinned-Dockerfile + build-context digest carries the content), so identical content in another build dir skips like the proxy does — which also removes the common case of two concurrent deploys racing celld's fence-image build.

### Fixed

- **A dropped DB setup pass no longer stalls the whole control plane in 5 s generations.** Every control request (actions and `/assets/*` alike, since `run_worker_first` sends assets through the worker) shares one isolate-level D1 setup pass. celld drops a request's pending work when that request answers or its client leaves, so when the starter's request finished first, the shared pass never settled: every waiter burned the full 5 s, then started its own equally orphanable pass — the 5 s, 10 s and 15 s stalls behind flake H and issues #91/#92. The starter now registers its pass with the worker lifetime (`ctx.waitUntil`), and waiters that outlast their bound share the single replacement pass instead of each starting their own. `ensureDb` accepts the lifetime and the bound (`EnsureDbOptions`; tests inject a zero bound and await real signals).
- **A failed load no longer poisons the panel, and nothing retries on a timer.** A resource whose load fails used to settle into the shared cache's permanent failure, so even remounting re-served the same error until a mutation forced a refetch. The failure is now evicted when it lands: the error still surfaces, but a later mount (or an explicit refetch) starts a fresh lookup. The round-1 timed auto-retry is gone — the product fix above removes the stall instead of waiting it out.
- **One fewer D1 round-trip on every admin action.** The env-anchored promotion check re-selected the user row on every admin request even when the fresh session role was already `admin`; it now returns early on that role, saving a sequential query against celld's single-threaded D1 on the hottest gate in the panel.
- **A lifetime-less setup waiter no longer stores a pass an abort can orphan.** A waiter that outlasts the 5 s shared-pass bound but carries no worker lifetime cannot register the replacement it would start, so it now fails fast instead of storing an unregistered pass: the next requests for the same store would otherwise await the orphan to the 15 s route timeout (flake H's `listEnvironments` + `errorDetail` pair, both 15.01 s to 504 after the same app's requests were aborted). The middleware always carries a lifetime, so it still owns every replacement; the fail-fast only triggers on a genuinely wedged pass.
- **The session read is bounded.** The better-auth session lookup reaches D1 with no timeout anywhere in its chain, so a wedged store rode every action to the 15 s timeout. `getSessionOrNull` now races the read at 5 s and throws on expiry: actions fail 500 with cause, browser routes deny as signed-out — deny either way, never proceed, never hang. `docker/check-worker-rules.ts` tripwires CI against the common regressions (module-level in-flight caches, session reads outside the bounded wrapper).
- **A failed snapshot meta upload is retried, not skipped.** The runner recorded a snapshot's hash as soon as the state object uploaded. If the metadata upload after it failed, the next pass saw identical bytes and skipped, leaving the bucket's `noite.sqlite.meta.json` stale (a new runner seeds its generation and skip hash from it) while `/ready` reported a fresh upload. The hash is now recorded only once both objects landed, and a skipped pass no longer resets the reported upload age.
- **App deletes and environment teardowns run to completion when the caller goes away.** The control plane times these calls out after 5 s, and a dropped request used to cancel the purge halfway — leaving the app row, the fleet and the scoped credentials behind. The destructive work now runs as its own task while the handler awaits it, so a disconnect only drops the waiter. A delete that finished server-side also no longer leaves a stale row behind: the admin apps list reloads after a failed mutation too, and the app's Danger Zone re-reads the app and follows the delete through when it is gone.
- **Deleting an app SIGKILLs its fleet first.** A graceful shutdown only does durability work the purge destroys a moment later, and young fleets regularly ignored SIGTERM for the whole grace — every slow delete in CI paid the full 3 s. Stops, sleeps and orphan sweeps keep the full graceful wait, and the 0.5 s settle before the S3 wipe stays.
- **S3 response bodies keep the request's own read deadline.** Every S3 body read now carries the same timeout as its request instead of relying on the HTTP client's internal total-timeout, so headers delivered with a body that never follows fail like a stalled send instead of hanging the caller.
- **A first deploy answers through the edge as soon as it reports success.** The runner added a new app or preview to the edge route table only after recording the deploy as successful. A request sent the moment the CLI, the UI or a script saw that success could get the "is starting" page (503) for a few milliseconds. The target is now routed first, and the deploy reports success after. A deploy whose route table the edge refuses now fails with the edge's answer, instead of reporting success for a target that isn't reachable. An edge that is restarting still lets the deploy through, because it boots from the table file, which already routes the target.
- **A just-created branch no longer misses from the branch picker.** A refs read overlapping a branch create could apply its pre-create manifest read, deleting the fresh ref from the push mirror (the picker's single refetch then cached its absence for the rest of the page); the same shape existed on the deploy-config read path, which synced with no seq check at all. Manifest re-apply is now double-checked under the slug's push mutex — an unlocked fast path serves local when the newest applied seq already covers the manifest, and only a newer manifest takes the guard and re-reads before syncing — and the applied seq never moves backward. Hot config readers serve local (cold hydration still syncs once), purge and slug-changing rename drop the slug's generation marker so a recreated slug's restarted seq applies rather than skipping as stale, and manifest staging uses a unique tmp path per call so a concurrent reader's download can never clobber a writer's flip.
- **The Errors, Deployments, Events, Logs and Metrics lists render their current data on load.** Every live list painted only stream frames, so a first frame delayed or lost anywhere between the runner and the browser left a skeleton until the data changed — for already-ingested data, forever. Each list now fetches its current snapshot once on a cold key (shared when a tab badge and its list use one key) and the stream keeps it live after; a failed fetch is ignored and stream frames always win once they arrive. New `errorList`, `listDeploys`, `eventsSnapshot`, `logTail` and `metricsFrame` actions serve those snapshots, view-gated like their streams.
- **A hung live-list snapshot fails visibly instead of holding a skeleton.** A first snapshot that hangs or fails every poll ended an open stream with no frames and no retry: the tab sat on skeleton with no banner. Every runner stream (errors, events, deploys, app state) and the log tail now ends with an error when no first frame arrives within 10 s, and the control hub drops a topic whose upstream opens but sends no first frame within 15 s — both surface as the retrying state the client already reopens, so the stall heals itself. The initial snapshot behind each list times out after 10 s too and is retried on a later paint. The `listDeploys` snapshot serves the same lean rows as the stream (finished rows carry no build log; fetch it on demand) while the runner list keeps full rows for API consumers, and `eventsSnapshot` rejects a non-integer or out-of-range `limit` with a 422 instead of a runner 500.
- **A lost `scoped_credential` row no longer leaves its key live forever.** When a mint's row never landed (a crash inside the snapshot loss window, then a restore), the old revoke path — which only acts on rows — could never reach the key, and the next mint for the scope handed out a second key while the first stayed valid. The new orphan reconcile above revokes those keys. Only principals carrying this install's tag can ever be revoked (MinIO keys whose attached policy is exactly the tagged per-key name, AWS users named `noite-<tag>-…` under exactly `/noite/<tag>/`); foreign users, other installs' keys, pre-tag keys and the operator's keys are never touched. A mint that hits an existing user name reads it back first and only clears a half-minted user under its own path — anything else fails loudly instead of deleting a foreign user. The listing runs without the mint lock (each candidate is fenced instead), and a listing failure revokes nothing.
- **A wedged `git` remote can no longer hold the e2e lane open in silence.** Every synchronous child process in the suite (`git` clone/push, the packaged CLI, its build) now carries a 120 s bound with `SIGKILL` and no credential prompts, and Playwright runs under a 25-minute parent-side `globalTimeout` (release shard 2 measured ~5 min). In merge-queue run 39785255412 a hung `git clone` blocked its worker's event loop, so no per-test or hook timeout could fire: 32 of 33 tests passed, then 35 minutes of silence until the job cancelled. The same wedge now fails loudly (`ETIMEDOUT` naming the command, or the `globalTimeout` naming the stuck test), and a red lane also captures the host process tree (`lane-host-procs.txt`) next to the container logs, so the stuck command is in the artifact.
- **Worker error occurrences no longer lose their request.** A failed span ingested before its access-log line was tailed stored its occurrence without method, path or status, and the re-read dedup kept the empty row forever — the Errors tab showed a blank request for an error whose line was in the log. The access-log tail now runs before the ingest each tick, and a span that still ingests first is marked pending so the tail backfills the stored row when the line lands.
- **Concurrent app and environment creates no longer start two fleets on one port.** Fleet ports were picked as the lowest free pair and then inserted in a separate step, so two creates racing each other read the same free pair and the loser's celld died at bind with "exited before answering its health gate". The pick and the row insert now run under one process-wide allocation lock, so the second claim always sees the first claim's ports.
- **`make doctor` no longer says "nulls ago".** Before the first state-snapshot upload `/ready` reports the upload age as JSON `null`, which the doctor line printed literally (`state snapshot (owner, last upload nulls ago)`). It now prints `no upload yet` and stays `ok` — the snapshot signal is additive and never fails `/ready`, so a fresh boot with nothing uploaded yet is normal, not degraded.
- **The multi-lane boot no longer fails on the first contested cgroup enable.** A healthcheck exec landing between the cgroup drain and the `subtree_control` write fails it with `EBUSY`, and the boot loop meant to retry that never did: the write helper formatted the OS error into a string, so the `EBUSY` classifier never matched and the first contention bailed the boot. Cgroup writes now keep the OS cause on the error chain, the retry rides out transient execs (the only possible squatters — the runner spawns nothing before setup, so its own children inherit the drained leaf by construction), and a persistent squatter still degrades loudly past the bounded budget. A fleet that exits between spawn and its cgroup move now also takes its orphaned workers with it instead of leaving them uncapped.

A stock Sentry SDK pointed at it reports exceptions to `POST /api/<n>/envelope/`, and they land in the Errors tab as the same issues as the Worker's own errors, labelled Browser (or SDK for server SDKs) with the page URL and release. Maps are kept for the current deploy and the last 10 successful ones. Preview environments don't keep maps yet.

A pending domain gets no route and no certificate. Several apps may hold a pending claim for the same hostname, and the first to verify wins. - **One fleet can no longer shed every app.** Each tenant fleet runs in its own cgroup v2 child with `memory.max` (`RUNNER_FLEET_MEMORY_MB`, 512 MiB by default) and `pids.max`, so a growing fleet is OOM-killed inside its own group — contained, and the supervisor restarts it — instead of pushing every fleet toward the shared shed threshold. Swap is disabled per leaf (`memory.swap.max=0`): without it the kernel swaps a capped fleet out instead of OOM-killing it. An OOM kill records a tenant-visible `fleet` app event and fleet log line (`fleet restarted: memory limit … MiB exceeded (Settings → Limits)`). `CELLD_MAX_RSS_MB` deliberately does not follow the per-fleet cap: celld measures container-scale working set, so a per-fleet value closed every fleet's ready gate in the lane. Settings → Limits gains a per-app **Fleet memory** override (applies on the fleet's next spawn), capped by the new operator knob `RUNNER_FLEET_MEMORY_MAX_MB` (default: the default cap, so a tenant can only lower its cap): the runner refuses a higher value in `multi` and clamps rows stored before the ceiling was lowered. The grant is narrow and multi-only (`docker/compose.multi.yaml`: `CAP_SYS_ADMIN` plus lifting Docker's default AppArmor mount denial — no `privileged`); single installs get nothing new. The hostile-tenant lane asserts each live fleet carries a positive `memory.max` and that `/ready` reports cgroups active.

### Changed

- **The Ilha + Void template replaces Oxide + ilha.** The creator offers exactly **Ilha + Void** and **TanStack Start**. Ilha + Void lives in the same repository, `ryuzcorp/noite-template-oxide`, now rewritten as Ilha pages on Void (Vite) with server-rendered pages, a server action and an island. The template id changed from `oxide` to `ilha-void` with no alias, so MCP `create_app` calls that pass `source: { kind: "template", template: "oxide" }` must switch to `ilha-void`. - **E2E runs a fast gate on pull requests and the full suite on release.** The lanes run two suites over the same specs: `fast` (the tagged critical paths — create, push and deploy, logs, Code mode edits, PR merge, auth/invite gates, template deploy, rollback, environments, error ingest — plus the isolation-relevant set on the multi lane) and `release` (every spec, including the new storage-editing and admin-page coverage). The bun base images stay on the floating `1.4` line (1.4.3 is the newest 1.x). celld 0.6.2 bundles exactly as 0.6.1 did, so the runner's shadow bundle and the Errors tab's mappings are unchanged; the only celld behaviour to know about is a forwarded Durable Object `stub.fetch()` now rejecting when the owner's handler fails, a WebSocket answer to a request without `Upgrade: websocket` failing as a `TypeError`/500, and `self` being defined in Worker isolates. esbuild 0.28.2 changes output in two places that matter: the `binary` loader, which Noite bundles never select (the runner strips Wrangler `rules`, and celld's default is `.wasm=copy` only), and, since 0.27.5, TypeScript parameter properties under `"useDefineForClassFields": true`, which now use define semantics as `tsc` does. DuckDB, rustfs, Node and jup are bug-fix or additive releases with nothing that changes how Noite uses them. Tenant Workers are redeployed onto the new toolchain by their next deploy, and fleets restart on the new celld with the upgrade.

### Fixed

- **`install --pre` installs the newest release again.** It took the first entry of GitHub's release list, which puts the release marked Latest ahead of newer pre-releases, so it installed 0.1.0-alpha.6 instead of 0.1.0-alpha.7. It now picks the most recently published release. `run.sh` is served from noite.now, so the fix applies without a new image.
- **Status badges stay in sync.** After a deploy, a stop or a sleep, the app header's status and the Deployments tab's Production and environment dots kept the old state (a yellow "Deploying" dot after a finished deploy) while the sidebar moved on, until a reload. An app's pages now follow a live state stream (`/api/apps/:id/state/stream`) and refresh whatever it shows has changed, and the sidebar's app list updates every 2 s instead of every 10 s.
- **The Ilha + Void template no longer loses early input, and adding a todo no longer reloads the page.** Its todo form and About-page counter were server-rendered in place but worked only once the page's scripts had run. A todo typed and added before that turned into a plain form GET that reloaded the page without adding it, and an early counter click did nothing. Both now stay disabled until the page can handle them. The todo action also answered with a bare `{"ok":true}` instead of the page data Void's client expects, so every add reloaded the whole page; it now updates in place. The template is fetched from GitHub when an app is created, so the fix applies without a new image.
- **A rollback issued right after a deploy no longer vanishes.** **Roll back** answered OK, but if the app's previous deploy was still finishing, the rollback was silently skipped: no deploy row appeared, and the page kept waiting for a deploy that never started. A rollback now creates its queued deploy before answering and waits its turn behind the in-flight deploy, the way environment deploys already did. The runner's rollback response (`deploys.rollback`, `POST /v1/apps/{id}/rollback`) also returns the new `deployId`.
- **Deleting an app with a slow fleet no longer wedges later deletes.** `stop_fleet` waited 15 s for graceful shutdown before SIGKILL, so deleting an app whose celld was slow to exit (e.g. right after a (re)start) outlasted the UI's 15 s action timeout: the caller gave up, the half-finished delete held the per-app build/delete lock, and every retry answered `409 deploy in flight` forever. The lock is now a drop-guard (a cancelled, failed or panicked holder always releases it), and deletes stop the fleet with a 3 s grace instead of 15 s — the data is wiped right after, so a slow graceful shutdown is pure delay. Stops, sleeps and orphan sweeps keep the full grace.
- **Requests no longer drop when any app starts, stops or deploys.** Every app lifecycle event rewrote the Caddyfile and restarted Caddy, and each restart dropped in-flight requests transport-level (`ERR_EMPTY_RESPONSE`, `ECONNRESET`) with no log and no 5xx — hanging page loads and failing POSTs, since Go answers nothing when the read completes after shutdown began. Caddy's config is now static after boot; a small edge module (`edge/`, built into the image) holds a route table the runner pushes through Caddy's admin API on every lifecycle event, so app events never reload. Rate limits, the fleet readiness hold, wake-on-request, the env gate, frame headers and the starting page all behave as before.

- Code mode's Terminal panel came back **empty** when it was reopened (`?terminal=1`): ghostty-web's render loop redraws only the rows its WASM render state marks dirty and clears that state after every render, so a canvas that had lost its pixels — the bitmap is thrown away whenever a resize assigns the canvas its new `width`/`height` — stayed blank until the shell next wrote something (the prompt of a command, an echo, any output), and the reopen itself repainted nothing: the fit addon does nothing while its container has no size (the shell is out of the document, or the panel is not laid out yet) or for 50 ms after a resize, and `Terminal.resize` returns early when the grid already has the size proposed. The panel now measures the pane the shell actually sits in (its `ResizeObserver` used to keep watching the pane the previous mount had built), fits on the frame the box is real, and forces the full repaint ghostty otherwise reserves for a resize, so the shell's screen is on show from the first frame.
- **Code mode switches branches in place.** Every `?ref=` change used to remount the whole browser: the tree and the editor went back to their "Opening checkout…" skeletons, a second pod frame booted cold (fetching and untarring the ref again), a second language-service worker was spawned, and a ref whose listing or pod frame did not answer in time left the panes on skeletons for good. The browser is now mounted once per app and installs the new ref's checkout under the panes it already has: the tree and the editor keep showing the branch the user came from (marked _Switching to `<ref>`…_, input blocked) until the new ref's rows and file are ready, the intel worker re-syncs to the new ref instead of being rebuilt, and the checkout the user came from stays open for 90 s, so toggling between two branches is instant and each branch's unpushed drafts are exactly where they were left (drafts are per app **and** branch, in the pod's own IndexedDB workspace — nothing crosses). A ref that cannot be opened — a listing or a pod frame that times out, a frame that dies mid-session — leaves what was on screen standing and offers **Retry** instead of a stuck skeleton. `?file=` reopens on the new ref when it exists there and falls back to the Worker config the way a first open does.
- **Code mode's diagnostics came back wrong until a reload after switching branches in place.** With `cloudflare.config.ts` open, a switch to another branch left `TS2307: Cannot find module 'cf/config'` under the import — the declaration was in the language-service worker's FS the whole time — and opening another file did not clear it; only a reload did. A switch re-set the versions the worker resolves packages against from the new ref's lockfile, which dropped **every** specifier's resolution, including the ones both lockfiles pin identically, and re-acquiring them only re-pointed the declaration URLs already fetched: no file landed, so the pane was never told to check the open file again. What a specifier resolved to now survives a lockfile unless that lockfile moved its package's version, a round that publishes a resolution without fetching anything still tells the pane to re-check, and a round that outlives the lockfile it started under drops its answer instead of publishing it.
- **Code mode's Changes panel pushed a "New branch…" commit to the browsed branch.** Picking **New branch…** and naming it still committed onto the branch you were browsing (often `main`): the target select's rework stopped sending the new branch's name. The push now creates the named branch at the browsed tip again.
- **An environment created while production was deploying failed at once** with "another deploy of this app is in flight" and deployed nothing until the next push. A deploy with a visible queued row (creating or redeploying an environment, a workspace preview) now waits for the app's running deploy to finish instead of failing; background tip deploys still skip and are picked up by the next reconcile.
- The branch picker stayed open after **Create**, so the next click on it closed it instead of opening it: a parent repaint wrote back a stale open state. The dropdown now owns its open state, which repaints leave alone.
- The Changes toggle's count badge holds the number alone again; the words around it are screen-reader text.

### Security

- The control UI is served cross-origin isolated: every document, module and worker script carries `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`, and its own assets `Cross-Origin-Resource-Policy: same-origin` (`apps/noite/public/_headers` for the deployed UI; the Vite dev server sets the same three on every response). The editor's TypeScript language service needs `SharedArrayBuffer`, which a browser exposes only in an isolated agent cluster; `require-corp` rather than `credentialless` because the UI loads no third-party subresource. A reverse proxy in front of Noite must pass response headers through unchanged (see Edge protection in the docs).
- **Code mode: no app-controlled code runs on the control UI's origin.** The whole workspace — Nodepod, the checkout, an install and its lifecycle scripts, the app's `dev` script and bundler config, a build, the Preview, and anything typed into the Terminal — is one document on the app's preview host (`app-0.preview.<slug>.<base>/noite-pod-host.html`), and it is the only document that creates the pod's process workers, so that code holds the preview origin's cookies and storage and not the control UI's session: it cannot call the control API as the signed-in viewer, and it cannot read any app's saved workspace out of the control origin's IndexedDB. The control page keeps the UI, the editor and every cookie-carrying call, and reaches the workspace over a `MessageChannel` that is origin-checked in both directions, handed over only after a nonce handshake and only to the frame the page itself embedded. The control origin answers 404 for every pod path — the host document, its bundle, Nodepod's process-worker bundle, its service worker and the dead preview bridge — so nothing a link can reach there creates a worker or registers a service worker. A page that cannot read the app's preview origin opens no workspace at all (it says so) instead of running without that separation, and a preview whose origin comes back empty is refused before anything is installed or run.

### Fixed

- Code mode showed a blank grid while a checkout opened, and a blank editor when nothing was open. While the workspace loads, the file tree and the editor now draw daisyUI skeletons shaped like their content (tree rows; a file header and code lines), announced to screen readers as **Opening checkout…**. The editor says **Select a file to view** when the browsed ref names no file to open, and **This repository has no files yet** when the branch holds nothing.
- Code mode's Preview stayed white in dark mode: the frame had a fixed white background, so an app that follows `prefers-color-scheme` (and the browser's own JSON and text views) drew its light dark-mode text on white. The frame now uses the theme's background; it already passes the page's color scheme to the app inside, and an app that declares no color scheme still gets the browser's light page.
- Hover tips in Code mode's editor died for the rest of the session after one placeholder: opening a binary or oversize file (or deleting the open file) painted over the container the tip lived in. The tip now hangs beside that container, so type info, diagnostics and declaration previews keep working.
- Switching branch, tag or commit in Code mode left the previous ref's tree wiring listening on the pane: a right-click on empty tree space opened a menu bound to the closed workspace (New file, Rename and Upload acted on a torn-down pod), and dropping files from the computer ran the upload twice. The wiring now tears its listeners down.
- A failed **Restart** in Code mode's Preview kept showing the old state and URL — a green **Ready** over a server that was gone. It now reports the error like a failed start does.
- A refused editor write left its warning banner in Code mode forever, still claiming the failure after later writes landed; the banner now clears on the next successful write.
- Code mode's editor shows the open file's change status. The header carries the same unpushed-change letter the file tree marks a row with (added, modified, moved, deleted), read from the workspace's own changes, so it survives a reload and follows a discard, an undo or another tab's write instead of being lost with the page. Previously the tree marked the row but the editor said nothing about the open file.
- A deploy failed with "parse wrangler config: trailing comma" when a `wrangler.jsonc` member ended with a comma followed by a comment.
- Push rules failed open: a push whose commands the runner couldn't parse skipped every check, so a push-role collaborator could force-push or delete `main`. Such a push is now refused, and git also enforces "no force-push, no delete" for every non-admin.
- Creating apps in parallel could go past the per-account app limit, and a losing create of the same slug could wipe the winner's repository. Creates are now serialized.
- The UI's git-auth reply no longer defaults to the push role when it names no role.
- Opening another file in the source browser threw away the unpushed edits of the file before, so a web commit could only ever change one file. Each change of `?file=` remounted the browser. Edits to any number of files now stay until you push them together.
- A boolean (`FLAG_…`) env var's toggle in Settings could keep showing on after it was turned off, until a reload: the control UI's ilha didn't write `checked={false}` back to a live checkbox. Bumped ilha to 0.15.2 and @ilha/router to 0.11.16, which also keep controlled `<select>` and `<textarea>` values in sync.
- The same bump made an in-place navigation leave a stale view behind: ilha reuses a keyed component without re-running it when its props are unchanged, and a `?query` read is not a reactive read, so a control that writes one (`?size=`, `?page=`, `?view=`, `?f=`, `?q=`, `?t=`, `?e=`, …) changed the URL while the grid, list or filter kept the old state — the storage editors, the admin searches and Code mode's panels among them. The control UI now reads search params through a wrapper whose reads subscribe the reading component to navigation, whether it reads the param itself or receives the handle as a prop.
- Preview binding data (Durable Objects, D1, KV, R2) no longer depends on the reload outrunning the workspace's debounced IndexedDB save: every write under the preview state's directory is mirrored synchronously into sessionStorage and overlaid after the restore, so a reload keeps counting, listing and reading where it left off. States past the mirror's size cap still fall back to the debounced save.
- Preview wrote its own tooling into the app: `srvx` and `vite` were installed with the pod's save-to-`package.json` flag, so the app's `package.json` gained them and showed up in Changes. They now install into the preview's harness directory beside the generated server, and the app's own dependencies install without being written back.
- Code mode: a workspace save that fails (a full browser store, a denied quota, a partition that went away) is now reported in the banner above the editor instead of only the console. The pod keeps retrying the save, so the banner is the only sign that what the editor shows is not being kept; the page's own `flush()`/`close()` rejections are reported the same way.
- Code mode's Preview refused to run on `https://noite.local` (a `CONTROL_EXTRA_HOSTS` name served over https by portless): the preview origin was always built on `BASE_DOMAIN`, so a `noite.localhost` dev base handed the secure page a plain-http `app-0.preview.<slug>.noite.localhost` frame and the panel showed the mixed-content refusal. The preview host now follows the page onto a DNS `CONTROL_EXTRA_HOSTS` entry (`https://app-0.preview.<slug>.noite.local`), which the edge already serves; bare IPs and the configured base keep today's origin.
- The app creator's mode tabs kept **Blank** highlighted after another mode was picked; the modes are now native radio cards.
- Creating an app with a slug someone already had showed the runner's raw error (`runner rpc apps.create: 409 slug already taken`) in a banner. The creator now says so under the Slug field and offers a free variant.
- Deleting an app could leave its celld running. The delete stopped the fleet and then spent seconds purging S3 while the app still counted as deployed, so the reconcile loop (or a request's wake) started it again, and with the row gone nothing stopped it. The orphan kept the app's port, and the next app given that port crash-looped on "Address already in use" and never served. A delete now marks the app stopped before purging and stops the fleet again after the row is gone, and every reconcile tick stops any fleet whose app no longer exists.
- Code mode could save a file's text from before its last keystrokes. The page ships one write per path at a time and held a typing burst's later text until the write in flight answered, so a flush asked for in between — a reload, a hidden tab, a closing tab — saved what the pod's volume held _then_: the last keystrokes of an edit the Changes panel already counted as a change were missing from the restored workspace (which, after a reload, showed the file with none of the edit). The page now ships whatever it still holds before it asks the pod to save. Even then, the pod's own save to IndexedDB is asynchronous and could die with the frame on a reload, so the checkout's unsaved writes (edits, new files, renames and deletes) are also mirrored synchronously into the tab's sessionStorage, the way the Preview's binding data already was, and replayed over the saved copy on the next open. The mirror empties itself whenever a save leaves nothing pending, so it never replays text older than what was saved.

## [0.1.0-alpha.3] - 2026-10-06

Opt-out instance telemetry, storage editors, the admin home, and a pre-release flow for releases.

### Operator action required

- **`RUNNER_BUILD_UID` and `RUNNER_BUILD_GID` are removed** and ignored if still set: delete them from your environment. Builds and release commands now run as one uid per app from a reserved range, `RUNNER_BUILD_UID_BASE` (default `10030`) and `RUNNER_BUILD_UID_RANGE` (default `1024`). The image pre-creates the default range in `/etc/passwd`; a custom range needs matching `/etc/passwd` and `/etc/group` entries, must stay below 65534 and must not contain `RUNNER_FLEET_UID` (10020).
- **Expect a one-time telemetry replay after the upgrade.** The runner re-reads the stored telemetry for the whole retention window (`RUNNER_TELEMETRY_RETENTION_DAYS`, 30 by default) for every app, to recover the rows the pre-alpha.2 ingest bug skipped. It runs in the background with no downtime; the cost is extra bucket reads and DuckDB CPU in proportion to window × apps. The runner logs `telemetry replay started` and `telemetry replay complete`. Telemetry older than retention was already pruned and cannot be recovered.
- Both databases upgrade themselves: the runner SQLite goes to schema version 5, the control D1 to 1.4.0. As before, an older image refuses newer data, so back up before upgrading.
- **This release adds anonymous instance telemetry, and it is on by default.** Once a day the instance sends one count-only heartbeat: the version, platform, storage kind, numbers of apps, deploys and users (users bucketed), install age and uptime. It is keyed by a random install id; no domains, names, emails or IPs are sent, and nothing at all is sent from a local domain. To turn it off, untick it in the Admin section of `/account`, or set `NOITE_TELEMETRY=0` (or `DO_NOT_TRACK=1`) in `.env`, which also locks the checkbox. The full list of fields is on [Telemetry](https://noite.now/self-hosting/telemetry).
- **A malformed `RUNNER_TELEMETRY_RETENTION_DAYS` now stops the runner at boot** with a config error. Before, it silently fell back to 14 days, though the documented default is 30. Unset still means 30.
- **Runner REST API callers:** status codes and one response changed; see Changed. Scripts that matched on 409 for storage or source errors, sent extra fields to `PATCH /v1/apps/{id}`, or read `remote` from the git-remote response need updating.

### Added

- Anonymous instance telemetry. The runner sends PostHog EU one `instance_heartbeat` event a day: no SDK, GeoIP lookup disabled, no person profiles. An Admin section on `/account`, shown to instance admins only and never while impersonating, turns it on or off and shows the exact payload. The runner API has `GET`/`PUT /v1/admin/telemetry` and RPC `telemetry.get`/`telemetry.set`. The installer prints a notice and accepts `NOITE_TELEMETRY`. Dev and e2e stacks never report.
- New login page: a product panel ("Push code. Get a URL.", three benefits, a deploy preview) next to a clean sign-in form, in light and dark, with a mobile layout. Sign in is the default tab; a fresh instance opens on "Set up Noite" and says the first account becomes the admin. Lost-passkey recovery is a separate view.
- First-run onboarding: a three-step tour after sign-in (push to deploy, one API key for Git and the CLI, stay in the loop: GitHub releases, Discord, GitHub Sponsors). Story-style progress bars, Back from the second step, arrow keys to move between steps, and a bottom sheet on mobile. The tour never navigates away: steps 1 and 2 spotlight the sidebar's Apps item and your avatar instead (skipped on mobile, where the sidebar is hidden). "Get started", × or Esc ends it for good. Accounts created before this release see it once.
- Admin home: `/apps` lists the control plane ("Noite · admin") for instance admins, and its page holds every admin tool: Overview, Metrics, Errors, Logs, Users, Apps and Invites tabs. Users, Apps and Invites are the panels god mode used, with the same actions and URL-kept searches. `/god-mode` and the account menu's "God Mode" item are removed. The whole page, and every admin action behind it, is refused while impersonating.
- D1 table editor (Storage → D1, and the control database on the Noite admin page):
  - **Layout:** a table list with row counts, a toolbar with search, filters, sort, refresh and Insert, Data and Definition views, and a side panel for editing rows. Paging, sorting, filtering and search run in SQL on the server, so they cover the whole table, not just the first rows.
  - **Row editor:** shows each column's type, primary key, NOT NULL, default and foreign key. NULL and the empty string are separate values, and an insert leaves untouched columns to their defaults. Helpers fill in "Now" timestamps, format JSON and toggle 0/1 columns; a foreign key opens the referenced row.
  - **Editing:** changed fields are highlighted and only they are saved. Delete asks for confirmation inside the panel, rows can be deleted in bulk (1–100 at a time, in one transaction), and a toast confirms every write.
  - **Control database:** read in-process by the control worker, never through `celld d1 execute`.
    - **Masked:** secret columns never leave the worker (session tokens, account passwords and OAuth tokens, verification codes, passkey keys, API keys). They can't be filtered, sorted or searched, so a secret can't be guessed piece by piece.
    - **Read-only:** the auth tables, except that deleting a `session` row revokes it. `user.role` and the ban columns are managed in the Users tab. Tables not explicitly allowed are read-only too.
    - **Your own row:** you can edit it but not delete it.
    - **Links:** a `user` row links to "Manage in Users", an `invite` row to "Manage in Invites".
- R2 browser (Storage → R2):
  - **Browsing:** breadcrumb navigation, folders, search within the current folder, list and column views, and pages of 100.
  - **Details panel:** an image or text preview, type, size, last modified and ETag, plus Download, Copy URL and Delete.
  - **Uploads and folders:** upload files (up to 64 MiB each) and create folders through `celld r2 put`, so an object carries the same record a Worker's `env.BUCKET.put()` writes, and the Worker reads uploads back as-is. Deletes go through `celld r2 delete`, including bulk deletes of up to 100 objects.
  - **Safe previews:** downloads use the object's own content type with `nosniff`, and SVG, HTML and XML are sandboxed.

Rows are keyed on the reserved `_control` slug with no `app` row, so reconcile, Caddy, scale-to-zero, purge and `GET /v1/apps` never see it. The Noite app page gains Overview, Metrics, Errors and Logs tabs (Logs include the control node's own output); instance admins only, never while impersonating. The numbers include the dashboard's own polling. `noite-runner telemetry reingest --slug _control` replays its window. `make dev` serves the UI from vite, not celld, so the page says telemetry needs the release image instead of showing empty charts.

### Changed

- Re-running the installer fills in any required `.env` setting that is missing or still at a dev default, instead of leaving the runner to refuse its config: the domain settings, ports, runner token, auth secret and RustFS keys. Values that are set are never changed, and the installer lists what it added. A missing `BASE_DOMAIN` is now asked for (or taken from `NOITE_DOMAIN`). Before, the installer stopped with "fix it or move it away".
- Telemetry ingest is idempotent and resumable. It works in hour-aligned chunks and replaces each window's minute buckets, span stats, log lines and error buckets instead of adding to them, so a retry, a catch-up after downtime or a replay never counts twice. After downtime the gap is read hour by hour, oldest first, bounded by retention.
- Telemetry ingest isolates a failing app: healthy apps keep aggregating while the broken one retries after a backoff. Apps that stopped (scale-to-zero, crash, runner shutdown) still get their remaining complete hours aggregated.
- Error issue counts are derived from the retained hour buckets, and logged-error capture is capped per app per hour (200) instead of per ingest pass.
- Boot order: signal handling, then Caddy, then every tenant fleet, then the REST listener, and only then the control UI deploy. A release that changes the UI bundle no longer delays tenant apps. Measured locally, 1, 5 and 15 apps all serve again within 5.1 s of the new container starting, and requests during that window are held at the edge, not refused.
- The nft egress policy matches the whole build uid range instead of a single build uid. The image no longer has a shared `build` user. `single` tenancy uses the same per-app uid path.
- Runner D1 API: `storage.d1.get` and its REST route are removed. `storage.d1.{tables,schema,rows,write,delete_rows}` and their REST equivalents under `/v1/apps/{id}/storage/d1/{database_id}/` replace them. Rows are read as JSON (`celld d1 execute --json`), and a write now treats `null` as SQL NULL and `""` as an empty string.
- Runner R2 API: listing takes `prefix` and `cursor` and returns folders plus content types. `PUT …/storage/r2/{bucket}/object?key=` uploads, and `storage.r2.delete` takes 1–100 `keys`.
- `oxidejs` 0.5.10 → 0.6.0, which drops the control UI's workarounds for the old behavior:
  - **Action typing:** the `checkedSchema` cast is gone; the server modules use `withSchema` directly, and the casts around awaited action results are removed.
  - **Errors:** user-facing action errors use oxide's `fail(message)` instead of the in-house `failAction`/`ActionError`, and error display no longer special-cases plain `{ message }` rejections, since action errors now arrive as `Error` objects.
  - **Database setup:** the once-per-isolate setup pass uses oxidejs `isolateOnce` (15 s timeout, 5 s wait) instead of a hand-written promise cache. On the release image it ran once per isolate, 3 passes across about 340 requests.
- Releases go through a pre-release. A `v*` tag publishes the version image and a GitHub pre-release with its CHANGELOG notes, but no longer moves `alpha` or `stable`. `curl -fsSL https://noite.now/run.sh | bash -s install --pre` installs the newest release, pre-releases included, pinned to its version. Marking the pre-release as a full release points `alpha` (and `stable` for a final version) at the same image, so plain installs and upgrades pick it up.
- Docs: the measured upgrade window replaces "about a minute for many apps".
- Runner API status codes. Storage and source failures used to answer 409 Conflict whatever went wrong. Now a missing object, table, deployed source or Git mirror is 404, an invalid path is 400, and an internal failure is 500. 409 is kept for real conflicts: a taken slug or hostname, a deploy in flight, or a web commit that lost the race against a push. RPC `events.*` returns 500 for a database error instead of 404.
- `PATCH /v1/apps/{id}` rejects unknown keys with 422, as RPC `apps.patch` already did, instead of ignoring them.
- The git-remote response (`GET /v1/apps/{id}/git-remote`, RPC `git.remote`) returns the URL once, as `url`. The duplicate `remote` field is gone.
- `/profile` is removed. Use `/account`.
- Invite codes on the account page and in the admin Invites tab stay visible, with a Copy button next to them. Before, the code itself switched to "copied" when clicked. Every copy button in the UI now behaves the same way.
- Codebase reorganization, no behavior change beyond the entries above:
  - **Runner API:** one service layer (`src/service/`) now implements both the REST and RPC APIs, replacing two copies that had drifted apart. New handler tests check that both give the same results.
  - **Large files split:** in the runner, `db.rs`, `host/metrics.rs`, `host/cmd.rs` and `main.rs`; in the control UI, the action modules, HTTP routes and the largest panels. The control UI's server-only code now lives in `lib/server/`.
  - **Generated types:** the runner's API types are generated for the UI, and CI fails when they are out of date.
  - **CI:** pull requests and release tags run the same reusable check workflow. Release tags were skipping the shell-script and schema checks.
  - **Docs:** the roadmap and design history moved from `SPEC.md` to `ROADMAP.md`.

### Fixed

- Deleting an app over RPC (what the control UI does) did not revoke its stored credentials; only the REST route did. Both now share one code path.
- Two builds running at once could read each other's worktree and build cache, because both ran as uid 10010.
- Rows skipped by the pre-alpha.2 ingest bug are recovered within retention by the one-time replay.
- A failed or partial telemetry pass no longer advances the watermark, one app's failing telemetry no longer stalls every other app, and compaction can no longer double count an hour whose source delete was interrupted.
- The app page's Stop button did nothing. The control UI sent `desired_state` to the runner's `apps.patch`, which reads `desiredState`, so the field was dropped and the patch changed nothing. It now sends the right key, and `apps.patch` refuses unknown parameters, so a mismatch shows an error instead of silently doing nothing.
- Dropdowns stayed open: after clicking an item that navigates, on a click outside them, and on Esc (the D1 Filter and Sort popovers only closed when their own button was clicked again). Every dropdown now closes on an item click, an outside click or Esc.
- A SIGTERM during boot killed the runner outright: fleets were SIGKILLed and the final state snapshot was lost. A stop now stops every fleet inside the stop budget and writes the snapshot at any point in boot.
