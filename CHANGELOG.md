# Changelog

Noite installs follow releases, not `main`. Pick a channel with `NOITE_IMAGE` (or `NOITE_VERSION` for the installer): `alpha` gets every promoted release, `stable` only final ones, and a version tag (`0.1.0-alpha.1`) holds an install in place. A release starts as a GitHub pre-release that only `run.sh | bash -s install --pre` installs; marking it as a full release moves the channels. `edge` and short-SHA tags are for CI and rollbacks.

Every release has an **Operator action required** section, even when it is "None". Read it before upgrading: an upgrade restarts the runner and every tenant fleet cold-boots, so batch upgrades.

Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Operator action required

- **The runner now checks for new releases once a day (opt-out).** Five minutes after boot and then hourly, the runner makes one anonymous `GET` of the public GitHub release list (`https://api.github.com/repos/ryuzcorp/noite/releases` — fixed URL, fixed User-Agent, no auth) and shows instance admins a dismissible banner when a newer promoted release exists on the install's channel. Nothing about the instance is sent — no version, no identifiers. To turn it off: clear **Check for new Noite releases** on `/account` (Admin tab), or set `NOITE_UPDATE_CHECK=0` in `.env` (the installer accepts it; `false` and `off` work too). The variable wins over the UI toggle. `make doctor` reports the check state and the newest release seen.
- **metrics.sqlite auto-migrates on boot: no action, no replay, no history loss.** The upgrade adds `environment_id` to the telemetry tables and rebuilds their primary keys around it, copying every row (existing rows become production). Downgrade across this change is unsupported, like every other downgrade.
- **Direct runner API callers:** RPC `limits.set` now takes the caller's `role` and refuses requests without the `admin` role, like the domains and environments mutations already do. Callers through the control UI are unaffected.

### Added

- **Admins hear about new releases.** The opt-out daily release check above feeds a dismissible per-version banner in the control UI shell (admins only; `dev` and SHA builds never notify) linking the release notes and the upgrade docs, plus `instance.update_status` (`GET /v1/admin/update`) for the toggle state, the running version and the newest release seen.
- **Per-environment telemetry.** Preview environments are first-class in telemetry: the ingest reads `envs/<slug>/<label>/telemetry/` alongside production, every metric/span/log/error row keys on `(app, environment)`, and the **Metrics** and **Errors** tabs scope by environment with a picker (Production first, then environments, `?env=` deep-links) while logs scope through the Deployments tab's environment groups. The sleep sweep parks environments on their own request activity, environment deploys keep source maps under their own prefix (environment errors symbolicate like production's), and the pull request page shows the head branch's environment card — status, URL, last deploy, links to its Metrics and Errors — or a **Create environment** action when there is none. MCP `app_logs` and `app_errors` take an optional `environment`. Custom events and the storage browsers stay app-wide.

### Changed

- **The Ilha + Void template lives at `ryuzcorp/noite-template-ilha`.** Its repository was renamed from `ryuzcorp/noite-template-oxide`, and new apps clone it under the new name. Installs on 0.1.0-alpha.8 and older keep creating apps from it: GitHub still serves git clones of the old name directly, with no redirect, which is what the runner's redirect-refusing clone needs (verified after the rename).
- **Runner state snapshots land faster and report their health.** The sync task polls for changes every 2 s (was 10 s), waits 5 s for bursts to settle (was 10 s) and uploads at most every 15 s (was a minute), so an ungraceful crash with a lost volume loses about 22 s of API mutations instead of about 70 s. Uploads are still skipped when the database bytes are unchanged, and the single-writer fence, the fail-closed restore and the snapshot format are untouched: no new config, and an older image reads the new snapshots. `/ready` gains an additive `snapshot` object (still the bucket owner, seconds since the last upload, last upload error) and `make doctor` prints it.
- **Observability reads without an environment mean production only.** The metrics, spans, devices, paths, refs, logs and errors endpoints and RPCs take an optional environment; absent or empty returns production rows, where production was previously the only data. The Events tab is always app-wide: custom event writes carry no environment identity.
- **Unpinned npm and pnpm projects run the image's bundled releases.** A deploy of a project that doesn't pin its package manager no longer resolves the registry's newest npm/pnpm (and downloads it per app): the runner names the exact bundled release (npm 12.2.1, pnpm 12.15.0) and seeds each app's `JUP_HOME` from the image's read-only store, so the manager itself never touches the registry. The app's own dependencies still come from the registry. A pin of any other release still downloads that release. Bumping a bundled release is an image release: upgrade to pick it up. The image grows by the 72 MB seed store (56 MB pnpm, 17 MB npm).
- **RPC `limits.set` now enforces the app role runner-side.** It takes the caller's `role` and requires `admin` (a missing, `view` or `push` role is a 403), the same defense in depth the domains and environments mutations already have. `limits.get` stays role-free like the other runner reads.

### Fixed

- **A failed snapshot meta upload is retried, not skipped.** The runner recorded a snapshot's hash as soon as the state object uploaded. If the metadata upload after it failed, the next pass saw identical bytes and skipped, leaving the bucket's `noite.sqlite.meta.json` stale (a new runner seeds its generation and skip hash from it) while `/ready` reported a fresh upload. The hash is now recorded only once both objects landed, and a skipped pass no longer resets the reported upload age.
- **App deletes and environment teardowns run to completion when the caller goes away.** The control plane times these calls out after 5 s, and a dropped request used to cancel the purge halfway — leaving the app row, the fleet and the scoped credentials behind. The destructive work now runs as its own task while the handler awaits it, so a disconnect only drops the waiter. A delete that finished server-side also no longer leaves a stale row behind: the admin apps list reloads after a failed mutation too, and the app's Danger Zone re-reads the app and follows the delete through when it is gone.
- **Deleting an app SIGKILLs its fleet first.** A graceful shutdown only does durability work the purge destroys a moment later, and young fleets regularly ignored SIGTERM for the whole grace — every slow delete in CI paid the full 3 s. Stops, sleeps and orphan sweeps keep the full graceful wait, and the 0.5 s settle before the S3 wipe stays.
- **S3 response bodies keep the request's own read deadline.** Every S3 body read now carries the same timeout as its request instead of relying on the HTTP client's internal total-timeout, so headers delivered with a body that never follows fail like a stalled send instead of hanging the caller.
- **A first deploy answers through the edge as soon as it reports success.** The runner added a new app or preview to the edge route table only after recording the deploy as successful. A request sent the moment the CLI, the UI or a script saw that success could get the "is starting" page (503) for a few milliseconds. The target is now routed first, and the deploy reports success after. A deploy whose route table the edge refuses now fails with the edge's answer, instead of reporting success for a target that isn't reachable. An edge that is restarting still lets the deploy through, because it boots from the table file, which already routes the target.
- **A just-created branch no longer misses from the branch picker.** A refs read overlapping a branch create could apply its pre-create manifest read, deleting the fresh ref from the push mirror (the picker's single refetch then cached its absence for the rest of the page); the same shape existed on the deploy-config read path, which synced with no seq check at all. Manifest re-apply is now double-checked under the slug's push mutex — an unlocked fast path serves local when the newest applied seq already covers the manifest, and only a newer manifest takes the guard and re-reads before syncing — and the applied seq never moves backward. Hot config readers serve local (cold hydration still syncs once), purge and slug-changing rename drop the slug's generation marker so a recreated slug's restarted seq applies rather than skipping as stale, and manifest staging uses a unique tmp path per call so a concurrent reader's download can never clobber a writer's flip.
- **The Errors, Deployments, Events, Logs and Metrics lists render their current data on load.** Every live list painted only stream frames, so a first frame delayed or lost anywhere between the runner and the browser left a skeleton until the data changed — for already-ingested data, forever. Each list now fetches its current snapshot once on a cold key (shared when a tab badge and its list use one key) and the stream keeps it live after; a failed fetch is ignored and stream frames always win once they arrive. New `errorList`, `listDeploys`, `eventsSnapshot`, `logTail` and `metricsFrame` actions serve those snapshots, view-gated like their streams.
- **A hung live-list snapshot fails visibly instead of holding a skeleton.** A first snapshot that hangs or fails every poll ended an open stream with no frames and no retry: the tab sat on skeleton with no banner. Every runner stream (errors, events, deploys, app state) and the log tail now ends with an error when no first frame arrives within 10 s, and the control hub drops a topic whose upstream opens but sends no first frame within 15 s — both surface as the retrying state the client already reopens, so the stall heals itself. The initial snapshot behind each list times out after 10 s too and is retried on a later paint. The `listDeploys` snapshot serves the same lean rows as the stream (finished rows carry no build log; fetch it on demand) while the runner list keeps full rows for API consumers, and `eventsSnapshot` rejects a non-integer or out-of-range `limit` with a 422 instead of a runner 500.

## [0.1.0-alpha.8] - 2026-10-21

Browser errors arrive through any Sentry SDK with stacks mapped back to your source, custom domains need DNS proof of ownership on multi-tenant installs, and every fleet holds bucket keys scoped to its own prefix. The edge no longer drops requests whenever an app starts, stops or deploys, and every pinned tool moves to its latest.

### Operator action required

- **Back up before upgrading: an install on 0.1.0-alpha.7 (runner schema version 8) upgrades itself to version 12 on boot** (Sentry ingest keys, custom-domain ownership claims, scoped bucket keys, the per-app memory override). An older image refuses the newer data.
- **Existing custom domains keep working.** Every custom domain attached before the upgrade is kept as verified.
- **Multi installs layer `docker/compose.multi.yaml` on, or stay at 503 on `/ready`; single installs change nothing.** Per-fleet memory caps need a writable cgroupfs mount, which the base compose no longer grants anything for: Docker mounts the container's cgroupfs read-only, and the multi overlay adds exactly `CAP_SYS_ADMIN` (one remount of the runner's own cgroup subtree at boot) plus lifting Docker's default AppArmor mount denial (`apparmor:unconfined`). The installer downloads both files and layers the overlay itself when `.env` says `NOITE_TENANCY=multi`. A compose file managed outside this repo (Coolify, hand-written files) must layer it by hand — every `compose` invocation names both files: `docker compose -f docker/compose.yaml -f docker/compose.multi.yaml up -d` Without the grant fleets share the container cgroup, `make doctor` prints the fix, and a `multi` install stays at 503 on `/ready` until the grant lands or the install drops to `single`. Railway installs are unaffected (they already run `single`). Rootless Podman cannot satisfy the grant (the remount is refused inside the user namespace), so a Podman `multi` install degrades loudly instead — run `multi` on Docker.
- **Direct runner REST callers:** `GET/POST /v1/apps/{id}/domains`, `DELETE …/domains/{hostname}` and the new `POST …/domains/verify` (RPC `domains.list|add|remove|verify`) now take the caller's `role` (`view` to list, `admin` to change) and refuse requests without it. The control UI, the CLI and MCP aren't affected.
- **Scoped bucket keys need nothing on bundled installs, one var on AWS.** `scoped_credential` replaces the never-written `app_credential` table, and every fleet and release command now holds keys limited to its own prefix — minted lazily at the next spawn or deploy, so existing installs pick them up with no manual step. What each backend needs: bundled RustFS and MinIO work with no configuration (verified against RustFS 1.0.0 and 1.0.3); AWS S3 needs `NOITE_CREDENTIAL_PROVIDER=aws` and an IAM-capable key (the runner creates one IAM user per app and environment); Cloudflare R2 has no prefix-scoped keys, so R2 installs run an explicit `root` mode. Root mode is never silent: the boot log, `/ready` (`credentials`), and `make doctor` all name it, and it warns loudly in `multi`.
- **The edge is stricter about odd requests.** Caddy 2.11 answers `431` past 16 KiB of request headers, drops header fields whose names contain `_` or `.`, and closes a body upload or response write that makes no progress for a minute (a quiet event stream between writes is unaffected). Apps behind the edge that relied on underscored or dotted headers, giant cookies or stalled uploads will see those requests fail where they used to pass.

### Added

- **Browser errors through any Sentry SDK.** Settings → Error reporting shows the app's DSN (`https://<key>@<control host>/<n>`, rotatable by admins). A stock Sentry SDK pointed at it reports exceptions to `POST /api/<n>/envelope/`, and they land in the Errors tab as the same issues as the Worker's own errors, labelled Browser (or SDK for server SDKs) with the page URL and release. Transactions, sessions, replays and other non-error items are accepted and dropped.
- **Error stacks show your original source.** Each production deploy keeps its source maps next to the bundle: the runner maps the deployed Worker itself, and browser maps come from your build if it emits them (Vite: `build.sourcemap: "hidden"`). The Errors tab maps each frame back to the original file, line and function, with the minified frame still shown beside it. There's no upload step. Maps are kept for the current deploy and the last 10 successful ones. Preview environments don't keep maps yet.
- **Custom domains need DNS proof of ownership on multi-tenant installs.** Before, any tenant could claim any hostname, first come first served. Now a new domain starts as _pending_, and Settings shows the TXT record to create (`_noite-challenge.<hostname>` with the domain's token) plus a **Verify** button that names what's wrong (no record, wrong value, DNS error). A pending domain gets no route and no certificate. Several apps may hold a pending claim for the same hostname, and the first to verify wins. On `single` installs a domain is verified as soon as it's added.
- **Fleets and release commands hold scoped bucket keys.** Each app's fleet and each preview environment's fleet now hold keys minted through the store's own IAM that read, write and list only their own prefix — an environment's keys never reach production's data, and no fleet reaches another app's. Covered per store (SPEC, Scoped credentials): bundled RustFS and MinIO through the MinIO admin API, AWS S3 through the IAM API, R2 and unrecognized stores on an explicit `root` mode. Renames supersede keys, deletes and environment teardowns revoke them (a retrying sweep finishes refused store deletes), and a deleted-then-recreated slug waits for the old key's revocation first. Release commands, which used to be skipped in `multi`, now run with the scope's own keys. The hostile e2e suite asserts a deployed Worker can't read another app's objects.
- **One fleet can no longer shed every app.** Each tenant fleet runs in its own cgroup v2 child with `memory.max` (`RUNNER_FLEET_MEMORY_MB`, 512 MiB by default) and `pids.max`, so a growing fleet is OOM-killed inside its own group — contained, and the supervisor restarts it — instead of pushing every fleet toward the shared shed threshold. Swap is disabled per leaf (`memory.swap.max=0`): without it the kernel swaps a capped fleet out instead of OOM-killing it. An OOM kill records a tenant-visible `fleet` app event and fleet log line (`fleet restarted: memory limit … MiB exceeded (Settings → Limits)`). `CELLD_MAX_RSS_MB` deliberately does not follow the per-fleet cap: celld measures container-scale working set, so a per-fleet value closed every fleet's ready gate in the lane. Settings → Limits gains a per-app **Fleet memory** override (applies on the fleet's next spawn), capped by the new operator knob `RUNNER_FLEET_MEMORY_MAX_MB` (default: the default cap, so a tenant can only lower its cap): the runner refuses a higher value in `multi` and clamps rows stored before the ceiling was lowered. The grant is narrow and multi-only (`docker/compose.multi.yaml`: `CAP_SYS_ADMIN` plus lifting Docker's default AppArmor mount denial — no `privileged`); single installs get nothing new. The hostile-tenant lane asserts each live fleet carries a positive `memory.max` and that `/ready` reports cgroups active.

### Changed

- **The Ilha + Void template replaces Oxide + ilha.** The creator offers exactly **Ilha + Void** and **TanStack Start**. Ilha + Void lives in the same repository, `ryuzcorp/noite-template-oxide`, now rewritten as Ilha pages on Void (Vite) with server-rendered pages, a server action and an island. The template id changed from `oxide` to `ilha-void` with no alias, so MCP `create_app` calls that pass `source: { kind: "template", template: "oxide" }` must switch to `ilha-void`. A new e2e spec creates an app from the template, waits for the deploy and checks that it serves.
- **E2E runs a fast gate on pull requests and the full suite on release.** The lanes run two suites over the same specs: `fast` (the tagged critical paths — create, push and deploy, logs, Code mode edits, PR merge, auth/invite gates, template deploy, rollback, environments, error ingest — plus the isolation-relevant set on the multi lane) and `release` (every spec, including the new storage-editing and admin-page coverage). Pull requests that touch runtime code run `fast` automatically; the `e2e` label runs `release`; every `v*` tag and a nightly run gate on `release`. Locally: `E2E_SUITE=fast make e2e`.
- **Every Docker-pinned tool moves to its latest.** celld 0.6.1 → 0.6.2, Caddy 2.10.0 → 2.11.7, esbuild sidecar 0.25.12 → 0.28.2, Node 24.21.0 → 24.22.0, rustfs 1.0.0 → 1.0.3, DuckDB 1.5.5 → 1.5.6, jup 0.6.3 → 0.6.5. The bun base images stay on the floating `1.4` line (1.4.3 is the newest 1.x). celld 0.6.2 bundles exactly as 0.6.1 did, so the runner's shadow bundle and the Errors tab's mappings are unchanged; the only celld behaviour to know about is a forwarded Durable Object `stub.fetch()` now rejecting when the owner's handler fails, a WebSocket answer to a request without `Upgrade: websocket` failing as a `TypeError`/500, and `self` being defined in Worker isolates. esbuild 0.28.2 changes output in two places that matter: the `binary` loader, which Noite bundles never select (the runner strips Wrangler `rules`, and celld's default is `.wasm=copy` only), and, since 0.27.5, TypeScript parameter properties under `"useDefineForClassFields": true`, which now use define semantics as `tsc` does. A Worker that relies on the old assignment order can behave differently after its next deploy. DuckDB, rustfs, Node and jup are bug-fix or additive releases with nothing that changes how Noite uses them. Tenant Workers are redeployed onto the new toolchain by their next deploy, and fleets restart on the new celld with the upgrade.

### Fixed

- **`install --pre` installs the newest release again.** It took the first entry of GitHub's release list, which puts the release marked Latest ahead of newer pre-releases, so it installed 0.1.0-alpha.6 instead of 0.1.0-alpha.7. It now picks the most recently published release. `run.sh` is served from noite.now, so the fix applies without a new image.
- **Status badges stay in sync.** After a deploy, a stop or a sleep, the app header's status and the Deployments tab's Production and environment dots kept the old state (a yellow "Deploying" dot after a finished deploy) while the sidebar moved on, until a reload. An app's pages now follow a live state stream (`/api/apps/:id/state/stream`) and refresh whatever it shows has changed, and the sidebar's app list updates every 2 s instead of every 10 s.
- **The Ilha + Void template no longer loses early input, and adding a todo no longer reloads the page.** Its todo form and About-page counter were server-rendered in place but worked only once the page's scripts had run. A todo typed and added before that turned into a plain form GET that reloaded the page without adding it, and an early counter click did nothing. Both now stay disabled until the page can handle them. The todo action also answered with a bare `{"ok":true}` instead of the page data Void's client expects, so every add reloaded the whole page; it now updates in place. The template is fetched from GitHub when an app is created, so the fix applies without a new image.
- **A rollback issued right after a deploy no longer vanishes.** **Roll back** answered OK, but if the app's previous deploy was still finishing, the rollback was silently skipped: no deploy row appeared, and the page kept waiting for a deploy that never started. A rollback now creates its queued deploy before answering and waits its turn behind the in-flight deploy, the way environment deploys already did. The runner's rollback response (`deploys.rollback`, `POST /v1/apps/{id}/rollback`) also returns the new `deployId`.
- **Deleting an app with a slow fleet no longer wedges later deletes.** `stop_fleet` waited 15 s for graceful shutdown before SIGKILL, so deleting an app whose celld was slow to exit (e.g. right after a (re)start) outlasted the UI's 15 s action timeout: the caller gave up, the half-finished delete held the per-app build/delete lock, and every retry answered `409 deploy in flight` forever. The lock is now a drop-guard (a cancelled, failed or panicked holder always releases it), and deletes stop the fleet with a 3 s grace instead of 15 s — the data is wiped right after, so a slow graceful shutdown is pure delay. Stops, sleeps and orphan sweeps keep the full grace.
- **Requests no longer drop when any app starts, stops or deploys.** Every app lifecycle event rewrote the Caddyfile and restarted Caddy, and each restart dropped in-flight requests transport-level (`ERR_EMPTY_RESPONSE`, `ECONNRESET`) with no log and no 5xx — hanging page loads and failing POSTs, since Go answers nothing when the read completes after shutdown began. Caddy's config is now static after boot; a small edge module (`edge/`, built into the image) holds a route table the runner pushes through Caddy's admin API on every lifecycle event, so app events never reload. Rate limits, the fleet readiness hold, wake-on-request, the env gate, frame headers and the starting page all behave as before.

## [0.1.0-alpha.7] - 2026-10-20

Fixes the Deployment logs pane alpha.6 shipped broken, makes every live panel recover on its own and share one connection per page, and makes "Running" mean the app actually serves.

### Operator action required

- None. No schema, config, DNS or certificate change.
- Behaviour to know about: a deploy now reports success only once its fleet answers celld's health check, waiting up to `RUNNER_WAKE_TIMEOUT_S` (120 s by default). A fleet that never becomes healthy fails the deploy with `fleet not healthy within …` where it used to report success.

### Fixed

- **Deployment logs stream again.** In 0.1.0-alpha.6 the Deployments tab's **Deployment logs** pane only said "Log stream disconnected — retrying…": the release image shipped without the control UI's `/api/apps/:id/logs/stream` route, which answered 404. A repo-wide ignore rule for `logs` directories had kept that file out of git.
- **Live panels recover on their own.** Deployment logs, deploy history, errors, events, usage and the app list went quiet for good, showing "… disconnected — retrying…", once the control UI or runner answered an error (a 502 while either restarts, say): the browser's `EventSource` does not retry after an HTTP error. They now reconnect with backoff (1 s up to 30 s), and the control UI answers a short 502 `runner unavailable` while the runner is down instead of failing the request.
- **"Running" means serving.** An app or environment showed **Running** as soon as its fleet was spawned, before celld listened, and a deploy reported success the same way. Both now wait for celld's health gate. A deploy whose celld exits before it serves fails at once, and one whose fleet is stopped or deleted in the meantime completes without waiting. A stop or delete during a deploy or start always wins over the status change.
- **Code mode: typing right after New File kept its order.** Under load, the first character typed into a new file could end up last (`xport const extra = 1;e`): the editor moved the caret back to the top after typing had begun.
- **The serving deploy's logs open on their own again.** The Deployments tab should open the deploy serving traffic with its logs showing. It stayed collapsed whenever the deploy list arrived before the app's details.
- **Pages with many live panels no longer freeze on plain-HTTP installs.** Each live panel held its own connection, and browsers allow six HTTP/1.1 connections per host. The Deployments tab with an environment reached six, so its links and API calls queued forever on `make dev`, LAN and other installs without HTTPS. A page now streams all its live panels over one connection (`/api/streams`), and a panel whose feed drops reconnects on its own while the others keep streaming. HTTPS installs (HTTP/2) weren't affected.
- **The login page's tabs and buttons wait for the page to be ready.** A click on **Create account** before the page had finished loading did nothing. The controls are now disabled until they can respond.

### Changed

- **CI:** the control UI and CLI unit tests run on every pull request and release tag; among them, a guard that every `/api/...` path the browser requests has a committed route file. The e2e lanes run spec files in parallel (3 workers) on a cached image build.

## [0.1.0-alpha.6] - 2026-10-20

The control UI moves to the Void framework, the CLI ships on npm as `@noitenow/cli`, and the runner gets stricter boot validation plus a round of concurrency and robustness fixes.

### Operator action required

- **Malformed numeric runner env vars now refuse boot.** A typo in any numeric `RUNNER_*`/`NOITE_*` setting, `NOITE_FLEET_PORTS`, the `RUNNER_BUILD_UID_BASE`/`RUNNER_FLEET_UID`/`RUNNER_FLEET_GID` sentinels, or the edge `NOITE_EDGE_*_RPM`/`RUNNER_WAKE_CONCURRENCY` knobs used to be silently ignored in favour of the default; the runner now fails once with a `config invalid` error naming each var, its bad value and the expected form. After upgrading, check `make doctor`/the runner logs for that error and fix the named variables. Unset (or empty, as Compose renders it) still means the default.
- **`HTTPS_PORT` now reaches the runner**, so the first-push URL follows the public edge instead of the runner API's raw port. Coolify/Railway installs should set `HTTP_PORT=80`/`HTTPS_PORT=443` (see the platforms docs); a prod install that leaves `HTTPS_PORT` unset links the 9443 dev default, which is unreachable.
- Otherwise none. No schema, DNS, or certificate change; no other env-var change.

### Added

- **Control UI on Void:** the control UI (`apps/noite`) migrates from Oxide to the Void framework on ilha 0.16 (`void@1.1.12` + `@ilha/void@0.1.4`), with the same routes, actions and serving contract. Behaviour is unchanged apart from the fixes below.
- **`@noitenow/cli` 0.1.0-alpha.6 on npm:** the published bundle runs on plain Node 20+ (previously it required Bun even when installed via npm). Every `v*` tag publishes the CLI at that exact version (dist-tag `alpha` for prereleases, `latest` for finals) after the release gate passes.
- `noite environments vars unset <environment> <name>` removes an environment variable override.
- A rollback end-to-end spec pins that rolling back to an earlier deploy serves that revision again.

### Fixed

- **Deployments include dotfiles** and redeploys drop stale ones; `noite deploy` prints the tenant's public host (`https://{slug}.{base}`, scheme/port from the git base) and keeps a path in the git base URL (`GIT_PUBLIC_BASE=http://host/v1/git` works now).
- **The first-push `remote: noite: …` line links the public edge URL** (`http://<slug>.noite.localhost:9080` in dev, `https://<slug>.<domain>` in prod) instead of the runner API's raw port.
- **Pod assets answer 404 on control hosts:** the runner-owned Caddyfile denies the six pod-asset paths (`/noite-pod-host.html/.js`, `/__sw__.js`, `/__worker__.js`, `/__nodepod_bridge__.html/.js`) on every control-host site before proxying, because the worker's asset fallback would otherwise serve them with a 200. The control UI's own bundle under `/assets/*` still serves, and preview-host behaviour is unchanged.
- **Runner concurrency:** creating, renaming or deleting apps while deploys or pushes are in flight no longer resurrects deleted data, races renames onto one slug, or orphans storage on malformed listings; snapshot runs no longer share temp paths, and a failed storage check at boot refuses to start instead of seeding a fresh generation.
- **Runner robustness:** S3 GET/PUT/LIST retry transient 5xx/SlowDown/transport errors (never 4xx); missing-key detection no longer mistakes key names or transport failures for "not found"; timed-out commands and stopped fleets kill the whole process group including grandchildren; deploy/log streams drop unserializable snapshots with a warning instead of blank events; snapshot setup failures surface as errors; expired or revoked credentials on delete/rename are logged; trailing-dot FQDNs pass the TLS gate like the custom-domain branch.
- Non-UTF-8 work-dir paths now fail the git request/deploy/rehydrate with an error instead of panicking the task, and a deploy whose target environment row is missing reports an error instead of crashing.
- Control UI server-rendering no longer crashes on the app-creation, onboarding and preview paths (browser-only globals guarded); a failed app grant rolls back the created row and surfaces the cause instead of masking it as a 500; deploy logs and file previews stay out of persistent snapshots.
- **Code mode could stay on the file you were leaving.** Clicking another file right after typing could leave the editor and `?file=` on the old file: the old file's last write settling after the click cancelled the open. The open now wins.

### Security

- The control UI is served cross-origin isolated: every document, module and worker script carries `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`, and its own assets `Cross-Origin-Resource-Policy: same-origin` (`apps/noite/public/_headers` for the deployed UI; the Vite dev server sets the same three on every response). The editor's TypeScript language service needs `SharedArrayBuffer`, which a browser exposes only in an isolated agent cluster; `require-corp` rather than `credentialless` because the UI loads no third-party subresource. A reverse proxy in front of Noite must pass response headers through unchanged (see Edge protection in the docs).
- **Code mode: no app-controlled code runs on the control UI's origin.** The whole workspace — Nodepod, the checkout, an install and its lifecycle scripts, the app's `dev` script and bundler config, a build, the Preview, and anything typed into the Terminal — is one document on the app's preview host (`app-0.preview.<slug>.<base>/noite-pod-host.html`), and it is the only document that creates the pod's process workers, so that code holds the preview origin's cookies and storage and not the control UI's session: it cannot call the control API as the signed-in viewer, and it cannot read any app's saved workspace out of the control origin's IndexedDB. The control page keeps the UI, the editor and every cookie-carrying call, and reaches the workspace over a `MessageChannel` that is origin-checked in both directions, handed over only after a nonce handshake and only to the frame the page itself embedded. The control origin answers 404 for every pod path — the host document, its bundle, Nodepod's process-worker bundle, its service worker and the dead preview bridge — so nothing a link can reach there creates a worker or registers a service worker. A page that cannot read the app's preview origin opens no workspace at all (it says so) instead of running without that separation, and a preview whose origin comes back empty is refused before anything is installed or run.

Bumped ilha to 0.15.2 and @ilha/router to 0.11.16, which also keep controlled `<select>` and `<textarea>` values in sync.

The pod keeps retrying the save, so the banner is the only sign that what the editor shows is not being kept; the page's own `flush()`/`close()` rejections are reported the same way.

- Deleting an app could leave its celld running. The delete stopped the fleet and then spent seconds purging S3 while the app still counted as deployed, so the reconcile loop (or a request's wake) started it again, and with the row gone nothing stopped it. The orphan kept the app's port, and the next app given that port crash-looped on "Address already in use" and never served. - Code mode could save a file's text from before its last keystrokes. The page ships one write per path at a time and held a typing burst's later text until the write in flight answered, so a flush asked for in between — a reload, a hidden tab, a closing tab — saved what the pod's volume held _then_: the last keystrokes of an edit the Changes panel already counted as a change were missing from the restored workspace (which, after a reload, showed the file with none of the edit). Even then, the pod's own save to IndexedDB is asynchronous and could die with the frame on a reload, so the checkout's unsaved writes (edits, new files, renames and deletes) are also mirrored synchronously into the tab's sessionStorage, the way the Preview's binding data already was, and replayed over the saved copy on the next open. ## [0.1.0-alpha.3] - 2026-10-06

Opt-out instance telemetry, storage editors, the admin home, and a pre-release flow for releases.

### Operator action required

- **`RUNNER_BUILD_UID` and `RUNNER_BUILD_GID` are removed** and ignored if still set: delete them from your environment. Builds and release commands now run as one uid per app from a reserved range, `RUNNER_BUILD_UID_BASE` (default `10030`) and `RUNNER_BUILD_UID_RANGE` (default `1024`). - Per-app build uid: builds and release commands run as the app's own uid (`app.build_uid`, allocated on its first build), and its worktree and build cache are `0700`. The hostile-tenant e2e suite now checks that a build cannot read a sibling app's worktree or cache.
- `noite-runner telemetry reingest [--since <RFC3339|duration>] [--slug <slug>] [--no-wait] [--timeout <seconds>]`: replay a telemetry window into `metrics.sqlite`, bounded by retention. Safe to repeat.
- `install.sh` warns before an upgrade that recreates the container, and asks once when it has a terminal. `--yes`, `NOITE_YES=1` or `NOITE_CONFIRM=1` skip the prompt; a fresh install, or a re-run whose image did not change, asks nothing.
- Boot-phase log lines with elapsed milliseconds (`tenant fleets booting; control UI deploys next`, `control bundle ready`).
- Docs link in the account menu.
- GitHub Sponsors button on the repository (`.github/FUNDING.yml`).

### Changed

- Re-running the installer fills in any required `.env` setting that is missing or still at a dev default, instead of leaving the runner to refuse its config: the domain settings, ports, runner token, auth secret and RustFS keys. Values that are set are never changed, and the installer lists what it added. A missing `BASE_DOMAIN` is now asked for (or taken from `NOITE_DOMAIN`). Before, the installer stopped with "fix it or move it away".
- Telemetry ingest is idempotent and resumable. It works in hour-aligned chunks and replaces each window's minute buckets, span stats, log lines and error buckets instead of adding to them, so a retry, a catch-up after downtime or a replay never counts twice. After downtime the gap is read hour by hour, oldest first, bounded by retention.
- Telemetry ingest isolates a failing app: healthy apps keep aggregating while the broken one retries after a backoff. Apps that stopped (scale-to-zero, crash, runner shutdown) still get their remaining complete hours aggregated.
- Error issue counts are derived from the retained hour buckets, and logged-error capture is capped per app per hour (200) instead of per ingest pass.
- Boot order: signal handling, then Caddy, then every tenant fleet, then the REST listener, and only then the control UI deploy. A release that changes the UI bundle no longer delays tenant apps. Measured locally, 1, 5 and 15 apps all serve again within 5.1 s of the new container starting, and requests during that window are held at the edge, not refused.
- The nft egress policy matches the whole build uid range instead of a single build uid. The image no longer has a shared `build` user. `single` tenancy uses the same per-app uid path.
- Runner D1 API: `storage.d1.get` and its REST route are removed. `storage.d1.{tables,schema,rows,write,delete_rows}` and their REST equivalents under `/v1/apps/{id}/storage/d1/{database_id}/` replace them. Rows are read as JSON (`celld d1 execute --json`), and a write now treats `null` as SQL NULL and `""` as an empty string.
- Runner R2 API: listing takes `prefix` and `cursor` and returns folders plus content types. `PUT …/storage/r2/{bucket}/object?key=` uploads, and `storage.r2.delete` takes 1–100 `keys`.
- `oxidejs` 0.5.10 → 0.6.0, which drops the control UI's workarounds for the old behavior:
  - **Action typing:** the `checkedSchema` cast is gone; the server modules use `withSchema` directly, and the casts around awaited action results are removed.
  - **Errors:** user-facing action errors use oxide's `fail(message)` instead of the in-house `failAction`/`ActionError`, and error display no longer special-cases plain `{ message }` rejections, since action errors now arrive as `Error` objects.
  - **Database setup:** the once-per-isolate setup pass uses oxidejs `isolateOnce` (15 s timeout, 5 s wait) instead of a hand-written promise cache. On the release image it ran once per isolate, 3 passes across about 340 requests.
- Releases go through a pre-release. A `v*` tag publishes the version image and a GitHub pre-release with its CHANGELOG notes, but no longer moves `alpha` or `stable`. `curl -fsSL https://noite.now/run.sh | bash -s install --pre` installs the newest release, pre-releases included, pinned to its version. Marking the pre-release as a full release points `alpha` (and `stable` for a final version) at the same image, so plain installs and upgrades pick it up.
- Docs: the measured upgrade window replaces "about a minute for many apps".
- Runner API status codes. Storage and source failures used to answer 409 Conflict whatever went wrong. Now a missing object, table, deployed source or Git mirror is 404, an invalid path is 400, and an internal failure is 500. 409 is kept for real conflicts: a taken slug or hostname, a deploy in flight, or a web commit that lost the race against a push. RPC `events.*` returns 500 for a database error instead of 404.
- `PATCH /v1/apps/{id}` rejects unknown keys with 422, as RPC `apps.patch` already did, instead of ignoring them.
- The git-remote response (`GET /v1/apps/{id}/git-remote`, RPC `git.remote`) returns the URL once, as `url`. The duplicate `remote` field is gone.
- `/profile` is removed. Use `/account`.
- Invite codes on the account page and in the admin Invites tab stay visible, with a Copy button next to them. Before, the code itself switched to "copied" when clicked. Every copy button in the UI now behaves the same way.
- Codebase reorganization, no behavior change beyond the entries above:
  - **Runner API:** one service layer (`src/service/`) now implements both the REST and RPC APIs, replacing two copies that had drifted apart. New handler tests check that both give the same results.
  - **Large files split:** in the runner, `db.rs`, `host/metrics.rs`, `host/cmd.rs` and `main.rs`; in the control UI, the action modules, HTTP routes and the largest panels. The control UI's server-only code now lives in `lib/server/`.
  - **Generated types:** the runner's API types are generated for the UI, and CI fails when they are out of date.
  - **CI:** pull requests and release tags run the same reusable check workflow. Release tags were skipping the shell-script and schema checks.
  - **Docs:** the roadmap and design history moved from `SPEC.md` to `ROADMAP.md`.

### Fixed

- Deleting an app over RPC (what the control UI does) did not revoke its stored credentials; only the REST route did. Both now share one code path.
- Two builds running at once could read each other's worktree and build cache, because both ran as uid 10010.
- Rows skipped by the pre-alpha.2 ingest bug are recovered within retention by the one-time replay.
- A failed or partial telemetry pass no longer advances the watermark, one app's failing telemetry no longer stalls every other app, and compaction can no longer double count an hour whose source delete was interrupted.
- The app page's Stop button did nothing. The control UI sent `desired_state` to the runner's `apps.patch`, which reads `desiredState`, so the field was dropped and the patch changed nothing. It now sends the right key, and `apps.patch` refuses unknown parameters, so a mismatch shows an error instead of silently doing nothing.
- Dropdowns stayed open: after clicking an item that navigates, on a click outside them, and on Esc (the D1 Filter and Sort popovers only closed when their own button was clicked again). Every dropdown now closes on an item click, an outside click or Esc.
- A SIGTERM during boot killed the runner outright: fleets were SIGKILLed and the final state snapshot was lost. A stop now stops every fleet inside the stop budget and writes the snapshot at any point in boot.

celld 0.6.1 and telemetry ingest fixes.

## [0.1.0-alpha.1] - 2026-10-01

First alpha: self-hosted only. There is no cloud version.

### Operator action required

- **Installs that pulled `:latest` must change tag.** `latest` is no longer published; it stops at the last build from `main`. Re-run the installer (it rewrites `NOITE_IMAGE` and keeps your `.env`), or set `NOITE_IMAGE=ghcr.io/ryuzcorp/noite:alpha` yourself (Compose, Coolify, Railway).
- **No database migration needed.** The runner stamps its SQLite with a schema version and the control D1 keeps a migration ledger; both start here. A database written by a newer release is refused at boot with a message, so a downgrade fails loudly instead of corrupting data.
- **Lost-passkey email is now actually sent.** Before this release the `NOITE_EMAIL_WEBHOOK_URL` was not read on the sign-in path, so on a real domain the code was logged by the control UI instead of delivered. If you set a webhook, it starts receiving codes now. With no webhook, recover with `docker exec noite noite-runner recover`.

### Added

- `noite-runner recover [--email <address>]`: prints a one-time sign-in code for the "Lost passkey?" screen, for operators with no email webhook.
- Schema versioning for upgrades without a wipe: `PRAGMA user_version` plus numbered migrations for the runner, a downgrade guard on the control D1 ledger.
- Release channels (`alpha`, `stable`) and version tags; the e2e lanes (`make e2e`, `make e2e-isolation`) gate every release tag.
- `SECURITY.md` and a known-limits page.

### Changed

- God mode: Users, Apps and Invites share one layout and the same search (input and Search button, kept in the URL), so tabs no longer shift.
- Changing an app's slug moved from the Identity card to its Danger Zone.

- Multi-tenant mode is documented as **semi-trusted tenants** for the alpha: see Self-hosting → Known limits.
