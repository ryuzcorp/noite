# Changelog

Noite installs follow releases, not `main`. Pick a channel with `NOITE_IMAGE` (or `NOITE_VERSION` for the installer): `alpha` gets every promoted release, `stable` only final ones, and a version tag (`0.1.0-alpha.1`) holds an install in place. A release starts as a GitHub pre-release that only `run.sh | bash -s install --pre` installs; marking it as a full release moves the channels. `edge` and short-SHA tags are for CI and rollbacks.

Every release has an **Operator action required** section, even when it is "None". Read it before moving versions: re-running the installer upgrades in place (`.env` and the volumes stay) and every tenant fleet cold-boots behind the edge.

Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [0.1.0-alpha.36] - 2026-11-14

### Operator action required

- None. `/account?t=admin` still works (it redirects); an operator who wants telemetry off or release checks disabled finds both switches on the control page's **Settings** tab, and the same environment variables (`NOITE_TELEMETRY`, `NOITE_UPDATE_CHECK`) still win over them.
- **Clients that posted JSON-RPC to `POST /rpc` must move to the REST `/v1` equivalents listed above.** The mirror answered `200` with a JSON-RPC `error.code`; the REST routes answer the HTTP status itself (`400`/`403`/`404`/`409`/`500`) with the runner's message as a plain-text body, so a client that parsed `error.code` or JSON-RPC batches needs its status handling updated. No configuration or data migration is involved, and the control UI ships with the image, so nothing else changes on upgrade.
- Remove `RUNNER_DUCKDB_MEMORY_MB`, `RUNNER_DUCKDB_THREADS` and `RUNNER_DUCKDB_TEMP_MB` from your `.env`/compose environment. They are ignored rather than fatal (the runner reads only the variables it knows and compose no longer forwards them), so an unchanged environment file does not break the upgrade — but the settings no longer do anything.
- The first boot after the upgrade drops the five retired telemetry tables from `metrics.sqlite`. No other table is touched and nothing needs to be done by hand. Their pages move to SQLite's freelist and are reused by later metrics writes; the file does not shrink on disk.
- Anything scraping `/devices`, `/paths`, `/refs` or `/spans` must stop: those routes are gone. `/metrics` keeps its path but returns hour buckets and no longer carries `latencyMs` — read `p50Ms`/`p95Ms` for latency.

### Added

- Hourly per-fleet counters in `metrics.sqlite`, the DuckDB-free replacement for the minute buckets: `app_hour` keeps one row per `(app, environment, hour)` with requests, 5xx errors, p50/p95 latency, peak and mean memory, CPU time and the newest request stamp, and `app_hour_lat` keeps the fixed log-scale latency histogram the percentiles are derived from. Requests, errors and latency come from the Caddy access log (`duration`/`status` on the line the error index already tails), counting only lines a fleet's own `reverse_proxy` answered: the `:80` redirect, a gate refusal, an edge rate-limit answer and the edge's error page never touch the counters. Memory from each fleet's cgroup charge sampled every tick (peak and mean, `_control` included), CPU from the existing `/proc` sampler. Writes replace the fleet's open hour instead of incrementing it, the access-log offset still advances only after a line's rows commit, and the rows are pruned with `RUNNER_TELEMETRY_RETENTION_DAYS`. Write-only for now: no route or UI reads these tables yet.

### Changed

- **Every admin surface is in one place.** The instance-wide switches left `/account`: the anonymous-telemetry opt-out and the release check now live on the control page's new **Settings** tab (`/apps/_control?t=settings`), next to Users, Apps and Invites. `/account` is personal settings only — profile, passkeys, API keys, your own invite codes and agent connect — and the header keeps its `admin` badge. Nothing loosened: both actions still refuse anyone but a real instance admin on the server (`requireControlAdmin`), and `/apps/_control` still answers "App not found." to everyone else. The retired `/account?t=admin` link (docs, bookmarks) redirects to the Settings tab, and the docs, `SPEC.md`, `README` and the website pages name the new home.
- App detail: the Overview errors card, the Errors and Events tabs and the Deployments log panes share the page's heading and padding rhythm. Each tab has one section heading (the duplicate one above the card is gone), the Errors status tabs sit beside the "Errors" heading with the current count, the deployment/build log block pads like the group header above it, and an environment's header names the branch it deploys next to its commit.
- App Settings: the in-page section tab strip is gone; every section still stacks on the one page, and `?section=` deep links still scroll to their heading.
- **The runner's JSON-RPC mirror is gone.** `POST /rpc` (`apps/runner/src/api/rpc.rs`, the `axum-jrpc` dependency and its parity tests) is removed; the control UI's runner client, the MCP tool table, envelope ingest and the e2e suites all call the REST `/v1` surface directly, so there is one transport left to maintain and one error model (an HTTP status plus the runner's own plain-text message).
- The REST surface gained the routes that only the mirror had, so every former RPC caller has an equivalent: `GET /v1/apps/by-slug/{slug}`, `GET`/`PUT /v1/apps/{id}/limits`, `GET /v1/apps/{id}/errors?status=&environmentId=`, `GET`/`PATCH /v1/apps/{id}/errors/{fingerprint}`, `GET /v1/apps/{id}/errors/ingest-key?role=`, `POST /v1/apps/{id}/errors/ingest-key/rotate?role=`, `POST /v1/errors/ingest` (project-addressed, the key carries the app) and `POST /v1/apps/{id}/storage/r2/{bucket}/delete` (1..100 keys in one batch).
- The API reference (`apps/website/docs/reference/api.mdx`) documents those routes and no longer has an RPC section; `SPEC.md` and `AGENTS.md` describe the runner as a single REST transport.
- **The image no longer ships the DuckDB CLI, and the runner no longer has a DuckDB-shaped configuration.** `docker/install-sidecars.sh` installs only esbuild (its pin guard and the arm64 image leg follow), and `RUNNER_DUCKDB_MEMORY_MB`, `RUNNER_DUCKDB_THREADS` and `RUNNER_DUCKDB_TEMP_MB` are gone from the runner's config, `.env.example`, the compose file and the docs: telemetry Parquet is read and folded in-process with a bounded working set (one 256 MiB object at a time), so there is no per-pass memory cap or spill directory left to size.
- **The dead telemetry tables are dropped on boot.** `metrics.sqlite` no longer defines `app_metric` (minute buckets), `app_device_stat`, `app_path_stat`, `app_ref_stat` (access-log analytics) or `app_span_stat` (hourly span stats), and their writers and prunes are removed with them. Nothing has read those tables since the hourly counters replaced them; attaching the database now runs an idempotent `DROP TABLE IF EXISTS` for each, so an upgraded install stops carrying them on its first boot and a fresh install never creates them. The pages go to SQLite's freelist and are reused by later metrics writes — the file itself does not shrink (nothing vacuums `metrics.sqlite`). `app_hour`, `app_hour_lat`, `app_log`, the watermarks, the compaction marks, the error tables and `metric_version` are unchanged.
- The docs, `SPEC.md`, `README.md`, `AGENTS.md` and the environment-variable tables describe the in-runner reader; the `make usage` counter section and the runner's `duckdb` spawn counter, which the previous layer already stopped feeding, are gone from the docs.
- `@ilha/void` 0.1.6 → 0.1.7, which raises its `ilha` peer to `>=0.16.3` (the version the UI already runs). The release carries no runtime or type changes — its published bundle is byte-identical to 0.1.6 — so the control UI's behaviour is untouched.
- The **Metrics** tab and `GET /v1/apps/{id}/metrics` now serve **hourly** counters instead of minute buckets, straight from the edge: each row is one `(app, environment, hour)` with the served request count, its 5xx errors (the tab shows the error rate), p50 and p95 latency, the fleet's peak and mean memory, and CPU time. The tab keeps the request, error and CPU bars, adds per-hour p50/p95 latency and memory charts, and the tiles show requests, error rate, p50/p95, peak memory and CPU. Memory and the percentiles are new; the old average latency (a sum) is gone.
- `GET /v1/apps/{id}/metrics` rows are `{appId, bucketTs, requests, errors, p50Ms, p95Ms, memoryMaxBytes, memoryAvgBytes, cpuMs}` and `bucketTs` is an hour stamp. `GET /v1/apps/{id}/metrics/version` now also moves when a counter row is rewritten, so the dashboard refreshes on the next poll instead of waiting for a telemetry flush.
- **Breaking:** `GET /v1/apps/{id}/devices`, `/paths`, `/refs` and `/spans` (and the `spans.get` RPC) are removed, together with the Metrics tab's Spans table and the Analytics cards (browsers, operating systems, paths, referrers). Their tables are still written until the DuckDB stack is removed, but nothing reads them.
- Scale-to-zero now reads the hourly counters' exact request stamp, so idle detection is no less precise than before (hour granularity alone would have loosened it by up to an hour).
- **The runner reads celld telemetry Parquet itself.** Errors and Logs no longer come from a DuckDB CLI query: the ingest lists each chunk's hour directories through the S3 client, decodes only the columns it needs with the `parquet` crate (no `arrow`; zstd, snappy, gzip and lz4 are all readable), and keeps the same newest-5000-log-lines and top-200-failed-span-group rules. Failed-span groups are aggregated one event hour at a time with compact 16-byte trace ids and a 1,000,000-distinct-trace ceiling per group and hour (one warning), so a hot error loop can no longer grow the runner's heap without bound; a corrupt or foreign object is skipped with a warning instead of holding the fleet's watermark. Watermarks, chunk planning, per-fleet fault isolation, replace semantics and the replay CLI are unchanged.
- **Hourly Parquet compaction is written by the runner.** The scheduled fold that keeps an hour to one object (and deletes the sources only after the copy is proved) now unions the inputs with the Parquet writer instead of `COPY` through DuckDB, preserving every input column by name and the unsigned annotations celld writes (`kind` UTINYINT, `http_status` USMALLINT). An hour whose fold would produce an object the ingest refuses (inputs over a 160 MiB budget, or an output over the 256 MiB cap) is left raw — sources kept and readable — and never blocks later hours. DuckDB is no longer invoked by the ingest or the compaction; the binary stays in the image until the follow-up removal.
- `make usage` no longer prints the `[duckdb]` counter section (the runner never runs DuckDB now).
- **A PR is built for one review round.** `AGENTS.md` now states the cycle-time rules: one push per round (collect every finding — CodeRabbit threads, security review, CI — fix them all, push once), CI green and every CodeRabbit thread answered before the independent security review and the merge queue, CodeRabbit treated as advisory (a rate-limited free-tier bot never blocks a merge; a valid late finding becomes a roadmap candidate unless it is release-blocking — a security, isolation or data-integrity defect ships only after the fix), and a ~800-changed-line cap per PR with the excluded lockfiles, generated bindings and `changelog.d/` fragments spelled out — a bigger item is split, dependent layers as a GitHub stack (`gh stack`), independent items as parallel PRs.
- **CI's e2e lanes replace the pre-PR local lanes.** PR CI runs the fast suite on both lanes (`@fast` on single, `@isolation` on multi) in ~5 min and the merge queue runs the full `release` suite on both lanes before anything lands, so the full local `make e2e`/`make e2e-isolation` before opening a PR is gone; a local run is for reproducing a failure with an `E2E_SPECS=` subset, plus the release-image smoke test (`TAG=<sha> make e2e`).
- **CodeRabbit reviews each PR once.** `.coderabbit.yaml` sets `reviews.auto_review.auto_incremental_review: false`, so a later push no longer spends a review or delays the round; `@coderabbitai review` requests another pass after a substantial change.
- The sidebar's live app list is part of the shell now: it shows on every page, not only under `/apps` and `/storage`. It reads the same live stream the `/apps` list does (one SSE topic, one connection per page, and the cached snapshot across navigations — no refetch per page), and an app's row still expands into App, Code, Pull requests and Settings with the part of the app the URL is in highlighted.
- Code mode's file tree is a slide-over below `lg` (opened from a Files button in the code bar, closed by picking a file), so the editor gets a phone's full width instead of a ~100px sliver.
- The new-pull-request form labels its base and head pickers, caps its width like the app's other forms, and lists the reasons Create is off in a box of its own instead of three grey lines.
- A pull-request row keeps its metadata on one readable line on a phone, with the age below it rather than in a squeezed third column.

### Fixed

- The new-pull-request page crashed (`Cannot read properties of undefined (reading 'length')`) whenever the picked base and head were a real pair: ilha keys an atom by its allocation order inside the fiber's render, and a compare resource created only once the picks differed shifted every later atom by one — the compare inherited the pull-request list's atom and the summary read `files` off that payload. The compare now lives in its own component keyed by the pair, so each pair gets its own resource and the form's own allocation sequence never changes.
- `PROJECT=<name>` now actually selects the compose project: the Makefile passes `-p $(PROJECT)` on every compose invocation (default stays `noite`), so `make dev PROJECT=x` no longer recreates the default `noite` stack. Before, `docker/compose.yaml`'s hard-coded `name: noite` won over `PROJECT` (and over `COMPOSE_PROJECT_NAME`), so a second-stack run silently recreated the first one. The file's `name:` is `${COMPOSE_PROJECT_NAME:-noite}` now — still `noite` when unset — and the name is validated once (lowercase `a-z`, `0-9`, `-`, `_`), so a stray value fails before it becomes an engine flag. `COMPOSE` is no longer overridable (an operator sets `COMPOSE_CMD`), `make doctor`/`make backup`/`make restore` follow the same project (a backup snapshots that project's own runner, and refuses rather than guess when it cannot find it), and `docker/uninstall.sh` honours `PROJECT`/`COMPOSE_PROJECT_NAME` and prints the project it will remove (refusing when that project has no stack), with `run.sh` forwarding both through `sudo`.
- A burst skip in the access-log tail (over 8 MiB unread in one tick, when every buffered line is dropped) is now recorded as an instance setting and makes the idle sweep skip that app while the skip falls inside its sleep window. Before, one flooded feed could park actively-served apps on the next sweep; explicit sleeps and memory-pressure parking are unaffected.
- **New File in the source tree no longer paints `Internal error (HTTP 500)` over the file it just opened.** The tree parks an `untitled` placeholder row for pierre's inline name input, and a selection event for that row (delivered when the row is added, or late from a tree a rebuild replaced) was turned into a blob read of a path no commit holds. The runner answered 404 and the pane painted the failure — sometimes after the real file had opened, so the editor never mounted. `lib/source/browser.tsx` now opens only a path the session holds (a committed file, a buffer, or a move's destination); a placeholder row is refused instead of read.
- App detail on a phone: the selected tab scrolls fully into view, and the tab strip has no visible scrollbar. The status line separates its facts by spacing, so no stray "·" starts or ends a wrapped line. The deploy row keeps its date and duration whole, and the log tabs align with the log text. Environment cards share one left edge, with the history toggle at the end of the header, and the Redeploy and Variables buttons are icon-only.
- The phone sidebar closes when a destination in it is tapped — an app, the app's own items, or an item in the profile menu — instead of staying open over the page it navigated to. The profile row itself still opens its menu.
- The phone sidebar has breathing room above the Apps item, and Esc closes it and returns focus to the toggle. The toggle is a real button now, so the drawer can be opened from the keyboard too.
- Nothing on a page can paint over the open phone drawer any more: the page column is one stacking context below `lg`, so a page's own `z-*` chrome (the sticky top bar, a sticky tab row, the app header's Deploy dropdown at `z-50`) is covered by the drawer instead of drawing through it. On phones the overlay also dims the page harder (60% instead of 40%), so the app list reads as the front layer.
- The create page's drag-and-drop hint wraps as one paragraph instead of breaking into three ragged columns (its `<p>` was a flex container, so each text node became a flex item).

## [0.1.0-alpha.35] - 2026-11-13

### Operator action required

- None.

### Added

- The app overview's **Deploy** menu has a branch picker: pick any branch and deploy its current tip to production once, without merging or changing the production branch. The default selection is the production branch, which behaves exactly like **Redeploy**. Deploy history labels the run `Deploy <branch>@<sha>`, and the next push to the production branch deploys as usual.
- `POST /v1/apps/<id>/deploy {ref}` (RPC `deploys.deploy`) deploys one branch's tip to production; push role required, admin-only while the app's branch protection is on. The deploy row records the new `branch` intent with the branch ref in `actor`.

### Changed

- The Deployments tab renders each environment as a layer card: the environment's name, status, URL and actions sit in a header strip on a slightly different surface than the deploy rows in the card body (production included), so an environment's history reads as one card instead of a header next to a separate list.
- `docker/check-versions.ts` splits its online leg: `--online` compares the immutable publisher pins (Node's signed `SHASUMS256.txt`, npm's `dist.integrity`, the GitHub release-asset digests, rustup's checksum) and gates every pull request; `--online-images` adds the image tag index digests. Official images re-push the same tag for a base-OS update, so `check.yml` resolves image digests only for a PR that changes a pin (`docker/Dockerfile`, `docker/compose.yaml`, CI's `rustfs` service or `platforms.mdx`), and the new weekly `pin-drift.yml` run does the full check and keeps one `Image pin drift` issue open while a pin no longer matches its publisher.
- The Settings page's section links are a daisyUI tab strip that sticks to the top while the sections scroll. It marks the section currently in view (scrolling updates the marker, not only clicks), stays on one row and scrolls sideways on narrow screens, and moves focus with Left/Right/Home/End.
- The open file's name header stays pinned at the top of the code pane while a long file scrolls under it, in both themes and on narrow panes (long names truncate).

### Fixed

- A D1 database with more than five tables lists its tables again. The row counts were one `SELECT … UNION ALL …` statement, and celld applies workerd's SQLite budget (`SQLITE_LIMIT_COMPOUND_SELECT = 5`) to every cell, so a sixth table failed the whole listing with a raw `D1_EXEC_ERROR` ("the SQL ends in an incomplete statement"). The counts now run as one `--batch` of per-table `SELECT COUNT(*)` statements. A database whose cell has never been opened, or that has no tables, shows the empty table view instead of an error.
- A failed D1 read shows a concise message ("Couldn't list the D1 tables: …") with a **Retry** button instead of the runner's argv: the bucket path, the generated SQL and celld's stderr now stay in the runner log, and the tenant sees only celld's own error line.
- A stopped or killed deploy no longer wedges the app's git mirror: the checkout of a build worktree used the bare mirror's own index, so a leftover `index.lock` failed every later deploy of that app ("Unable to create '…/index.lock': File exists"). Every checkout now owns its index file, so a concurrent read (d1's project dir, a source preview, a preview environment) or a stop mid-checkout cannot break the next deploy — and a checkout no longer moves the mirror's `HEAD`.
- `docker.io/library/rust:1-bookworm` is re-pinned to the digest the tag carries after upstream's base-OS rebuild. A moved tag no longer fails the `check` job on unrelated pull requests; it is reported by the weekly drift run instead.
- Code mode no longer says a repository has no files when it only has no `?file=`: a browse now opens `package.json`, then `README.md`, then the first file in tree order, and only a ref with no files at all shows the empty note. The chosen file is written to `?file=` in place (`replaceState`), so Back still leaves the page.

## [0.1.0-alpha.34] - 2026-11-12

### Operator action required

- Booting this image on a schema-104 database migrates to 106 in the boot transaction: 105 is `ALTER TABLE deploy ADD COLUMN error TEXT`, 106 adds the `app_purge` table (pending app-data wipes, with the build uid they still reserve). No backfill: deploys finished before the upgrade have no row-level reason (their log still holds the `ERROR:` line) and their duration reads from the same `updated_at` as new rows.
- **CI caches rebuild once.** CI cache volumes are now named `noite-ci-cache-<install tag>-<app id>` (an 8-hex-digit tag, then a UUID) instead of `noite-ci-cache-<slug>`, so each app's first CI build after the upgrade starts from an empty cache. The old slug-named volumes are not this install's namespace any more and are left in place; list them with `docker volume ls -q --filter name=noite-ci-cache- | grep -Ev '^noite-ci-cache-[0-9a-f]{8}-[0-9a-f-]{36}$'` and remove them with `docker volume rm`.
- **Re-pull the image to pick these up.** Every pin below is baked into `ghcr.io/ryuzcorp/noite`; a Compose install upgrades with `docker compose pull` (or the installer), and the bundled `rustfs` sidecar moves with `docker/compose.yaml`.
- **RustFS 1.0.3 → 1.0.5 reads existing data in place.** The upgrade was exercised on a private stack: a bucket written by 1.0.3 (a `git/` bundle and a telemetry Parquet object) lists, reads, writes and deletes unchanged under 1.0.5 on the same volume. RustFS's 1.0.5 notes require every node to finish the upgrade before pool changes; a single-node install has nothing to sequence, but do not add or remove disks mid-upgrade. RustFS 1.0.4/1.0.5 nodes only answer a `DELETE` with `503` while older nodes are still up, so if you run more than one node, finish the upgrade before deleting apps.
- **DuckDB 1.5.6 → 2.0.0 changes the CLI asset name, not the queries.** The image now installs `duckdb-cli-linux-<arch>.tar.gz` (1.x shipped `duckdb_cli-linux-<arch>.zip`); the telemetry SQL was re-run against 2.0.0 (settings, `read_parquet`, `strftime` on `TIMESTAMPTZ`, `COPY … zstd`, `SET VARIABLE`), so no operator step. DuckDB 2.0 writes a newer database format, but Noite never opens a database file — every pass is in-memory.

### Added

- A finished deploy in the Deployments tab says how long it took (`took 1m 42s`), computed from the row's start and its last write (`created_at` → `updated_at`).
- A failed, stopped or timed-out deploy shows its own one-line reason in its row (`build failed: …`, `cancelled by the operator`, `deploy stalled …`). Runner schema version 105 adds `deploy.error`.

### Changed

- `DELETE /v1/apps/{id}` answers as soon as the row is gone (3 s bound): `204` when the cleanup also finished, `202` while the credential revoke or the background wipe still runs. The app disappears from `apps.list`/`apps.get` immediately, as before.
- **A deploy's failure is no longer repeated in a second alert above the app.** The reason lives on the deploy's own row; the app and environment `lastError` alerts now carry only operational failures the deploy history cannot show (a fleet that never spawned, a failed import), and those stay visible. Existing per-deploy alerts are not duplicated, and nothing the deploy history shows becomes invisible.
- Deployment status badges use one casing: Queued, Building, Deploying, Succeeded, Failed, Stopped, Timed out.
- **Every npm dependency, Rust crate, Go module and baked-image pin moves to its latest release.** UI: `void` 1.3.0 → 1.8.0, `@ilha/void` 0.1.5 → 0.1.6, `effect` 4.1.0 → 4.1.4, `better-auth`/`@better-auth/*` 1.7.14 → 1.7.22, `@pierre/diffs` 1.5.2 → 1.6.4, `@pierre/trees` 1.0.0-beta.6 → 1.0.0, `vite` 8.3.5 → 8.3.8, `tailwindcss`/`@tailwindcss/vite` 4.3.3 → 4.3.5, `@playwright/test` 1.64.1 → 1.65.0, `@cloudflare/workers-types` and `@types/bun` to their current releases; lint tooling `oxlint` 1.90 → 1.93, `oxfmt` 0.75 → 0.78, `ultracite` 8.0.1 → 8.2.0. Void sandbox: `void` 1.5.0 → 1.8.0 (with `VOID_VERSION` and its lockfile). CLI: `@effect/platform-node`/`effect` 4.1.0 → 4.1.4, `@types/node` 26.6.5 → 26.6.6. Website: `blume` 2.2.6 → 2.2.7.
- **Runner crates move to their latest releases** (`cargo update` plus `rusty-s3` 0.10.2 → 0.11.0, which made every `ListObjectsV2` `Contents` field optional). A listing now fails with `s3 LIST object <key> has no <field>` when a store omits a required `LastModified`, `Size` or `ETag`, instead of fabricating a version (`git_store` keys objects by ETag) or a zero size.
- **The edge module builds against Caddy 2.11.9** (from 2.11.7), matching the image's `CADDY_VERSION`, with its Go module graph refreshed.
- **Image pins:** Node 24.22.0 → 24.22.3, jup 0.6.5 → 0.6.6, npm 12.2.1 → 12.2.2, pnpm 12.15.0 → 12.18.0, Docker CLI 29.9.2 → 29.9.3, RustFS 1.0.3 → 1.0.5, DuckDB 1.5.6 → 2.0.0 (esbuild stays 0.28.2; celld 0.6.3-ryuzcorp.8 is the newest fork tag; the bun base images stay on the floating `1.4` line). The runner's `BUNDLED_NPM_VERSION`/`BUNDLED_PNPM_VERSION` name the same npm/pnpm releases the image seeds.
- **The control bundle's deploy-root `wrangler.json` is written by a build step, not a Vite hook.** void 1.8 closes its environments in an order that ran the old `closeBundle` plugin before `dist/ssr/wrangler.json` existed, so it returned early and the image shipped without `dist/wrangler.json`; the runner then refused the baked bundle (`no wrangler config under /opt/noite/control/dist`) and `/ready` never passed. `bun run build` now runs `scripts/emit-celld-config.ts` after `vite build` returns, and a missing SSR manifest fails the build instead of shipping an undeployable control plane.
- **`oxlint` 1.93's new `promise/prefer-catch` rule** covers the two-argument `then(onFulfilled, onRejected)` form the Void sandbox's completion listeners and serialization tails use deliberately; their existing `oxlint-disable-next-line` markers now name both rules, and the control server's best-effort rollback/cleanup reads as a `try`/`catch`.
- Every external base image is pinned by tag _and_ multi-arch index digest — the Caddy builder, Node, rust, both bun stages (`BUN_DEBIAN_DIGEST`, `BUN_SLIM_DIGEST`) — and so is the bundled RustFS image in `docker/compose.yaml` and in CI's runner service. The readable tags stay next to the digests.
- `docker/check-versions.ts` fails when an external `FROM` has no digest, when a downloaded artifact has no per-arch checksum for amd64 _and_ arm64, when a checksum is defined but nothing verifies with it, when a download is piped straight into `tar`/`sh`, or when compose, CI and `platforms.mdx` disagree on the RustFS image. Its new `--online` leg (run in CI) compares every image digest and tarball checksum with the publisher's own file, so a version bump that leaves a stale digest fails the check. `AGENTS.md` documents how to update a pin.

### Fixed

- Creating an app no longer fails (or deletes the app it just created, cancelling a template import) when the sidebar's grant-less-creator heal writes the creator's admin grant at the same moment. The grant write's insert is now conflict-safe on the unique `(appId, userId)` row — the loser reads the winner's row instead of throwing — and a create whose grant fails but leaves the caller an admin keeps the app. A demotion through that path still applies the same last-admin guard the update path does.
- A database failure no longer echoes the SQL text, the bound parameters or the schema objects it names into a user-facing 422, an MCP tool error or a runner-failure message: a wrapped query error reads "Database query failed" (the create path answers "Could not record your access to the app", the invite and role paths say the collaborator was removed meanwhile), and the create/MCP boundaries unwrap it through the same helper. The server log keeps the cause chain, but a query wrapper's own stack — the statement plus every bound parameter, which an auth-table write would put credentials in — is replaced with "<name>: query failed". The same helper now backs every log sink on these paths: better-auth's own logger (its internal catches — the session lookup, key verification, passkeys — logged the raw statement and a session token) and a non-API failure, which is rethrown past the router's raw log to `handleAuth`, which answers a generic 500; the recovery-code mint; the git-auth, ingest, MCP and source key lookups and role verdicts; the apps SSE poll; `requireAdmin`; the ban/unban key sweeps; and the telemetry fact count.
- Deleting an app no longer leaves its host on the "paused" page, and no longer blocks creating an app — the same slug or any other — for minutes. The delete now stops the fleet, drops the row and pushes the edge route table before the destructive wipe starts, then wipes local dirs and the `git/`, `fleets/` and `envs/` prefixes as a background chore, so the slug is free the moment the call answers and the host answers "no app for this slug".
- A re-created slug only waits for at most one in-flight wipe batch: `apps.create` asks the registered background wipe to stop, the wipe ends at its next batch boundary and the create re-wipes under the slug's guard. A wipe that was queued for a re-created slug re-checks the row after taking the guard and leaves the new app's objects alone.
- Creating an app no longer takes a process-wide lock: the create is exclusive per slug (its push guard) and the per-account quota count-then-insert uses its own short lock taken after it. One create parked behind another app's slow delete/purge used to stall every create on the instance.
- Preview-environment and slug renames no longer hold the process-wide create lock; the target slug's push guard serializes them, with the slug-taken check repeated under the guards so a loser bails before moving anything.
- A rename onto a slug a delete just freed wipes that slug's leftover prefixes under its guard before moving its own objects in. The row is dropped before the background wipe, so a freed slug is no longer guaranteed empty; without the wipe the renamed app would inherit the deleted tenant's git history and celld durability.
- A deleted app's data wipe is now durable. The hard delete writes a purge tombstone (`app_purge`, schema 106) in the same transaction as the row, so a crash, a restart or an upgrade mid-wipe, a store failure, or a wipe a re-created slug stopped before its create aborted is retried: at boot and on the reconcile loop's slow tick the runner resumes every pending wipe, paced and stoppable, and clears the tombstone once the slug's prefixes are empty. Before this, the wipe lived only in memory and such data stayed in the bucket forever.
- A deleted app's per-app build uid now stays reserved until the wipe that still owns its data finishes (schema 106: the `app_purge` tombstone carries it, and the uid allocator skips tombstoned uids; schema 106 instead of a separate step, since both ship in this release). The row delete frees the uid at once, but its `builds/<slug>` and `cache/<slug>` trees survive, owned by that uid, until the background wipe removes them; handing the uid to a new app in that window ran its first build as the departed tenant — the isolation lane caught a hostile build reading a sibling's package caches. A uid whose app still has an unfinished rename stays reserved even longer: the target that rename may already hold data under owns those trees, so the purge tombstone is kept — and the uid unallocatable — until the rename resume pass wipes the target and drops the marker. The allocator's scan and claim also run in one `BEGIN IMMEDIATE` transaction, so a uid moving into a tombstone can never be claimed by a second app in the same window.
- CI cache volumes are keyed by this install's tag and the app id instead of the slug, and a reconcile sweep at boot and on the slow tick removes the volumes of that namespace that no live app owns (a deleted app whose wipe died, a rename). A re-created slug therefore starts from an empty cache — builds restart once — and can no longer mount the departed tenant's package caches; the delete's own removal is only a fast path and never gates the tombstone. The per-install tag keeps two installs that share one container daemon from deleting each other's volumes (a pre-tag volume is no longer treated as owned and is left for the operator to remove).
- An app delete now drops the fleet's in-memory telemetry marks (watermark, "already compacted" hours) for the app and every environment it owned, exactly as an environment teardown already did for its own: a slug or label reused in the same process starts from the floor instead of inheriting the dead fleet's marks.
- The app's and its environments' scoped bucket keys are marked `revoking` in that same row-delete transaction, before the slug is free, and the delete now also revokes them at the store (bounded) before it releases the slug, so a holder of the old key cannot read the next tenant's objects. A revoke that does not land in that bound is retried in the background. Minting a key for a slug/prefix now also revokes any `live` or `revoking` key that still reaches that prefix whose app row is gone or has moved to another prefix, and boot reconciles `scoped_credential` and `fleet_operator_token` rows left behind by an app that no longer exists — so a re-created slug can never inherit a key, and tenant B cannot read `fleets/<slug>/` with tenant A's still-valid key.
- A rename that failed after moving part of the app's local dirs and S3 objects now resumes on retry instead of wiping the target prefix, which already holds data the earlier attempt moved. The attempt is recorded durably before the first object moves (the record's file and both of its directories are fsynced, and a failure aborts the rename before anything moves); a retry of the same app/slug pair skips the leftover wipe and the idempotent move finishes. While the record exists its target slug is reserved: a create, another rename onto it, or a rename of the same app to a _different_ slug is refused with a retryable conflict instead of orphaning or wiping the only copy of the moved data. The reconcile loop resumes unfinished renames from the record — at boot as well as on the slow tick — and an app delete keeps the record: a record whose app is gone means the objects it moved to the target belong to nobody, so the resume pass wipes that target under the target's guard (only while no app row owns the slug) and drops the record afterwards. A failed delete therefore preserves the record, and its target stays reserved until the wipe succeeds. The record is otherwise dropped when the rename commits, when the app already sits at another slug, or when a resumed purge owns the slug — so a stale record can never block a slug or make a retry adopt another tenant's leftovers.
- Scoped credentials are bound to the app's _current_ slug: `ensure` refuses a scope whose prefix is not the one the app row (and, for an environment scope, the environment row) names now, so a fleet spawn still holding a pre-rename app snapshot can neither be handed nor mint a key for a slug another app has taken. A rename commits the row before the old key is marked, and this closes the window on the read side too. The same fence now covers the write side: `db::rename_app` holds the mint lock across its row write, and an environment teardown marks the key and drops the row as one fenced step, so a mint that already passed its check can neither insert a key for a prefix the app no longer owns nor outlive its environment row.
- A push re-checks, under the slug's guard, that the row it was authorized against is still the app behind that slug: a push that raced a delete and re-create can no longer hydrate and write the successor's repository.
- Background wipes share one process-wide pace: 250-key `DeleteObjects`, one batch in flight at a time with a 50 ms gap between batch starts, instead of each wipe pacing itself (N concurrent deletes used to multiply the store load) and instead of firing 1000-key deletes back to back. Request-path wipes (deleted-ref cleanup, environment teardown) never queue behind it. On a small host that pacing is what keeps a concurrent deploy's own S3 client inside its timeouts — a bundled RustFS on a 2 GB host was timing out a tenant deploy during a purge.
- A credential mint is fenced against the app delete: the delete removes the row while holding the same mint lock, and `ensure` refuses to mint for a row that is gone, so an in-flight fleet spawn can no longer leave a live key (invisible to the `revoking`-only sweep) for a deleted app. Operator-token and scoped-key boot reconciliation now also treats a missing _environment_ row as an orphan, and the loop retries an incomplete orphan-row pass every ten minutes instead of giving up after five attempts.
- Create and delete failures name the step that failed and a failure class (timed out, denied, unavailable, not empty, …) plus a short `ref` that matches the runner log line, instead of a bare 500, a generic message, or the raw chain with the bucket, prefixes, work-dir paths and store stderr.
- The delete's row transaction takes the database write lock up front (`BEGIN IMMEDIATE`). It reads the slug before it deletes the row, and a deferred transaction that another commit overtakes in that gap is refused immediately (`database is locked`) without the busy timeout retrying it — a delete always runs beside the previous delete's background wipe, so a delete could fail with an internal error and leave the app in place. Now the concurrent writer waits.
- The Deployments tab's empty environments line no longer points at Code mode previews, which were removed; it now suggests a branch environment or a pull request.
- **A failed create, slug check or upload now says what failed and why.** Effect's shorthand wrappers (`Effect.tryPromise(() => …)`) used to reach the UI as the library default "An error occurred in Effect.tryPromise", hiding the server's message; every client command now shows the operation ("Creating the app failed", "Checking the slug failed", …) followed by the control/runner error text and, for 5xx answers, the HTTP status. A network failure reads "network error: …" and a request that never reaches the server reads "the server didn't answer within 20 s" (the upload route waits 120 s), instead of hanging or surfacing a bare fetch error. A failed slug check reports under the Slug field; it stays advisory, and create still validates the slug. The web-commit route keeps the runner's `{error}` text instead of prefixing it with a bare status line.
- The image build verifies every remote download before it unpacks it: the Node tarball against the sha256 in the release's signed `SHASUMS256.txt` (both architectures), esbuild against the `@esbuild/linux-*` package's registry sha512, the DuckDB CLI against the sha256 GitHub publishes for the release asset, and the dev target's rustup bootstrap against rustup's own `rustup-init.sha256` instead of piping a shell script. A re-pushed or tampered asset now fails the build rather than shipping.
- The orphaned CI-cache-volume sweep on the reconcile loop is now its own slow-tick pass with its own timer and in-flight flag. It used to share the purge-resume task, so a wipe resume that held a slug guard for seconds kept the sweep from running for a whole interval, and a long sweep delayed the next resume. The sweep still runs detached, never under a slug guard, and a failure only logs and retries on a later pass.
- A rename that keeps failing no longer blocks its target slug forever. The durable rename marker now records the failed automatic-resume count, the last failure class and the time; after twelve failed passes (about an hour at the loop's five-minute tick) the runner stops auto-resuming it and records a `rename stuck` app event naming both slugs. A manual retry of that target resets the count and retries, and a rename of the app back to the marker's source (_to cancel_) moves whatever the attempt had already moved back — local dirs and the `git/`, `fleets/` and `envs/` prefixes, under the AppLock and both push guards — drops the marker and frees the target, while the app keeps its slug. The cancel records itself in the marker before moving, so a crash mid-cancel is finished as a cancel by the resume pass (never as the forward rename), and the marker unlink is part of the result (no success reported while the reservation survives). The reverse move is destination-wins: an object the app wrote under its own slug while the attempt was pending is newer than the target's copy, so the target copy is deleted and the newer object kept.
- Creating or renaming onto a slug an unfinished rename reserves now answers a distinct `409` that names the way out: "the slug is reserved by an unfinished rename of another app", or for the owner's own app the source to rename back to. It no longer says "still being renamed; retry shortly".
- The failure class recorded in a rename marker and its stuck event is a fixed set (`storage move failed`, `local move failed`, …): a store listing error names the prefix it walked, and that text is never persisted or shown to the tenant. Markers naming a slug outside the grammar are skipped (and kept, with their reservation) before any pass turns them into a path or bucket prefix; a marker whose slug merely collides with a configured control host still passes, since that reservation depends on live config.
- A slug-only rename writes only the slug-derived columns of the app row. A name-only rename runs without the deploy claim, and the move's full-row write could carry the name read before the move back over the newer one.
- A purge (delete, create's leftover wipe and a rename's target wipe) removes the `.<slug>.recreated-<ts>` salvage dirs `move_dir` leaves when a rename is retried while the reconcile loop has already recreated the old state dir. It covers `projects/`, `fleets/`, `builds/`, `cache/`, `envs/`, and the `.git`-infixed dirs under `repos/` and `git-http/`; the match is the exact prefix, so a neighbouring slug (`ab` vs `abc`) is never touched. A rename (or cancel) that commits off a slug also renames that app's salvage trees to the slug it now holds, so a later create of the old slug cannot sweep the app's parked data as the new tenant's own.

### Operator action required

- On upgrade the runner tears down every environment row left from workspace previews before it serves: the fleet is stopped, the local state and `envs/<slug>/<label>` prefix are deleted, every `refs/previews/*` ref is deleted from every app's mirror and durable manifest (a one-shot sweep, because the old teardown removed the row but left the hidden ref), the route is rebuilt without its host, and the row is removed. A compose install that wants the previous day-long window must now set `RUNNER_SLEEP_AFTER_H=24` (or `RUNNER_SLEEP_AFTER_MIN`) explicitly — otherwise its small-host apps start parking after 15 idle minutes.

### Added

- **The agent loop closes: an API key can now go from code to production without the UI.** Fourteen new MCP tools — `commit_files` (writes, deletes, moves, a new branch from a base, and an `expectedTip` compare-and-set), `create_branch`/`delete_branch`, `list_prs`/`get_pr`/`create_pr`/`comment_pr`/`review_pr`/`merge_pr`/`close_pr`, `rollback`/`redeploy`/`cancel_deploy` and `wait_for_deploy` — each gated through the one app-resolution helper with the role the UI uses, and each answering a typed refusal (`protected_branch`, `stale_tip`, `not_mergeable`, `not_open`, `forbidden`, …) as `structuredContent.refusal` so an agent can branch on the code instead of parsing English. `get_pr` reports the checks that gate merging (mergeability, approvals, the preview deploy of the head commit) and the preview environment tracking the branch; `wait_for_deploy` is one bounded long poll (≤ 60 s, `resume` hint) because the transport is stateless HTTP.
- **The web-commit route accepts `Authorization: Bearer noite_…`.** A key authenticates through the same function `/mcp` uses and is gated on the app by the one key-enforcement helper, so a key limited to other apps, capped below `push`, expired or owner-banned cannot commit; the commit actor reads `<user> via key <name>`. Cookie auth and the route's body limits are unchanged.
- **`noite pr list|view|create|merge`, `noite rollback`, `noite logs`, `noite deploy status|wait`.** They reuse the MCP tools, so the CLI and an agent share one implementation of every rule.

Keys created before this are unchanged: account-wide, uncapped, never expiring.

An app-restricted key cannot `create_app` or claim a new slug with a git push, and `list_apps` returns only its apps. Expired keys are refused everywhere with `API key expired`.
- The Account page's key list shows each key's apps, ceiling, expiry and last use.

Schema version 103 adds the nullable `deploy.actor` column (existing rows and automatic push deploys read `NULL`, i.e. nobody to name).

### Changed

- **`commit_files`' compare-and-set is enforced by the runner, not by a read-then-write guess.** The web-commit body takes an optional `expectedTip`; a branch that moved since the caller read it is refused with `tip moved` (409) before any object is written, and the publish carries the same value so the window before the ref write cannot let a racing push through either.
- **`/mcp` has its own request bound (65 s) instead of the 15 s action bound.** A tool call that waits on purpose (`wait_for_deploy`) would otherwise be cut into a 504 the caller cannot read. Every other route keeps 15 s.
- **`/mcp` is inside the platform rate limiter.** Tool calls count against the same per-client, per-route-class budget as the other API classes (`NOITE_RATE_LIMIT_RPM`), so a key-driven agent that bursts is bounded like any public client.

An edit is now a blob read, a buffer in the page and an HTTP `POST`, so a failure is a status code instead of a dead frame, and unsaved work is the page's alone.
- **Payload:** a Code mode page view drops from **2.0 MB to 0.65 MB of JavaScript transferred** (8.4 MB → 2.16 MB decoded, 56 → 29 chunks); the route's own chunks are 0.12 MB of the total.

  - the **in-browser Terminal** and with it `npm install`, a dev server and any command run locally;

- **The runner and the edge no longer carry the in-browser pod or workspace previews.** `source.preview`, its hidden `refs/previews/<user>/<branch>` refs and `EnvironmentKind::Workspace` are gone, so an environment is always one branch; `source.bundle` and `source/archive` (the language-service bundle and the workspace tarball) are gone with the editor that read them. The pod host (`pod-<app id>.<base>`) is gone from the route table and the TLS ask, and its `preview` route-table kind is refused by the edge (the previous table keeps serving).
- `RUNNER_ENVIRONMENT_TTL_H` is removed with the sweep it configured; branch environments still live until their branch or their row goes.
- **An idle runner no longer re-sends the whole edge route table every 5 s.** The reconcile tick builds the table as before, but POSTs it only when the table changed since the file was written; otherwise it asks the edge which generation it serves (`GET /edge/routes`, a few bytes over loopback) and skips the push when the answer is the current one. A Caddy that restarted and lost its in-memory table reports a different generation, so the next tick pushes again; a refused or unanswered push is still retried on the next tick. Because that probe reports the generation and not the routes (the edge applies an equal generation with different routes as a correction), one full push still goes out every five minutes, so an equal-generation correction lands within that window. No configuration change.
- A key whose stored scope cannot be read is refused instead of being treated as account-wide.

The sleep sweep cadence now follows the threshold (a quarter of it, clamped 5–60 minutes) instead of staying hourly, so an app actually parks near its window. Hosts with more memory keep their 6 h / 24 h tiers.
- `RUNNER_SLEEP_AFTER_MIN` (minutes) is the new fine-grained threshold knob and wins over `RUNNER_SLEEP_AFTER_H` (hours) when both are set; either set to `0` still disables sleeping install-wide, and both clamp to 30 days (`2592000` s) with a boot warning instead of failing or parking everything; an existing `RUNNER_SLEEP_AFTER_H` above `720` (e.g. `8760`, meaning "never") keeps working and boots with the clamp. ### Fixed

- The editor no longer loses keystrokes, scroll position or the open file's text when the page repaints, when a branch switch lands, when a second tab is open, or when a pod worker dies: there is one copy of the text (the page's buffer) and one writer.
- **A failed upgrade teardown no longer breaks environment listings.** A retired `kind='workspace'` row surviving a non-fatal boot teardown is now skipped by every environment read — an app's preview list, the install-wide listing and the route table — instead of failing the whole query on a decode error; the next boot still removes it.
- **Merging a pull request with `deleteBranch` no longer waits for the deleted branch's preview environment to be wiped.** The ref move now returns as soon as the manifest flip and mirror update land, and the environment teardown (fleet stop, settle, S3 prefix sweep, credential revoke, row delete) runs in its own task. It used to run inside the merge/push request, where a fleet's graceful SIGTERM drain could hold the runner call past the control plane's 5 s bound; the abort then dropped the half-done wipe after the fleet entry had already left the process map, so nothing finished the stop or removed the row. The same ref-driven path also stopped holding the app's git push lock across the drain.
- **The queued wipe is keyed by the environment's immutable id, not by its reusable `(slug, label)`.** It re-reads the row and its app under the app's git push guard before wiping, so it follows a rename to the row's current slug and is a clean no-op when a purge or an earlier teardown already removed the row (the admin delete and the ref deletion now share it). A re-created branch environment is resolved by the newest row, never the one being torn down.
- **A boot sweep removes branch environments whose ref is no longer in the durable manifest.** A runner crash or shutdown between the ref move and the queued wipe used to leave the row behind, and the reconcile loop respawned a fleet for a deleted branch; the sweep runs before the loop and logs-and-continues on failure.
- **Create no longer re-grants admin to a removed or demoted creator.** A retried create (a push, MCP `create_app` or the UI) used to adopt any existing row whose `user_id` matched the caller — the creator field, not an access grant — and then grant **admin** unconditionally, so a removed or push-only creator regained admin by re-using the slug. Adoption now requires either that the account is _currently_ an admin on the app (no grant is written) or that the app has no collaborators at all and the row landed inside the 15-minute recovery window (the timed-out create whose grant never ran). Every other case answers "slug taken". The key-driven create paths also resolve the adopted app through the same key gate before returning a role, so a capped key never answers `admin`.
- A key's scope and expiry can no longer be changed through the client-reachable `/api-key/update`: they are mint-time fields, and the route now refuses them.

### Security

- **A caller-chosen ref can no longer reach the runner's own namespaces.** `repo_tree`/`repo_blob`/`repo_log`/`repo_commit`/`repo_compare`, the browser commit's `fromSha`/`expectedTip`, environment create, branch create and a pull request's head/base all resolved any ref the caller named — including the hidden `refs/previews/<user>/<branch>` snapshot a collaborator's workspace preview writes, which made it readable and publishable as an advertised branch. One boundary predicate now refuses `refs/previews/`, `refs/notes/`, `refs/stash/` and `refs/seed/` for caller input (as an invalid ref, so the answer never confirms the hidden ref exists), resolves names only through `refs/heads/` and `refs/tags/` (never git's `$GIT_DIR/<name>` pseudo-refs, where a rehydrate's `FETCH_HEAD` can point at a preview tip), and accepts a sha only when a branch or tag reaches it — so a preview commit sha disclosed by a deploy or environment row does not make the snapshot readable. Branches, tags and ordinary shas resolve as before; the preview deploy keeps an explicit internal resolve for the row it owns. `commit_files` also refuses a raw ref in `base`/`expectedTip` up front with the `invalid` refusal.

- **A stopped deploy is `cancelled`; a swept one is `stalled`.** Both used to be recorded as `failed`, with the cause only in the log text. The stop endpoint and a run that finds its own token tripped close the row as `cancelled`, the stuck-deploy sweep closes a row nothing reported on as `stalled`, and both are terminal through the same guarded writers: a late log line, a second stop or a second sweep is refused. The app and environment chip still reads failed with the stop or timeout as its summary, while the Deployments tab shows **Stopped** and **Timed out** badges.
- **Automatic deploys stop retrying a failing sha.** After two consecutive failed deploys of the same target (app or environment) at the same sha, automatic deploys of that sha pause instead of looping; a new push or an explicit Deploy/Redeploy/Rollback resumes them. The app row and each environment carry an `autoDeploy` state (`eligible`, `failing`, `exhausted` or `stopped`, with the sha and failure count) derived from the deploy rows so it survives a restart, the Deployments tab says "Automatic deploys paused after 2 failed attempts of `<sha>`; push a fix or deploy manually", and each target records its own "auto deploy paused" event.
- **Settings is one page under Pull requests** (`/apps/<id>/settings`), not a side panel on the app page and no longer an item in its tab row. Every section the role may see is stacked on that page — Identity, Domains, Limits, Error reporting, Collaborators and Environment, then Branch protection and Danger zone for app admins — each with its own heading and save flow; a compact contents list at the top jumps to a section, and `?section=` scrolls to that section's heading (`/apps/<id>/settings?section=domains`). Old `?panel=settings` links redirect to the page and carry a known `?section=` along; unknown ones open it at the top.
- **Removing a custom domain or a collaborator asks first.** The Remove action opens the app's confirm dialog, names the hostname or the collaborator's email, and states the consequence (the domain stops serving the app; the collaborator loses access). Esc and Cancel leave the claim or grant in place.
- **Settings forms track their draft against the last saved value**, so an unchanged Save is disabled and a failed save keeps the input.
- **Every lifecycle is now one explicit state machine.** Deploys, fleets, environments, env-var provenance, imports and deletes, PRs and reviews, error issues and domains, telemetry and access logs, readiness, bucket snapshots, deploy mirrors, the edge route table, the CLI, the void-proxy, the sandbox controller and every control-UI island (now on ilha 0.16.3 with `@ilha/model`) each have one state type, one guarded transition function and a documented state table, instead of parallel flags, map presence, `pid = 0` or a `HEAD` file. Stale async answers are refused by generation instead of being applied late. The app lifecycle tables read the runner's generated `AppStatus`, `DeployStatus` and `DesiredState` unions, so a status the runner adds fails the UI's compile until its label and action are decided, and a failed push carries the pod's typed refusal code so the read-only explanation is chosen by code rather than by matching the error's English (the runner's text-only refusals and an unreachable server are still read that way). Wire values and stored shapes are unchanged — REST JSON, DB strings, the route table, SSE frames and CLI output all stay as they were — and the only visible changes are the fixes listed.
- The deploy e2e helpers treat `cancelled` and `stalled` as terminal, so a stopped or swept deploy no longer leaves a poll running to its deadline.

### Fixed

- **Two sign-ups at the same moment can no longer both become admin.** The bootstrap role is claimed with one conditional write, and the loser is refused instead of admitted without an invite code. Invitations hold up too: a code whose redeemer's account was deleted no longer shows as available, Revoke on a used code says so, re-inviting a collaborator cannot demote the app's last admin, and accepting an older invitation no longer overwrites a newer role grant.
- **Account screens fail visibly instead of hanging or bouncing.** A failed session read shows an error with Retry rather than an endless skeleton, and sign-in verifies the session cookie like registration does instead of looping between `/apps` and `/login`. The login panel no longer swaps Sign in for Create account under the pointer while the signup policy loads, the first-run tour stays open with its error and a skip when saving "onboarded" fails, and the release-check and telemetry cards keep "Checking…" until they report and show the stored preference while an operator lock is in force.
- **Admin and account actions refuse impossible requests.** The admin Apps tab no longer offers Start for an app whose desired state is unknown, and one row's action no longer disables every other row; deleting the last passkey is refused until another device is added, and an API key can no longer be created with no scope selected.
- **The admin Apps panel and the app header agree on Start/Stop.** An app that is importing, or whose import failed, no longer offers a toggle in the admin panel that the header does not.
- **Creating an app from a dropped folder no longer creates a second app when the upload fails.** The form remembers the app it created, links to it, and its button becomes "Retry upload", which commits the folder into that app instead of stranding a second one.
- **The invitations banner answers one invitation at a time and reports a failure on its own row**, instead of one click disabling every invitation and one error reading as if it were about the whole list.
- **Environment groups tell the truth.** A stopped environment reads as stopped in its group header with its last error still visible, and a preview deploy group no longer marks a release live while the environment is stopped.
- **Creating an environment never deploys a branch you did not pick.** A branch that disappears resets the selection, and submitting it is refused with a reason; a `?env=` link to a deleted environment says so instead of silently showing Production.
- **The app header's status dot and its Start/Stop label can no longer contradict each other.**
- **A successful `noite deploy` no longer reports CI failure afterwards.** `$GITHUB_OUTPUT` is written as soon as the push lands, and a write error (disk full, unwritable path) now warns instead of failing the step: the deploy is already live and cannot be undone.
- **A failing `gh` call on the deploy PR comment is reported** with its exit code and stderr, instead of the create/update calls being silently treated as success.
- **A retained deploy temp dir no longer contains the API key.** Git authenticates through its environment header instead of a key in the remote URL, so the workdir's `.git/config` never holds the token, and a kept workdir has URL userinfo scrubbed before it is retained.
- **Switching refs can no longer hang on "Switching to …".** A request for the ref the panes still show is a new switch instead of a no-op, and a pod that takes the open but never answers ends on "Could not open" with Retry after a bounded wait.
- **Typing is never overwritten by the pod's change feed.** A keystroke spends the token of any read still in flight, so an older read can no longer repaint the document and drop the keys that followed.
- **A checkout whose pod stopped after its listing loaded is refused** instead of leaving a dead tree and editor behind the "Could not open" card, and the card names the ref that actually failed. A failed Deploy preview and a failed push also stay with the button that caused them, and the read-only banner no longer describes a different branch from the failure card.
- **A pod-side change arriving while a file opens no longer cancels that open**, so `?file=` and the editor agree.
- **Smaller code-mode edges no longer leave stale actions or dialogs.** A changed row whose committed text is still being read keeps its Discard button and diff; renaming a new file after its placeholder was taken back can no longer rename a path the pod never had; two drops cannot interleave their confirmations and a refused drop clears the outline; the branch picker clears its stale action error and opens one delete confirmation at a time.
- **The workspace waits for the pod frame's own acknowledgement**, and says the host answered but never took the port instead of failing each request on its own deadline.
- **A push the page reported as settled without its commit no longer leaves the pod mid-push.** The refusal keeps the push open for another answer, and a push the page never settles expires so the next one can start.
- **A tab that loses the saved workspace's lock stops claiming to save**: it returns to following, says its edits are not being kept, and reloads cleanly.
- **The tree and Changes panel are no longer one pass behind a rename or a terminal write**, and an out-of-order change event cannot roll the panel back.
- **Language intelligence restarts its worker after a crash** instead of losing diagnostics, hover and go-to-definition for the rest of the mount, and a terminal whose frame died says so instead of showing a prompt that swallows keystrokes.
- **A second tab no longer waits out its full timeout** when the other tab is not the one saving the workspace, a bracketed window of unsaved edits the browser refused to mirror is reported, and a branch opened after a large one no longer inherits its declaration budget cap.
- **A slow static asset can no longer be answered with a 15 s JSON 504.** The control UI's `run_worker_first` now excludes `/assets/*`, so static chunks are served by the asset layer instead of behind the Worker's session check, per-request database bootstrap, rate limit and 15 s action bound. The 29-byte `{"error":"Request timed out"}` bodies the e2e "flake wave" traced to shared chunks such as `pages-client`, `Data`, `branches` and `errors` are gone.
- **Deleting D1 rows can no longer remove rows you did not pick.** The selection is keyed by each record's own key, so a refresh, sort or background reload cannot remap it; clearing or editing the selection cancels an armed delete, Esc during a save no longer closes the dialog and loses the unsaved-changes guard, and edits are refused while a write is in flight.
- **The D1 row editor starts fresh.** Opening a record whose values equal the previous one resets the fields instead of carrying the previous drafts, and text hidden by the NULL toggle is not restored.
- **The D1 toolbar search no longer commits a stale query onto another table's URL**, and shows the applied query again after a table switch or a foreign-key jump.
- **R2 bulk delete can no longer remove objects the search filtered out**, and the header checkbox shows a partial selection as indeterminate instead of unchecked.
- **A slow R2 upload no longer disables the detail panel's own delete**, and a page-level error banner does not outlive the write it described.
- **The new-folder form keeps its typed name and stays open when the runner refuses the create**, and explains an invalid name instead of only disabling the button.
- **A failed reload of the D1 grid, R2 listing, Durable Object list or a pull request shows an error banner above the last loaded data** instead of presenting stale data as fresh, and D1, R2 and pull-request write errors are announced to assistive technology.
- **Stopping a deploy either prevents it or refuses cleanly.** Activation is now the point of no return in one step: a stop before it wins and nothing activates, a stop after it answers 409 with the deploy finishing normally, and the row is no longer marked failed while the new generation serves.
- **A finished deploy row can no longer be rewritten.** A late log line, a second stop, the stall sweep or a retried deploy is refused instead of moving a `failed` or `success` row back to `building` or flipping its story.
- **The git-tip sweep no longer undoes a rollback.** The fallback sweep deployed the branch tip whenever `last_deploy_sha` differed from it, so a rollback was silently replaced by the tip within a minute. It now only deploys a tip whose sha has never been deployed successfully in that target: an already-built release the live sha moved off is the operator's choice, while pushes and explicit redeploys deploy on their own trigger.
- **The Deployments tab's Start/Stop and import retry settle from the app's state stream** instead of polling silently for up to three minutes; a missed deadline shows an explicit "still waiting" notice.
- **Stopping a deploy that already finished no longer leaves a permanent red error inside the row**; it says the deploy already finished.
- **MCP `deploy_status` reports `live` correctly again.** A sleeping (scale-to-zero) app reads `live: true` because it serves on the next request, while a crash- or OOM-held fleet reads `false` even though its row still says `running`.
- **`make up`/`make dev`/`make dev-host` start on rootless Podman again.** With `DOCKER_SOCKET` unset and no host Docker socket, the Makefile mounts `/dev/null` in its place and sets `NOITE_SANDBOX=0` (unless already set), instead of Podman refusing the missing bind source. Hosts with a Docker socket, or an explicit `DOCKER_SOCKET`, are unchanged. `make dev-host` also adds `BETTER_AUTH_URL`'s host to the served control hosts, so the README's `https://noite.local` phone setup boots without a `CONTROL_EXTRA_HOSTS` prefix.
- **`make dev`/`make dev-host` build the Void sandbox controller bundle, so sandbox apps deploy on a dev stack.** `docker/dev-sandbox.sh` compiles the bundle inside the container before the runner starts and again whenever `apps/void-sandbox` changes, publishing it at `/opt/noite/void-sandbox` through an atomically swapped symlink.
- **The edge always serves the newest route table.** A Caddy reload no longer reinstates the boot-time file over a table the runner pushed since, a drained edge no longer serves the table it released (and refuses requests as if it were still booting), and a correction pushed under an already-live generation now applies instead of being dropped as identical.
- **The edge refuses route combinations its static config cannot act on** — a gate on a tenant or custom host, a wake on the control plane, a rewrite outside git and the fallback page, or rate limits on a deny route — with a 400 at push instead of silently ignoring them. Every table the runner emits today still validates.
- **A configured edge rate limit is a real ceiling.** The budget is derived from the window and rounded down (`floor(rpm × 10 s / 60 s)`), and below 6/min the window widens to an exact divisor of a minute, so 1/min is one request per 60 s instead of six a minute and 100/min is 100, not 102.
- **`Retry-After` reports the real remaining time.** It is the time until enough of the key's stamps leave the window for it to admit again, so after a lowered rate a client that honours the header is admitted instead of looping on 429s.
- **A request refused by the app ceiling no longer spends the client's budget.** The client zone and the app zone are decided in one step, and both record a stamp only when both admit the request.
- **Eviction and sweep no longer clear a live throttle.** Eviction only drops keys whose budget has recovered, a sweep keeps every key still inside its window, and a full zone with nothing evictable admits new keys uncounted until its windows pass instead of resetting a limit a client could then spray past.
- **A tenant slug can no longer share a platform rate-limit zone.** Zones now carry their owner (`platform:client:<kind>`, `app:<slug>:client`, `app:<slug>:all`), so an app slugged `control`, `preview` or `fallback` no longer draws from the platform host's per-visitor budget. The first push after the upgrade sweeps the old names.
- **A failed `/email/send` no longer becomes permanent for its idempotency key.** Only an attempt where a delivery was observed accepted is recorded; a full or partial accept replays byte-identically and sends nothing, while a failed, outcome-unknown or rejected-only attempt records nothing so the retry really retries. An `outcome_unknown` retry can still duplicate a message the relay already queued, which the per-recipient error says.
- **An SMTP AUTH timeout is a transport error, not a credential failure.** It is classified and logged as such and never triggers a credential rotation by itself.
- **`/health` no longer reports `email: true` for an SMTP config that refuses sends.** An invalid mode/port, or `plain` mode without `VOID_PROXY_SMTP_ALLOW_PLAINTEXT=1`, now shows the same verdict the send handler gives.
- **Error counts no longer include pruned hours.** Pruning old error data recomputes each surviving issue's lifetime count in the same pass, so the displayed number matches the retained series instead of drifting above it.
- **A source map that was missing on first use no longer stays negatively cached forever.** A map uploaded moments later now symbolicates, because negative entries expire like manifest entries.
- **Deleting an app or environment drops its fleet-token process cache with its token rows**, so a recreated slug or label cannot be probed with the dead fleet token until the runner restarts.
- **Fleets no longer strand an app in the wrong state.** A parked app can no longer come back as "running" with no fleet, a failed wake leaves it asleep and the next request retries the wake hop instead of serving a dead route, a cancelled health confirm can no longer leave it at `building` forever, and a late probe cannot resurrect a stopped fleet's entry. A deploy wake now wakes the fleet state too, and a deploy's health gate no longer reads a crash-held or still-spawning fleet as "gone" (which recorded success without the gate and skipped migrations).
- **Crash and OOM loops back off and keep their hold.** A fleet that keeps dying waits 5, 10, 20, 40 then 60 s (OOM kills up to 300 s); parking or waking keeps the hold while a wake still restarts the escalation count; an app that crashes during a scale-to-zero wake is no longer respawned once per request; a stop during a restart backoff ends at once; and a failed wake stops the fleet with SIGTERM (so celld releases its leases) instead of SIGKILL.
- **A stop or park that lands mid-spawn no longer leaves an unsupervised fleet or kills its successor.** A spawn that loses its claim kills only the child it started and leaves the winning fleet's resources alone, and its scaffolding is cleaned by exactly one owner. A fleet whose cgroup leaf cannot be created now fails the spawn in `multi` instead of running uncapped while `/ready` says containment is live.
- **`/ready` reports the live install, not the boot snapshot.** It re-reads both isolation probes on every answer (a fleet whose limits were refused later, or a flushed nft table, no longer reads healthy), and its snapshot age no longer grows while an unchanged bucket is current.
- **A half-hydrated deploy mirror is retried**, at boot and at checkout, instead of looking present forever and failing every read with "unknown revision".
- **A slug that spells a platform host is refused** at create, rename and import: the reserved labels are derived from the edge route table itself, so a non-default `CONTROL_SUBDOMAIN`, an extra control hostname or the `api`/`git` hosts under any tenant base can never become a tenant site. The edge also drops, and logs, any tenant or custom-domain route that collides with a platform host.
- **`BASE_DOMAIN`, `CONTROL_SUBDOMAIN` and `CONTROL_EXTRA_HOSTS` are canonicalized on load** (trimmed, lowercased, no trailing dot), matching the `Host` normalization the edge applies, so a dotted or uppercase value no longer leaves route keys the edge can never match.
- **Switching pages or tabs no longer flashes "Live updates are unavailable".** The hub announces only the replacement link, not the teardown of the one it replaced, and a feed that starts connecting again returns to loading — a skeleton when it has no value, its last value when it has one — instead of painting an error over a load already in flight.
- **A dropped live-feed topic no longer leaves its poller running.** Ending an attempt aborts that topic's own request, a 4xx refusal (revoked role, deleted app, unknown topic) reports a terminal refusal instead of retrying forever, and the usage stream's first-frame budget matches its 30 s poll cadence.
- **A frame that arrives before the EventSource `open` event counts as loaded**, while the hub's frameless "topic opened" marker does not: a cold or empty feed keeps its skeleton until its first real frame.
- **An auth change fences in-flight fetches by store epoch**, so signing in, signing out or impersonating in one tab can no longer replay the previous account's snapshot into the next account's panels.
- **Hub connections are rate-limited per client IP** like the other public routes, and a slow app create is recovered and granted inside the route's 15 s bound instead of timing out at 15 s while recovery continued to ~24 s.
- **Pull-request state changes are compare-and-swap.** A merge that raced a close can no longer leave the PR closed while carrying a merge commit, reopening a merged PR answers a conflict instead of silently doing nothing, and a review submitted as the PR closes is refused instead of stored on the closed pull.
- **The pull-request view only offers actions that can succeed.** A duplicate base/head pair can no longer be posted twice and Create waits for the branch compare; Merge is offered only when the pull is mergeable and Reopen only when its head branch still exists; a dismissed or older-head review no longer disables the review buttons for the session.
- **The header Deploy menu keeps its rollback through the app detail landing.** A page load paints the header from the previous snapshot first, so the new Stop/Start control used to replace the menu's subtree and close it, and the rollback lookup froze on the release already serving. The action row is keyed, and the target is now derived against the live sha at render, so the menu keeps its open state and its rows and never offers the serving release as "Roll back to".
- **A failed history lookup is shown with a retry**, instead of the menu claiming there is no earlier deploy.
- **Double-clicking Stop, Roll back or Redeploy sends one call**, not two.
- **Import retry and delete no longer corrupt a running app.** Retry is refused with a 409 for a deployed or busy app instead of setting its status back to `importing`; a failed import is stored as `error` rather than an unknown badge value; the "an import is running" claim is released on every exit path, so a panic can no longer block retries until the runner restarts. Deleting an app stops its import first, waits for it to end, and re-checks that the app still owns the slug before a ref move, so an app created later with that slug cannot inherit the imported tree; retry, patch and rename on an app being deleted answer 409.
- **A sandbox cell can no longer leak capacity or race its own teardown.** An interrupted stop still schedules the cleanup that frees its concurrency slot, a request that arrives while the idle alarm is destroying the cell is refused with `VOID_SANDBOX_unavailable`, and a stopped lease asked to confirm a start tears the container down instead of leaving it running with no record able to stop it.
- **Telemetry compaction no longer silently loses an hour.** A failed fold is tracked and retried independently instead of advancing the per-fleet watermark past it; a second `noite-runner telemetry reingest` is no longer dropped, because the replay row is cleared only for the request that was applied; and a line's access-log counters commit with its error-request backfill, advancing the offset only after they commit, so stats are not double counted after a mid-loop database error.
- **A live stream now reaches a terminal state.** A topic that never delivers a first frame, or stops delivering frames for a minute after its first, ends with an error instead of staying open and silently stale.

### Security

- **Banning an account revokes its API keys.** `banUser` deleted the account's sessions but left its profile keys working, so a banned user could keep pushing over git smart-HTTP, posting event ingest and calling `/mcp`. Every key consumer now refuses a key whose owner is banned through one shared predicate, a ban deletes the account's keys in the same flow, key creation is refused while an account is banned, and unbanning sweeps any key a create raced in during the ban: revoked stays revoked, so mint a new one.
- The security gate now treats the bundled Caddy edge module (`edge/**`) and the static Caddyfile writer that consumes its table (`apps/runner/src/host/caddy.rs`) as sensitive: a change to the route table, the host matcher, the rate limiter or the gate/asleep hops needs an independent review and the `security-reviewed` label.

### Operator action required

- The first push to each repository after upgrading rewrites its `git/{slug}/MANIFEST.json` as manifest v2. This build reads v1 and v2; an older build reads only v1. No manual step is needed to upgrade. Take a backup before upgrading, and preserve repositories pushed after the upgrade before restoring `git/`: the prefix holds both manifests and tip bundles, so restoring an older backup discards every push made since, across repositories. Do not roll back to an image older than this release after pushing; git pushes to already-upgraded repositories then fail until the prefix is repaired.

### Changed

- The git storage/mirror/manifest engine is now the published `ryuz_git` 0.2 crate (crates.io, same repo family) instead of runner-local modules: all manifest/mirror/publish operations go through `Wal<RefsCodec>` (manifest CAS, immutable tip bundles, mirror rebuilt from the manifest), and `host/git_manifest.rs` is deleted. Role/collaborator auth and branch protection (`git_policy.rs`), smart-HTTP routes, tip-bundle layout, deploy hooks, paths, errors and logs are unchanged.
- Manifests are v2 on the first push after this change (forward-only): `RefsCodec` reads the existing v1 manifests and writes v2 (same refs plus sequence/revision metadata). No migration step; old mirrors rehydrate from the manifest as before.
- S3 access for git goes through a new `host::git_store::ObjectStore` adapter over the native S3 client (rusty-s3 signing + one reqwest pool): conditional writes (`If-None-Match: *` create, `If-Match` CAS update), conditional/freshness/range reads, and versioned deletes. 404 maps to missing while transport errors, timeouts and 5xx stay retryable, so an unreachable store is never mistaken for "no manifest".
- Noite CI (`noite.ci.yaml`) now runs on the shared `ryuz_workflow` crate (ryuzcorp/crates) instead of a runner-local module. The accepted workflow surface grows: `strategy.matrix` with `max-parallel`/`fail-fast`, `runs-on` (kept as a routing hint), job-level `env` and `defaults.run`, `shell: bash|sh`, `container:` as an `image:` alias, and `uses: checkout|cache|upload-artifact` with `with`. Matrix values reach steps as `RYUZ_MATRIX_<KEY>` env vars; an explicit `env` of the same name wins.
- The engine brings its safety properties to deploys: per-step and per-job timeouts kill the container, exit 137 is reported as out-of-memory, containers carry a `ryuz_workflow.pid` label and are swept at start (and removed on cancellation), env values never reach argv and are masked in the log, and artifacts stage outside the worktree and install without following symlinks. Jobs still run one at a time (`max_parallel: 1`) and a workflow must still leave `dist/` for the deploy.
- Workflow, job and step `env` may not set names reserved for the host container CLI (`PATH`, `HOME`, `TMPDIR`, `LD_*`, `DOCKER_*`, `CONTAINER_*`, `PODMAN_*`, `XDG_*`, proxy/TLS variables); export those inside `run` instead.

## [0.1.0-alpha.26] - 2026-11-07

### Operator action required

- Apps with a `noite.ci.yaml` now run it instead of the built-in install/build. Standard installs need nothing: the runner already has the Docker socket and pulls the default image on first use. CI containers consume the host's memory and CPU like the built-in build, so a 2 GB box still cannot build the 1.3 GiB template; use a bigger box or a prebuilt dist.
- Scheduled apps no longer auto-sleep without an explicit override: if an install relied on idle-sleep for cron/queue workers, set Sleep after per app (Settings → Limits) or leave them awake.
- Small hosts derive a shorter threshold (`1` h at ≤ 2 GiB, `6` h at ≤ 4 GiB): set `RUNNER_SLEEP_AFTER_H` explicitly to keep the previous `24` h behavior.

### Added

- Deploys now prove the new generation before serving it: after staging, the deploy asks the staged generation for `HEAD <path>` (`RUNNER_DEPLOY_PROBE_PATH`, default `/`) through `celld invoke` — the staged pins plus the app as `--target`, like the staged migrations — before the one `celld activate` moves the pointer, on every deploy (a Void redeploy after its staged migrate, any other deploy right after its stage). An answered status below 500 activates; a 5xx or a missing answer fails the deploy with nothing activated, so the previous generation keeps serving until the new one is proven live. The one unprobed activation is a deploy with no live old generation (a first deploy, a stopped app or a parked fleet): celld answers `no node leases`, there is nothing to fail over from, and the deploy activates instead of failing. `RUNNER_DEPLOY_PROBE_TIMEOUT_S` (default 30) bounds the probe; empty path disables it (a celld without `invoke`).
- Noite CI: a repo-root `noite.ci.yaml` (a light GitHub-Actions subset: `jobs`, `steps`, `run`, `env`, `working-directory`, `timeout-minutes`, optional `image`) runs in a container per job instead of the built-in install/build. The workflow's `dist/` is the deploy root; a failure fails the deploy before release/activate, so the live version keeps serving. Containers are cap-dropped, no-new-privileges, memory/CPU/pids-capped, no host binds, no Docker socket inside, and the checkout is copied in/out with `docker cp`; `HOME` and package caches persist in a per-app named volume. Images are an exact allowlist (`RUNNER_CI_IMAGE`, `RUNNER_CI_IMAGES`), network `bridge` or `none`, kill switch `RUNNER_CI=0`. Bounded: 64 KiB config, 32 jobs/steps, 32 KiB scripts, 120 min/step.

### Changed

- Scale-to-zero policy: Settings → Limits gains a per-app Sleep after threshold in seconds (`0` = never, valid range `60`–`2592000`); empty inherits the install default. Preview environments use their owning app's override, re-checked under the transition lock.
- `RUNNER_SLEEP_AFTER_H` unset now derives from detected memory (≤ 2 GiB: `1` h, ≤ 4 GiB: `6` h, else `24` h); an explicit value (including `0` = never) still wins.
- Apps running scheduled work (a non-empty `triggers.crons` or `queues.consumers` in the last deployed Wrangler config) no longer auto-sleep unless the owner set an explicit Sleep after override. Memory-pressure parking still parks them; the next request wakes them.
- A failed wake now records a tenant-visible `wake failed` fleet event and bumps the `wake_failed` sleep counter in `GET /v1/admin/stats`.

## [0.1.0-alpha.25] - 2026-11-07

### Operator action required

- A 2 GB install builds the Void debug app (measured 810 MB peak); the ~1.3 GiB Void/Ilha template still needs a bigger box or a prebuilt dist.

### Fixed

- A tenant build can no longer make the host unresponsive. The build cgroup leaf now gets a hard `cpu.max` quota of one core less than the box, split across concurrent build slots (a 2 vCPU VPS keeps a core for the runner, RustFS, Caddy, the fleets and SSH) and a low `io.weight`, alongside the existing memory cap. It is idempotent, skips a host with less than the file plus 3 GB free, and `NOITE_SWAP=0` turns it off; the uninstaller removes it. Re-run the installer to get it on an existing install.

## [0.1.0-alpha.23] - 2026-11-07

### Operator action required

- None.

### Changed

- The persistent per-app build cache cap is now 1024 MiB (was 512). A cold `bun install` of the shipped Void/Ilha template writes ~872 MB, so the old cap pruned the cache it had just filled at the end of every deploy and the next one downloaded it again; the cache survives deploys and is still pruned largest-first and deleted with the app. Worst-case disk is 1 GiB per app (the default install has 39 GB free on a 2 GB VPS).
- The bundled RustFS service now sets `RUSTFS_ALLOCATOR_RECLAIM_ENABLED` and `RUSTFS_ALLOCATOR_RECLAIM_FORCE` explicitly, so freed allocator pages return to the OS between idle periods instead of accumulating: prod measured 752 MB anonymous in the store's own container after four days, outside the noite container's memory accounting. The console stays disabled (it is admin UI, not storage).

### Fixed

- Deleting an app now frees its slug as soon as the app row is gone: the stop of any re-spawned fleet, then the push guard and deploy claim, run before the post-delete cleanup (edge route push, provider key revoke, operator-token cleanup). A slow or hung cleanup step used to keep the slug taken after the app had disappeared from the list, so create or rename onto that slug waited on the guard past the control plane's 5 s and failed with "operation aborted due to timeout". The remaining cleanup is bounded to 30 s and logged when it outlives that, so a hung provider call can no longer outlive the delete task.
- Create, rename and delete runner calls in the control UI now allow 14 s (the route's own bound is 15 s) instead of the 5 s default (the runner still answers delete within 3 s): clearing a deleted slug's leftovers or moving a large S3 prefix no longer shows as an abort while the runner is still working.
- The memory-pressure parking sweep now measures what the kernel OOM killer does on an unbounded install: the host's used memory (`MemTotal - MemAvailable`) instead of this container's own `memory.current`. The bundled RustFS runs in its own container and the runner's cgroup is unbounded on the default compose, so the old check read ~20% while the box sat near 75%; the last guard before the OOM killer never fired and idle apps were never parked. Bounded installs (a container `mem_limit`) keep measuring their own cgroup. `/ready` and `/v1/admin/stats` now carry `memory.scope` (`container` or `host`) alongside the existing bytes and percent.
- MinIO/RustFS admin and AWS IAM calls now time out after 10 s instead of hanging forever. A hung admin call stalled key mint/revoke and the orphan-key sweep, and (before the delete fix) could hold a deleted app's slug. A timeout during the MinIO `auto` probe is now a detection failure that fails the boot, instead of being read as "no admin API" and silently downgrading the install to root keys; a stalled IAM response body is now an error instead of an empty string that parsed as a successful empty listing and hid orphaned keys.
- Renaming an app now runs as its own task, like delete: the control plane aborting the call (14 s lifecycle bound) only drops the waiter, and the move completes instead of leaving the row on the old slug with local dirs or S3 prefixes half moved. A slug that still belongs to another app answers `409` immediately; a slug freed by a delete has no leftovers (its purge completed before the row went away) and can be taken. Regression tests cover a taken target, a deleted target, and a dropped caller (the last fails without the detached task: the move is canceled and the row stays on the old slug).

## [0.1.0-alpha.20] - 2026-11-06

### Operator action required

- None.

### Added

- Memory-pressure parking: when the container is at or above `RUNNER_PRESSURE_PCT` (85%) of its detected limit, the runner parks the least-recently-active app or preview environment idle for `RUNNER_PRESSURE_IDLE_S` (300 s), stopping 10 points below the trigger. It wakes transparently on its next request and records a `fleet parked` event; anything with an in-flight deploy is never chosen. `0` disables it. `/ready` and `/v1/admin/stats` now report container `current_bytes`/`limit_bytes`/`used_percent`, and stats lists each fleet's cgroup charge under `fleet_memory`.

### Changed

- A small host now sizes the resident set from its own memory: per-fleet celld caches are capped (`RUNNER_FLEET_LOCAL_CACHE_MB`, a sixteenth of the box clamped 64–512 MiB; celld's own default was 2 GiB per node), the control fleet gets its own capped cgroup leaf (`RUNNER_CONTROL_MEMORY_MB`, a quarter of the box) instead of running uncapped, and fleets without cgroup leaves get a derived container-wide shed threshold (75% of the box) so celld answers 503 before the kernel OOM-kills the container.
- Cold boots ramp instead of stacking: `RUNNER_FLEET_SPAWN_BATCH` starts at most one cold fleet per reconcile pass on two cores or fewer, and `RUNNER_BUILD_CONCURRENCY` serializes tenant deploys. Restarts of an already-running fleet are never delayed by either.

### Fixed

- A fleet that exits without an OOM kill no longer respawns every reconcile tick forever: it backs off 5, 10, 20, 40 s and caps at 60 s, resetting after five minutes of uptime. OOM kills keep their longer cgroup backoff, and a deliberate stop clears the chain.
- The per-fleet log ring is a `VecDeque`: appending no longer shifted the whole 500-line buffer per line. `/ready` reuses one HTTP client instead of building a new pool every 10 s probe.
- Telemetry ingest and compaction no longer run DuckDB at its own defaults (80% of RAM, every core): every invocation now carries a memory cap, a thread count and a capped spill directory, so a 24-hour catch-up or compaction scan spills instead of growing past the box. Unset derives the cap from the memory this container may use (10%, clamped 128–1024 MiB) and its cores (capped 4); `RUNNER_DUCKDB_MEMORY_MB`, `RUNNER_DUCKDB_THREADS` and `RUNNER_DUCKDB_TEMP_MB` override them. Measured on one 24-hour chunk (24 M spans, 581 MB Parquet): 1.55 GB peak RSS before versus 271 MB at the cap a 2 GB box derives. The limits use DuckDB's `MiB` unit, so a configured MiB value is exactly that many MiB.
- A killed DuckDB pass leaves its spill behind, and stale bytes count against the spill cap, which would wedge every later pass. Boot clears the directory outright (no query can be running); a failed pass sweeps entries older than an hour, so a live query's files are never touched.

### Security

- Telemetry DuckDB now receives its SQL on stdin instead of `-c` on the command line. That SQL carries the platform store keys, and `/proc/<pid>/cmdline` is world-readable while tenant build processes share the container's PID namespace, so a build script that sampled the runner's children could have captured them. Every interpolated store field and every object key in the compaction and glob SQL is now a quoted DuckDB literal with doubled quotes, so a credential containing a quote can no longer end a statement. Logged DuckDB errors are scrubbed of both raw and SQL-escaped store keys.

The tag and store identity hash the endpoint as configured, so the install keeps its tag across the upgrade and its existing keys stay revocable — but changing the endpoint re-tags the install, and keys under the old tag read as foreign: the sweep drops their rows without revoking them, so delete the old keys at the store by hand.
- Requires celld `v0.6.3-ryuzcorp.7` for the not_found object; against an older celld a missing key surfaces as a step error instead of 404.
- A Void-app deploy that fails naming `ISR_CACHE`, `noite-void-proxy` or `__VOID_PROXY` needs that name freed for the platform. If you set a `BETTER_AUTH_SECRET` value yourself it keeps winning; a generated one appears in Settings → Environment (production) or the environment's Variable overrides (previews) like any other setting (value hidden as usual) and can be replaced there.
- Requires celld `v0.6.3-ryuzcorp.7` (staged invocation): do not deploy this runner against an older celld, which has no `invoke` subcommand or `--header-env`; a staged migrate against it fails the deploy (nothing activates) with an error naming the celld requirement.
- Migrations are forward-only: rolling back the code never un-applies them, so a deploy that fails at `migrate` leaves applied migrations in place — fix the migration and redeploy, which skips what is already applied. Keep migrations backward-compatible with the previous release. On a first deploy (or a fleet with no live node, which migrates after adoption), stopping the app mid-deploy skips its migrations; redeploy to run them. A redeploy's staged migrate runs regardless of a stop, so stopping can never skip it.

Only the first-deploy and fallback paths still migrate after activation: there a failed `migrate` leaves the new Worker serving a half-migrated schema while the deploy reads Failed. The step is bounded: worker responses past 4 MiB fail the deploy, warning/name lists log the first 20 plus a count, and per-request timeouts cap the worst case at ~15 min staged (~18 on the legacy endpoint).

- If an allowlist relied on `@domain` matching subdomains, list each subdomain explicitly (`@example.com` no longer admits `sub.example.com`); if an AI model endpoint uses `http`, it must be a loopback sidecar with `NOITE_VOID_AI_ALLOW_PLAINTEXT=1`, else the boot fails naming the var.
- Settings values are now readable by Worker code via `env` (plaintext `vars` in the deployed config — celld has no secret store). If you kept a value in Settings specifically because Workers could not see it, move it out: there is no process-only tier anymore. A deploy that fails naming a reserved variable needs that variable renamed.

  - Container `exec` can allocate a terminal (`pty`, `isPty`, `resize(cols, rows)`).

Liveness probes use the public health endpoint, which the token does not guard.
- Void apps with D1 migrations now migrate on every deploy: before the deploy is marked success, a `migrate` step collects the pushed tree's `db/migrations/*.sql` (Void's rule: sorted, `seed.sql` excluded) and drives the Worker's in-worker migration endpoints with the fleet's `__VOID_PROXY_TOKEN` — protocol v2 where advertised (capabilities negotiated against the tree's dialect, classifier version and list hash, then app migrations with reconcile-on-unknown, then auth migrations), legacy `POST /__void/migrate` for older sqlite runtimes. A direct registry ref must be digest-pinned (`@sha256:` plus 64 lowercase hex); an unpinned tag fails the deploy before anything builds. `instanceType` is ignored in v1.

- Operator cap `NOITE_VOID_SANDBOX_MAX_CONCURRENT` (default `4`; `0` admits none; validated at boot), rendered as `__VOID_SANDBOX_MAX_CONCURRENT` plus the `max_instances` backstop. Over the cap, `getSandbox()` throws Void's `SandboxLimitError`.
- Sandbox `exec` supports PTY terminal sessions (`pty: true` or `{ cols, rows }`): the wire `isPty` reports the terminal and `resize(cols, rows)` resizes it (celld patch `0006`).
- Known deviations: aborts kill the process — the platform has no signal delivery into the container.

- `node:crypto` `scrypt` and `scryptSync` work in Workers (Better Auth password hashing, which Void auth uses, threw "not implemented").
- `Response.clone()` works on a streaming body (celld patch `0004`): the clone and the original each get the whole body, as on Cloudflare. It used to throw `Cannot clone a streaming response before consumption`, so a Worker that caches a copy of a streamed response (Void's ISR on server-rendered pages) answered 500. `Request.clone()` and `Response.clone()` now also refuse a body that was partly read through its reader, as on Cloudflare, instead of cloning the remainder.

Previously each `void_migrate` run leaked its fixtures (`cap-total` alone drops 70 MB per run; gigabytes had piled up and broken unrelated tests through the `/tmp` quota), and the `api`, `prs`, `forge`, `limits`, `domains`, `errors`, `apps`, `source`, `import`, `package_manager`, `metrics`, `build_output`, `generated_config`, `worker_vars`, `void_deploy`, `void_sandbox` and `void_cohost` harnesses all leaked on at least the panic path. A full suite run now leaves `/tmp` exactly as it found it.

Root cause was the test, not the group kill — `run_cmd`'s `killpg` cannot miss a grandchild that stayed in the step's process group (no `setsid`/`setpgid` in the script, no spawn/kill race across the 2 s timeout, the pid is pinned by the pending wait), but a killed test binary never reaches the kill, and the fixed marker then poisoned every later run's `/proc` scan until someone killed the stale sleeper by hand. The two supervisor group-kill tests got the same treatment.

- The email allowlist matches parsed addresses exactly: `@domain` entries match that domain only (subdomains need their own entry), never a string suffix.
- A tenant config can no longer alias the proxy's mail-idempotency store (`MAIL_IDEMPOTENCY` binding or `noite-void-proxy-mail` id), aim a second service binding at the proxy script, or use the mail binding name as a var — each fails the deploy naming it.
- `/ai/run` with `stream:true` returns upstream errors with their status instead of masking them as 200 SSE.
- Cohosted deploys render to owner-only temp projects removed on every path (failed deploys leave nothing on runner disk); the fleet token is ensured once per deploy and threaded into app and proxy alike, so a mid-deploy rotation cannot split them.
- Boot validation refuses `http` AI endpoints except loopback sidecars with `NOITE_VOID_AI_ALLOW_PLAINTEXT=1` (the per-app key would otherwise travel unencrypted), and rejects CR bytes in the mail domain, relay host and allowlist entries.
- The sandbox controller no longer redeploys on every deploy: per-deploy container-image paths are excluded from its content hash (the pinned-Dockerfile + build-context digest carries the content), so identical content in another build dir skips like the proxy does — which also removes the common case of two concurrent deploys racing celld's fence-image build.
- Cohosted script deploys (controller, proxy) retry once on infra-class errors, like the app deploy; tenant failures still fail at once.

### Fixed

- **A dropped DB setup pass no longer stalls the whole control plane in 5 s generations.** Every control request (actions and `/assets/*` alike, since `run_worker_first` sends assets through the worker) shares one isolate-level D1 setup pass. celld drops a request's pending work when that request answers or its client leaves, so when the starter's request finished first, the shared pass never settled: every waiter burned the full 5 s, then started its own equally orphanable pass — the 5 s, 10 s and 15 s stalls behind flake H and issues #91/#92. The starter now registers its pass with the worker lifetime (`ctx.waitUntil`), and waiters that outlast their bound share the single replacement pass instead of each starting their own. `ensureDb` accepts the lifetime and the bound (`EnsureDbOptions`; tests inject a zero bound and await real signals).
- **A failed load no longer poisons the panel, and nothing retries on a timer.** A resource whose load fails used to settle into the shared cache's permanent failure, so even remounting re-served the same error until a mutation forced a refetch. The failure is now evicted when it lands: the error still surfaces, but a later mount (or an explicit refetch) starts a fresh lookup. The round-1 timed auto-retry is gone — the product fix above removes the stall instead of waiting it out.
- **One fewer D1 round-trip on every admin action.** The env-anchored promotion check re-selected the user row on every admin request even when the fresh session role was already `admin`; it now returns early on that role, saving a sequential query against celld's single-threaded D1 on the hottest gate in the panel.
- **A lifetime-less setup waiter no longer stores a pass an abort can orphan.** A waiter that outlasts the 5 s shared-pass bound but carries no worker lifetime cannot register the replacement it would start, so it now fails fast instead of storing an unregistered pass: the next requests for the same store would otherwise await the orphan to the 15 s route timeout (flake H's `listEnvironments` + `errorDetail` pair, both 15.01 s to 504 after the same app's requests were aborted). The middleware always carries a lifetime, so it still owns every replacement; the fail-fast only triggers on a genuinely wedged pass.
- **The session read is bounded.** The better-auth session lookup reaches D1 with no timeout anywhere in its chain, so a wedged store rode every action to the 15 s timeout. `getSessionOrNull` now races the read at 5 s and throws on expiry: actions fail 500 with cause, browser routes deny as signed-out — deny either way, never proceed, never hang. `docker/check-worker-rules.ts` tripwires CI against the common regressions (module-level in-flight caches, session reads outside the bounded wrapper).
- **A failed snapshot meta upload is retried, not skipped.** The runner recorded a snapshot's hash as soon as the state object uploaded. If the metadata upload after it failed, the next pass saw identical bytes and skipped, leaving the bucket's `noite.sqlite.meta.json` stale (a new runner seeds its generation and skip hash from it) while `/ready` reported a fresh upload. The hash is now recorded only once both objects landed, and a skipped pass no longer resets the reported upload age.
- **App deletes and environment teardowns run to completion when the caller goes away.** The control plane times these calls out after 5 s, and a dropped request used to cancel the purge halfway — leaving the app row, the fleet and the scoped credentials behind. The destructive work now runs as its own task while the handler awaits it, so a disconnect only drops the waiter. A delete that finished server-side also no longer leaves a stale row behind: the admin apps list reloads after a failed mutation too, and the app's Danger Zone re-reads the app and follows the delete through when it is gone.
- **Deleting an app SIGKILLs its fleet first.** A graceful shutdown only does durability work the purge destroys a moment later, and young fleets regularly ignored SIGTERM for the whole grace — every slow delete in CI paid the full 3 s. Stops, sleeps and orphan sweeps keep the full graceful wait, and the 0.5 s settle before the S3 wipe stays.
- **S3 response bodies keep the request's own read deadline.** Every S3 body read now carries the same timeout as its request instead of relying on the HTTP client's internal total-timeout, so headers delivered with a body that never follows fail like a stalled send instead of hanging the caller.
- **A first deploy answers through the edge as soon as it reports success.** The runner added a new app or preview to the edge route table only after recording the deploy as successful. A request sent the moment the CLI, the UI or a script saw that success could get the "is starting" page (503) for a few milliseconds. The target is now routed first, and the deploy reports success after. A deploy whose route table the edge refuses now fails with the edge's answer, instead of reporting success for a target that isn't reachable. An edge that is restarting still lets the deploy through, because it boots from the table file, which already routes the target.
- **A just-created branch no longer misses from the branch picker.** A refs read overlapping a branch create could apply its pre-create manifest read, deleting the fresh ref from the push mirror (the picker's single refetch then cached its absence for the rest of the page); the same shape existed on the deploy-config read path, which synced with no seq check at all. Manifest re-apply is now double-checked under the slug's push mutex — an unlocked fast path serves local when the newest applied seq already covers the manifest, and only a newer manifest takes the guard and re-reads before syncing — and the applied seq never moves backward. Hot config readers serve local (cold hydration still syncs once), purge and slug-changing rename drop the slug's generation marker so a recreated slug's restarted seq applies rather than skipping as stale, and manifest staging uses a unique tmp path per call so a concurrent reader's download can never clobber a writer's flip.
- **The Errors, Deployments, Events, Logs and Metrics lists render their current data on load.** Every live list painted only stream frames, so a first frame delayed or lost anywhere between the runner and the browser left a skeleton until the data changed — for already-ingested data, forever. Each list now fetches its current snapshot once on a cold key (shared when a tab badge and its list use one key) and the stream keeps it live after; a failed fetch is ignored and stream frames always win once they arrive. New `errorList`, `listDeploys`, `eventsSnapshot`, `logTail` and `metricsFrame` actions serve those snapshots, view-gated like their streams.
- **A hung live-list snapshot fails visibly instead of holding a skeleton.** A first snapshot that hangs or fails every poll ended an open stream with no frames and no retry: the tab sat on skeleton with no banner. Every runner stream (errors, events, deploys, app state) and the log tail now ends with an error when no first frame arrives within 10 s, and the control hub drops a topic whose upstream opens but sends no first frame within 15 s — both surface as the retrying state the client already reopens, so the stall heals itself. The initial snapshot behind each list times out after 10 s too and is retried on a later paint. The `listDeploys` snapshot serves the same lean rows as the stream (finished rows carry no build log; fetch it on demand) while the runner list keeps full rows for API consumers, and `eventsSnapshot` rejects a non-integer or out-of-range `limit` with a 422 instead of a runner 500.
- **A lost `scoped_credential` row no longer leaves its key live forever.** When a mint's row never landed (a crash inside the snapshot loss window, then a restore), the old revoke path — which only acts on rows — could never reach the key, and the next mint for the scope handed out a second key while the first stayed valid. The new orphan reconcile above revokes those keys. Only principals carrying this install's tag can ever be revoked (MinIO keys whose attached policy is exactly the tagged per-key name, AWS users named `noite-<tag>-…` under exactly `/noite/<tag>/`); foreign users, other installs' keys, pre-tag keys and the operator's keys are never touched. A mint that hits an existing user name reads it back first and only clears a half-minted user under its own path — anything else fails loudly instead of deleting a foreign user. The listing runs without the mint lock (each candidate is fenced instead), and a listing failure revokes nothing.
- **A wedged `git` remote can no longer hold the e2e lane open in silence.** Every synchronous child process in the suite (`git` clone/push, the packaged CLI, its build) now carries a 120 s bound with `SIGKILL` and no credential prompts, and Playwright runs under a 25-minute parent-side `globalTimeout` (release shard 2 measured ~5 min). In merge-queue run 39785255412 a hung `git clone` blocked its worker's event loop, so no per-test or hook timeout could fire: 32 of 33 tests passed, then 35 minutes of silence until the job cancelled. The same wedge now fails loudly (`ETIMEDOUT` naming the command, or the `globalTimeout` naming the stuck test), and a red lane also captures the host process tree (`lane-host-procs.txt`) next to the container logs, so the stuck command is in the artifact.
- **Worker error occurrences no longer lose their request.** A failed span ingested before its access-log line was tailed stored its occurrence without method, path or status, and the re-read dedup kept the empty row forever — the Errors tab showed a blank request for an error whose line was in the log. The access-log tail now runs before the ingest each tick, and a span that still ingests first is marked pending so the tail backfills the stored row when the line lands.
- **Concurrent app and environment creates no longer start two fleets on one port.** Fleet ports were picked as the lowest free pair and then inserted in a separate step, so two creates racing each other read the same free pair and the loser's celld died at bind with "exited before answering its health gate". The pick and the row insert now run under one process-wide allocation lock, so the second claim always sees the first claim's ports.
- **`make doctor` no longer says "nulls ago".** Before the first state-snapshot upload `/ready` reports the upload age as JSON `null`, which the doctor line printed literally (`state snapshot (owner, last upload nulls ago)`). It now prints `no upload yet` and stays `ok` — the snapshot signal is additive and never fails `/ready`, so a fresh boot with nothing uploaded yet is normal, not degraded.
- **The multi-lane boot no longer fails on the first contested cgroup enable.** A healthcheck exec landing between the cgroup drain and the `subtree_control` write fails it with `EBUSY`, and the boot loop meant to retry that never did: the write helper formatted the OS error into a string, so the `EBUSY` classifier never matched and the first contention bailed the boot. Cgroup writes now keep the OS cause on the error chain, the retry rides out transient execs (the only possible squatters — the runner spawns nothing before setup, so its own children inherit the drained leaf by construction), and a persistent squatter still degrades loudly past the bounded budget. A fleet that exits between spawn and its cgroup move now also takes its orphaned workers with it instead of leaving them uncapped.

- **Browser errors through any Sentry SDK.** Settings → Error reporting shows the app's DSN (`https://<key>@<control host>/<n>`, rotatable by admins). A stock Sentry SDK pointed at it reports exceptions to `POST /api/<n>/envelope/`, and they land in the Errors tab as the same issues as the Worker's own errors, labelled Browser (or SDK for server SDKs) with the page URL and release. Transactions, sessions, replays and other non-error items are accepted and dropped.

The Errors tab maps each frame back to the original file, line and function, with the minified frame still shown beside it. There's no upload step. Maps are kept for the current deploy and the last 10 successful ones. Preview environments don't keep maps yet.
- **Custom domains need DNS proof of ownership on multi-tenant installs.** Before, any tenant could claim any hostname, first come first served. Now a new domain starts as _pending_, and Settings shows the TXT record to create (`_noite-challenge.<hostname>` with the domain's token) plus a **Verify** button that names what's wrong (no record, wrong value, DNS error). A pending domain gets no route and no certificate. Several apps may hold a pending claim for the same hostname, and the first to verify wins. On `single` installs a domain is verified as soon as it's added.
- **Fleets and release commands hold scoped bucket keys.** Each app's fleet and each preview environment's fleet now hold keys minted through the store's own IAM that read, write and list only their own prefix — an environment's keys never reach production's data, and no fleet reaches another app's. Covered per store (SPEC, Scoped credentials): bundled RustFS and MinIO through the MinIO admin API, AWS S3 through the IAM API, R2 and unrecognized stores on an explicit `root` mode. Renames supersede keys, deletes and environment teardowns revoke them (a retrying sweep finishes refused store deletes), and a deleted-then-recreated slug waits for the old key's revocation first. Release commands, which used to be skipped in `multi`, now run with the scope's own keys. The hostile e2e suite asserts a deployed Worker can't read another app's objects.
- **One fleet can no longer shed every app.** Each tenant fleet runs in its own cgroup v2 child with `memory.max` (`RUNNER_FLEET_MEMORY_MB`, 512 MiB by default) and `pids.max`, so a growing fleet is OOM-killed inside its own group — contained, and the supervisor restarts it — instead of pushing every fleet toward the shared shed threshold. Swap is disabled per leaf (`memory.swap.max=0`): without it the kernel swaps a capped fleet out instead of OOM-killing it. An OOM kill records a tenant-visible `fleet` app event and fleet log line (`fleet restarted: memory limit … MiB exceeded (Settings → Limits)`). `CELLD_MAX_RSS_MB` deliberately does not follow the per-fleet cap: celld measures container-scale working set, so a per-fleet value closed every fleet's ready gate in the lane. Settings → Limits gains a per-app **Fleet memory** override (applies on the fleet's next spawn), capped by the new operator knob `RUNNER_FLEET_MEMORY_MAX_MB` (default: the default cap, so a tenant can only lower its cap): the runner refuses a higher value in `multi` and clamps rows stored before the ceiling was lowered. The grant is narrow and multi-only (`docker/compose.multi.yaml`: `CAP_SYS_ADMIN` plus lifting Docker's default AppArmor mount denial — no `privileged`); single installs get nothing new. The hostile-tenant lane asserts each live fleet carries a positive `memory.max` and that `/ready` reports cgroups active.

### Fixed

- **`install --pre` installs the newest release again.** It took the first entry of GitHub's release list, which puts the release marked Latest ahead of newer pre-releases, so it installed 0.1.0-alpha.6 instead of 0.1.0-alpha.7. It now picks the most recently published release. `run.sh` is served from noite.now, so the fix applies without a new image.
- **Status badges stay in sync.** After a deploy, a stop or a sleep, the app header's status and the Deployments tab's Production and environment dots kept the old state (a yellow "Deploying" dot after a finished deploy) while the sidebar moved on, until a reload. An app's pages now follow a live state stream (`/api/apps/:id/state/stream`) and refresh whatever it shows has changed, and the sidebar's app list updates every 2 s instead of every 10 s.
- **The Ilha + Void template no longer loses early input, and adding a todo no longer reloads the page.** Its todo form and About-page counter were server-rendered in place but worked only once the page's scripts had run. A todo typed and added before that turned into a plain form GET that reloaded the page without adding it, and an early counter click did nothing. Both now stay disabled until the page can handle them. The todo action also answered with a bare `{"ok":true}` instead of the page data Void's client expects, so every add reloaded the whole page; it now updates in place. The template is fetched from GitHub when an app is created, so the fix applies without a new image.
- **A rollback issued right after a deploy no longer vanishes.** **Roll back** answered OK, but if the app's previous deploy was still finishing, the rollback was silently skipped: no deploy row appeared, and the page kept waiting for a deploy that never started. A rollback now creates its queued deploy before answering and waits its turn behind the in-flight deploy, the way environment deploys already did. The runner's rollback response (`deploys.rollback`, `POST /v1/apps/{id}/rollback`) also returns the new `deployId`.

Rate limits, the fleet readiness hold, wake-on-request, the env gate, frame headers and the starting page all behave as before.

- Code mode's Terminal panel came back **empty** when it was reopened (`?terminal=1`): ghostty-web's render loop redraws only the rows its WASM render state marks dirty and clears that state after every render, so a canvas that had lost its pixels — the bitmap is thrown away whenever a resize assigns the canvas its new `width`/`height` — stayed blank until the shell next wrote something (the prompt of a command, an echo, any output), and the reopen itself repainted nothing: the fit addon does nothing while its container has no size (the shell is out of the document, or the panel is not laid out yet) or for 50 ms after a resize, and `Terminal.resize` returns early when the grid already has the size proposed. The panel now measures the pane the shell actually sits in (its `ResizeObserver` used to keep watching the pane the previous mount had built), fits on the frame the box is real, and forces the full repaint ghostty otherwise reserves for a resize, so the shell's screen is on show from the first frame.
- **Code mode switches branches in place.** Every `?ref=` change used to remount the whole browser: the tree and the editor went back to their "Opening checkout…" skeletons, a second pod frame booted cold (fetching and untarring the ref again), a second language-service worker was spawned, and a ref whose listing or pod frame did not answer in time left the panes on skeletons for good. The browser is now mounted once per app and installs the new ref's checkout under the panes it already has: the tree and the editor keep showing the branch the user came from (marked _Switching to `<ref>`…_, input blocked) until the new ref's rows and file are ready, the intel worker re-syncs to the new ref instead of being rebuilt, and the checkout the user came from stays open for 90 s, so toggling between two branches is instant and each branch's unpushed drafts are exactly where they were left (drafts are per app **and** branch, in the pod's own IndexedDB workspace — nothing crosses). A ref that cannot be opened — a listing or a pod frame that times out, a frame that dies mid-session — leaves what was on screen standing and offers **Retry** instead of a stuck skeleton. `?file=` reopens on the new ref when it exists there and falls back to the Worker config the way a first open does.
- **Code mode's diagnostics came back wrong until a reload after switching branches in place.** With `cloudflare.config.ts` open, a switch to another branch left `TS2307: Cannot find module 'cf/config'` under the import — the declaration was in the language-service worker's FS the whole time — and opening another file did not clear it; only a reload did. A switch re-set the versions the worker resolves packages against from the new ref's lockfile, which dropped **every** specifier's resolution, including the ones both lockfiles pin identically, and re-acquiring them only re-pointed the declaration URLs already fetched: no file landed, so the pane was never told to check the open file again. What a specifier resolved to now survives a lockfile unless that lockfile moved its package's version, a round that publishes a resolution without fetching anything still tells the pane to re-check, and a round that outlives the lockfile it started under drops its answer instead of publishing it.
- **Code mode's Changes panel pushed a "New branch…" commit to the browsed branch.** Picking **New branch…** and naming it still committed onto the branch you were browsing (often `main`): the target select's rework stopped sending the new branch's name. The push now creates the named branch at the browsed tip again.
- **An environment created while production was deploying failed at once** with "another deploy of this app is in flight" and deployed nothing until the next push. A deploy with a visible queued row (creating or redeploying an environment, a workspace preview) now waits for the app's running deploy to finish instead of failing; background tip deploys still skip and are picked up by the next reconcile.
- The branch picker stayed open after **Create**, so the next click on it closed it instead of opening it: a parent repaint wrote back a stale open state. The dropdown now owns its open state, which repaints leave alone.
- The Changes toggle's count badge holds the number alone again; the words around it are screen-reader text.

### Security

- The control UI is served cross-origin isolated: every document, module and worker script carries `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`, and its own assets `Cross-Origin-Resource-Policy: same-origin` (`apps/noite/public/_headers` for the deployed UI; the Vite dev server sets the same three on every response). The editor's TypeScript language service needs `SharedArrayBuffer`, which a browser exposes only in an isolated agent cluster; `require-corp` rather than `credentialless` because the UI loads no third-party subresource. A reverse proxy in front of Noite must pass response headers through unchanged (see Edge protection in the docs).
- **Code mode: no app-controlled code runs on the control UI's origin.** The whole workspace — Nodepod, the checkout, an install and its lifecycle scripts, the app's `dev` script and bundler config, a build, the Preview, and anything typed into the Terminal — is one document on the app's preview host (`app-0.preview.<slug>.<base>/noite-pod-host.html`), and it is the only document that creates the pod's process workers, so that code holds the preview origin's cookies and storage and not the control UI's session: it cannot call the control API as the signed-in viewer, and it cannot read any app's saved workspace out of the control origin's IndexedDB. The control page keeps the UI, the editor and every cookie-carrying call, and reaches the workspace over a `MessageChannel` that is origin-checked in both directions, handed over only after a nonce handshake and only to the frame the page itself embedded. The control origin answers 404 for every pod path — the host document, its bundle, Nodepod's process-worker bundle, its service worker and the dead preview bridge — so nothing a link can reach there creates a worker or registers a service worker. A page that cannot read the app's preview origin opens no workspace at all (it says so) instead of running without that separation, and a preview whose origin comes back empty is refused before anything is installed or run.

### Fixed

- Code mode showed a blank grid while a checkout opened, and a blank editor when nothing was open. While the workspace loads, the file tree and the editor now draw daisyUI skeletons shaped like their content (tree rows; a file header and code lines), announced to screen readers as **Opening checkout…**. The editor says **Select a file to view** when the browsed ref names no file to open, and **This repository has no files yet** when the branch holds nothing.
- Code mode's Preview stayed white in dark mode: the frame had a fixed white background, so an app that follows `prefers-color-scheme` (and the browser's own JSON and text views) drew its light dark-mode text on white. The frame now uses the theme's background; it already passes the page's color scheme to the app inside, and an app that declares no color scheme still gets the browser's light page.
- Hover tips in Code mode's editor died for the rest of the session after one placeholder: opening a binary or oversize file (or deleting the open file) painted over the container the tip lived in. The tip now hangs beside that container, so type info, diagnostics and declaration previews keep working.
- Switching branch, tag or commit in Code mode left the previous ref's tree wiring listening on the pane: a right-click on empty tree space opened a menu bound to the closed workspace (New file, Rename and Upload acted on a torn-down pod), and dropping files from the computer ran the upload twice. The wiring now tears its listeners down.
- A failed **Restart** in Code mode's Preview kept showing the old state and URL — a green **Ready** over a server that was gone. It now reports the error like a failed start does.
- A refused editor write left its warning banner in Code mode forever, still claiming the failure after later writes landed; the banner now clears on the next successful write.
- Code mode's editor shows the open file's change status. The header carries the same unpushed-change letter the file tree marks a row with (added, modified, moved, deleted), read from the workspace's own changes, so it survives a reload and follows a discard, an undo or another tab's write instead of being lost with the page. Previously the tree marked the row but the editor said nothing about the open file.
- A deploy failed with "parse wrangler config: trailing comma" when a `wrangler.jsonc` member ended with a comma followed by a comment.
- Push rules failed open: a push whose commands the runner couldn't parse skipped every check, so a push-role collaborator could force-push or delete `main`. Such a push is now refused, and git also enforces "no force-push, no delete" for every non-admin.
- Creating apps in parallel could go past the per-account app limit, and a losing create of the same slug could wipe the winner's repository. Creates are now serialized.
- The UI's git-auth reply no longer defaults to the push role when it names no role.
- Opening another file in the source browser threw away the unpushed edits of the file before, so a web commit could only ever change one file. Each change of `?file=` remounted the browser. Edits to any number of files now stay until you push them together.
- A boolean (`FLAG_…`) env var's toggle in Settings could keep showing on after it was turned off, until a reload: the control UI's ilha didn't write `checked={false}` back to a live checkbox. Bumped ilha to 0.15.2 and @ilha/router to 0.11.16, which also keep controlled `<select>` and `<textarea>` values in sync.
- The same bump made an in-place navigation leave a stale view behind: ilha reuses a keyed component without re-running it when its props are unchanged, and a `?query` read is not a reactive read, so a control that writes one (`?size=`, `?page=`, `?view=`, `?f=`, `?q=`, `?t=`, `?e=`, …) changed the URL while the grid, list or filter kept the old state — the storage editors, the admin searches and Code mode's panels among them. The control UI now reads search params through a wrapper whose reads subscribe the reading component to navigation, whether it reads the param itself or receives the handle as a prop.
- Preview binding data (Durable Objects, D1, KV, R2) no longer depends on the reload outrunning the workspace's debounced IndexedDB save: every write under the preview state's directory is mirrored synchronously into sessionStorage and overlaid after the restore, so a reload keeps counting, listing and reading where it left off. States past the mirror's size cap still fall back to the debounced save.
- Preview wrote its own tooling into the app: `srvx` and `vite` were installed with the pod's save-to-`package.json` flag, so the app's `package.json` gained them and showed up in Changes. They now install into the preview's harness directory beside the generated server, and the app's own dependencies install without being written back.
- Code mode: a workspace save that fails (a full browser store, a denied quota, a partition that went away) is now reported in the banner above the editor instead of only the console. The pod keeps retrying the save, so the banner is the only sign that what the editor shows is not being kept; the page's own `flush()`/`close()` rejections are reported the same way.
- Code mode's Preview refused to run on `https://noite.local` (a `CONTROL_EXTRA_HOSTS` name served over https by portless): the preview origin was always built on `BASE_DOMAIN`, so a `noite.localhost` dev base handed the secure page a plain-http `app-0.preview.<slug>.noite.localhost` frame and the panel showed the mixed-content refusal. The preview host now follows the page onto a DNS `CONTROL_EXTRA_HOSTS` entry (`https://app-0.preview.<slug>.noite.local`), which the edge already serves; bare IPs and the configured base keep today's origin.
- The app creator's mode tabs kept **Blank** highlighted after another mode was picked; the modes are now native radio cards.
- Creating an app with a slug someone already had showed the runner's raw error (`runner rpc apps.create: 409 slug already taken`) in a banner. The creator now says so under the Slug field and offers a free variant.
- Deleting an app could leave its celld running. The delete stopped the fleet and then spent seconds purging S3 while the app still counted as deployed, so the reconcile loop (or a request's wake) started it again, and with the row gone nothing stopped it. The orphan kept the app's port, and the next app given that port crash-looped on "Address already in use" and never served. A delete now marks the app stopped before purging and stops the fleet again after the row is gone, and every reconcile tick stops any fleet whose app no longer exists.
- Code mode could save a file's text from before its last keystrokes. The page ships one write per path at a time and held a typing burst's later text until the write in flight answered, so a flush asked for in between — a reload, a hidden tab, a closing tab — saved what the pod's volume held _then_: the last keystrokes of an edit the Changes panel already counted as a change were missing from the restored workspace (which, after a reload, showed the file with none of the edit). The page now ships whatever it still holds before it asks the pod to save. Even then, the pod's own save to IndexedDB is asynchronous and could die with the frame on a reload, so the checkout's unsaved writes (edits, new files, renames and deletes) are also mirrored synchronously into the tab's sessionStorage, the way the Preview's binding data already was, and replayed over the saved copy on the next open. The mirror empties itself whenever a save leaves nothing pending, so it never replays text older than what was saved.

## [0.1.0-alpha.3] - 2026-10-06

Opt-out instance telemetry, storage editors, the admin home, and a pre-release flow for releases.

### Operator action required

- **`RUNNER_BUILD_UID` and `RUNNER_BUILD_GID` are removed** and ignored if still set: delete them from your environment. Builds and release commands now run as one uid per app from a reserved range, `RUNNER_BUILD_UID_BASE` (default `10030`) and `RUNNER_BUILD_UID_RANGE` (default `1024`). The image pre-creates the default range in `/etc/passwd`; a custom range needs matching `/etc/passwd` and `/etc/group` entries, must stay below 65534 and must not contain `RUNNER_FLEET_UID` (10020).
- **Expect a one-time telemetry replay after the upgrade.** The runner re-reads the stored telemetry for the whole retention window (`RUNNER_TELEMETRY_RETENTION_DAYS`, 30 by default) for every app, to recover the rows the pre-alpha.2 ingest bug skipped. It runs in the background with no downtime; the cost is extra bucket reads and DuckDB CPU in proportion to window × apps. The runner logs `telemetry replay started` and `telemetry replay complete`. Telemetry older than retention was already pruned and cannot be recovered.
- Both databases upgrade themselves: the runner SQLite goes to schema version 5, the control D1 to 1.4.0. As before, an older image refuses newer data, so back up before upgrading.
- **This release adds anonymous instance telemetry, and it is on by default.** Once a day the instance sends one count-only heartbeat: the version, platform, storage kind, numbers of apps, deploys and users (users bucketed), install age and uptime. It is keyed by a random install id; no domains, names, emails or IPs are sent, and nothing at all is sent from a local domain. To turn it off, untick it in the Admin section of `/account`, or set `NOITE_TELEMETRY=0` (or `DO_NOT_TRACK=1`) in `.env`, which also locks the checkbox. The full list of fields is on [Telemetry](https://noite.now/self-hosting/telemetry).
- **A malformed `RUNNER_TELEMETRY_RETENTION_DAYS` now stops the runner at boot** with a config error. Before, it silently fell back to 14 days, though the documented default is 30. Unset still means 30.
- **Runner REST API callers:** status codes and one response changed; see Changed. Scripts that matched on 409 for storage or source errors, sent extra fields to `PATCH /v1/apps/{id}`, or read `remote` from the git-remote response need updating.

### Added

- Anonymous instance telemetry. The runner sends PostHog EU one `instance_heartbeat` event a day: no SDK, GeoIP lookup disabled, no person profiles. An Admin section on `/account`, shown to instance admins only and never while impersonating, turns it on or off and shows the exact payload. The runner API has `GET`/`PUT /v1/admin/telemetry` and RPC `telemetry.get`/`telemetry.set`. The installer prints a notice and accepts `NOITE_TELEMETRY`. Dev and e2e stacks never report.
- New login page: a product panel ("Push code. Get a URL.", three benefits, a deploy preview) next to a clean sign-in form, in light and dark, with a mobile layout. Sign in is the default tab; a fresh instance opens on "Set up Noite" and says the first account becomes the admin. Lost-passkey recovery is a separate view.
- First-run onboarding: a three-step tour after sign-in (push to deploy, one API key for Git and the CLI, stay in the loop: GitHub releases, Discord, GitHub Sponsors). Story-style progress bars, Back from the second step, arrow keys to move between steps, and a bottom sheet on mobile. The tour never navigates away: steps 1 and 2 spotlight the sidebar's Apps item and your avatar instead (skipped on mobile, where the sidebar is hidden). "Get started", × or Esc ends it for good. Accounts created before this release see it once.
- Admin home: `/apps` lists the control plane ("Noite · admin") for instance admins, and its page holds every admin tool: Overview, Metrics, Errors, Logs, Users, Apps and Invites tabs. Users, Apps and Invites are the panels god mode used, with the same actions and URL-kept searches. `/god-mode` and the account menu's "God Mode" item are removed. The whole page, and every admin action behind it, is refused while impersonating.
- D1 table editor (Storage → D1, and the control database on the Noite admin page):
  - **Layout:** a table list with row counts, a toolbar with search, filters, sort, refresh and Insert, Data and Definition views, and a side panel for editing rows. Paging, sorting, filtering and search run in SQL on the server, so they cover the whole table, not just the first rows.
  - **Row editor:** shows each column's type, primary key, NOT NULL, default and foreign key. NULL and the empty string are separate values, and an insert leaves untouched columns to their defaults. Helpers fill in "Now" timestamps, format JSON and toggle 0/1 columns; a foreign key opens the referenced row.
  - **Editing:** changed fields are highlighted and only they are saved. Delete asks for confirmation inside the panel, rows can be deleted in bulk (1–100 at a time, in one transaction), and a toast confirms every write.
  - **Control database:** read in-process by the control worker, never through `celld d1 execute`.
    - **Masked:** secret columns never leave the worker (session tokens, account passwords and OAuth tokens, verification codes, passkey keys, API keys). They can't be filtered, sorted or searched, so a secret can't be guessed piece by piece.
    - **Read-only:** the auth tables, except that deleting a `session` row revokes it. `user.role` and the ban columns are managed in the Users tab. Tables not explicitly allowed are read-only too.
    - **Your own row:** you can edit it but not delete it.
    - **Links:** a `user` row links to "Manage in Users", an `invite` row to "Manage in Invites".
- R2 browser (Storage → R2):
  - **Browsing:** breadcrumb navigation, folders, search within the current folder, list and column views, and pages of 100.
  - **Details panel:** an image or text preview, type, size, last modified and ETag, plus Download, Copy URL and Delete.
  - **Uploads and folders:** upload files (up to 64 MiB each) and create folders through `celld r2 put`, so an object carries the same record a Worker's `env.BUCKET.put()` writes, and the Worker reads uploads back as-is. Deletes go through `celld r2 delete`, including bulk deletes of up to 100 objects.
  - **Safe previews:** downloads use the object's own content type with `nosniff`, and SVG, HTML and XML are sandboxed.

Rows are keyed on the reserved `_control` slug with no `app` row, so reconcile, Caddy, scale-to-zero, purge and `GET /v1/apps` never see it. The Noite app page gains Overview, Metrics, Errors and Logs tabs (Logs include the control node's own output); instance admins only, never while impersonating. The numbers include the dashboard's own polling. `noite-runner telemetry reingest --slug _control` replays its window. `make dev` serves the UI from vite, not celld, so the page says telemetry needs the release image instead of showing empty charts.

### Changed

- Re-running the installer fills in any required `.env` setting that is missing or still at a dev default, instead of leaving the runner to refuse its config: the domain settings, ports, runner token, auth secret and RustFS keys. Values that are set are never changed, and the installer lists what it added. A missing `BASE_DOMAIN` is now asked for (or taken from `NOITE_DOMAIN`). Before, the installer stopped with "fix it or move it away".
- Telemetry ingest is idempotent and resumable. It works in hour-aligned chunks and replaces each window's minute buckets, span stats, log lines and error buckets instead of adding to them, so a retry, a catch-up after downtime or a replay never counts twice. After downtime the gap is read hour by hour, oldest first, bounded by retention.
- Telemetry ingest isolates a failing app: healthy apps keep aggregating while the broken one retries after a backoff. Apps that stopped (scale-to-zero, crash, runner shutdown) still get their remaining complete hours aggregated.
- Error issue counts are derived from the retained hour buckets, and logged-error capture is capped per app per hour (200) instead of per ingest pass.
- Boot order: signal handling, then Caddy, then every tenant fleet, then the REST listener, and only then the control UI deploy. A release that changes the UI bundle no longer delays tenant apps. Measured locally, 1, 5 and 15 apps all serve again within 5.1 s of the new container starting, and requests during that window are held at the edge, not refused.
- The nft egress policy matches the whole build uid range instead of a single build uid. The image no longer has a shared `build` user. `single` tenancy uses the same per-app uid path.
- Runner D1 API: `storage.d1.get` and its REST route are removed. `storage.d1.{tables,schema,rows,write,delete_rows}` and their REST equivalents under `/v1/apps/{id}/storage/d1/{database_id}/` replace them. Rows are read as JSON (`celld d1 execute --json`), and a write now treats `null` as SQL NULL and `""` as an empty string.
- Runner R2 API: listing takes `prefix` and `cursor` and returns folders plus content types. `PUT …/storage/r2/{bucket}/object?key=` uploads, and `storage.r2.delete` takes 1–100 `keys`.
- `oxidejs` 0.5.10 → 0.6.0, which drops the control UI's workarounds for the old behavior:
  - **Action typing:** the `checkedSchema` cast is gone; the server modules use `withSchema` directly, and the casts around awaited action results are removed.
  - **Errors:** user-facing action errors use oxide's `fail(message)` instead of the in-house `failAction`/`ActionError`, and error display no longer special-cases plain `{ message }` rejections, since action errors now arrive as `Error` objects.
  - **Database setup:** the once-per-isolate setup pass uses oxidejs `isolateOnce` (15 s timeout, 5 s wait) instead of a hand-written promise cache. On the release image it ran once per isolate, 3 passes across about 340 requests.
- Releases go through a pre-release. A `v*` tag publishes the version image and a GitHub pre-release with its CHANGELOG notes, but no longer moves `alpha` or `stable`. `curl -fsSL https://noite.now/run.sh | bash -s install --pre` installs the newest release, pre-releases included, pinned to its version. Marking the pre-release as a full release points `alpha` (and `stable` for a final version) at the same image, so plain installs and upgrades pick it up.
- Docs: the measured upgrade window replaces "about a minute for many apps".
- Runner API status codes. Storage and source failures used to answer 409 Conflict whatever went wrong. Now a missing object, table, deployed source or Git mirror is 404, an invalid path is 400, and an internal failure is 500. 409 is kept for real conflicts: a taken slug or hostname, a deploy in flight, or a web commit that lost the race against a push. RPC `events.*` returns 500 for a database error instead of 404.
- `PATCH /v1/apps/{id}` rejects unknown keys with 422, as RPC `apps.patch` already did, instead of ignoring them.
- The git-remote response (`GET /v1/apps/{id}/git-remote`, RPC `git.remote`) returns the URL once, as `url`. The duplicate `remote` field is gone.
- `/profile` is removed. Use `/account`.
- Invite codes on the account page and in the admin Invites tab stay visible, with a Copy button next to them. Before, the code itself switched to "copied" when clicked. Every copy button in the UI now behaves the same way.
- Codebase reorganization, no behavior change beyond the entries above:
  - **Runner API:** one service layer (`src/service/`) now implements both the REST and RPC APIs, replacing two copies that had drifted apart. New handler tests check that both give the same results.
  - **Large files split:** in the runner, `db.rs`, `host/metrics.rs`, `host/cmd.rs` and `main.rs`; in the control UI, the action modules, HTTP routes and the largest panels. The control UI's server-only code now lives in `lib/server/`.
  - **Generated types:** the runner's API types are generated for the UI, and CI fails when they are out of date.
  - **CI:** pull requests and release tags run the same reusable check workflow. Release tags were skipping the shell-script and schema checks.
  - **Docs:** the roadmap and design history moved from `SPEC.md` to `ROADMAP.md`.

### Fixed

- Deleting an app over RPC (what the control UI does) did not revoke its stored credentials; only the REST route did. Both now share one code path.
- Two builds running at once could read each other's worktree and build cache, because both ran as uid 10010.
- Rows skipped by the pre-alpha.2 ingest bug are recovered within retention by the one-time replay.
- A failed or partial telemetry pass no longer advances the watermark, one app's failing telemetry no longer stalls every other app, and compaction can no longer double count an hour whose source delete was interrupted.
- The app page's Stop button did nothing. The control UI sent `desired_state` to the runner's `apps.patch`, which reads `desiredState`, so the field was dropped and the patch changed nothing. It now sends the right key, and `apps.patch` refuses unknown parameters, so a mismatch shows an error instead of silently doing nothing.
- Dropdowns stayed open: after clicking an item that navigates, on a click outside them, and on Esc (the D1 Filter and Sort popovers only closed when their own button was clicked again). Every dropdown now closes on an item click, an outside click or Esc.
- A SIGTERM during boot killed the runner outright: fleets were SIGKILLed and the final state snapshot was lost. A stop now stops every fleet inside the stop budget and writes the snapshot at any point in boot.
