# Frontend style (`apps/noite`)

Read before changing TS/TSX, ilha components, or Void JSON actions. `AGENTS.md` keeps the rules every change must satisfy; this page is the house style.

## TS / TSX (apps/noite)

- Explicit types; `SAFETY:` comment before any `as unknown as T`.
- Wrap `new URL(...)` (throws on bad input).
- Lowercase `onclick`-style event props (ilha).
- Dynamic `import()` for heavy libs to code-split (Pierre stays dynamic for bundle size; `scule` is static).
- Control UI house rules: icons as JSX components from `lib/ui/icons.tsx`; controlled inputs only (`value`/`checked` + `oninput`/`onchange`, resets via atom writes); shared async data via the SWR hooks in `lib/resources.ts` and live panels via `liveFeed()` in `lib/feeds.ts` (both paint the last snapshot from `lib/swr-store.ts` across remounts and reloads, so skeletons only show on a cold key — a resource reads one `state()` (`ResourceState`: only `Loading` is a skeleton; use `resourceValue`/`resourceError`) and a live panel reads one `state()` (`FeedState`: `Cold`/`Cached`/`Live`/`Reconnecting`/`Refused`/`Paused`/`Offline`; use `feedValue`/`feedLoaded`/`feedRetrying`), never a `data()`/`loading()`/`latest()`/`status()` combination; persist only what the UI renders, never credentials); URL state through `searchParam`; `ref` callbacks for vanilla libraries; `<Dialog>` (`lib/ui/dialog.tsx`) for modals; no `node:` (or bare Node builtin) import in page-reachable code — server-only work lives behind a server-only module (`bun docker/check-client-node-imports.ts` enforces it).
- ilha pitfalls (each shipped as a bug once): (1) components re-run on every parent render, `watch` runs the _latest_ render's callback, `ref` fires only on mount, and `watch.once` runs during render before refs attach — keep DOM handles and other per-instance mutable state in `atom.lazy(makeBox)()`, never in body `let`s, and await refs before touching them; (2) `resource()`/`fromEventSource()` stay bound to their first key/URL in a reused fiber — render route bodies keyed by their params (`<Body key={id} …/>`); (3) the layout never remounts, so every auth change (sign-in, sign-out, impersonation) must call `invalidateSession()` — after the auth call completes — to drop all user-scoped caches and snapshots; (4) never write atoms during render (e.g. seeding form fields from loaded data) — it races ilha's patching; derive the displayed value instead (`draft() ?? loaded`). (5) never let a vanilla library append into an ilha-rendered element — the morph deletes children and attributes the JSX doesn't declare; mount it inside a shadow root you own (`paneIn` in `lib/source/browser.tsx`); (6) a parent re-render detaches and re-attaches reused child subtrees, blurring focus inside them, and ilha can't restore focus inside shadow roots — keep fast-changing state (e.g. a dirty count) out of any ancestor of a focused imperative widget by reading it in a small leaf component; (7) every component paints into a `<span data-ilha-slot style="display:contents">` host, so any component under child-combinator CSS breaks (daisyUI `menu` `li > *` matched the span, un-styling sidebar/account/storage links) — render the native element directly there: `useLink()` on a plain `<a>` for GET links, and keep `Link` where prefetch/`data` is needed or no `>` selector applies.
- UI state machines: a lifecycle is one value, never parallel flags (`busy` + `error` + `done`). Small state (one action's run/fail, a dialog's steps) is one atom holding a `Data.TaggedEnum` plus pure transition functions. An island with several interacting messages or async steps is an `@ilha/model` app (`defineApp`: TaggedEnum messages, one pure `update`, commands as Effects whose expected failures become messages, `keyed` for latest-wins, subscriptions for streams). `defineApp` components take no props, so inputs go through `islandProps` in `lib/island.tsx`: `Props.read()` in `init` (seed the model) or `view` (inputs the parent keeps changing), and export `Props.wrap(app)`; a command gets its inputs from the message that started it. Name the constructors apart from the type (`type Message = Data.TaggedEnum<…>; const Msg = Data.taggedEnum<Message>()`, `Record<never, never>` for an empty case): oxlint's `no-redeclare` and `ban-types` refuse the docs' idiom. Unit-test `update` directly.
- `for…of` over `.forEach()`; `i += 1` over `i++`; arrows over `function` forms; prefer early `return` and non-nested ternaries.
- Buttons: `btn-sm` everywhere — no other size modifiers (`btn-xs`/`btn-md`/`btn-lg`/`btn-xl`).

## Void JSON actions

Adding an action without importing its runner helper fails at runtime as `runnerX is not defined`; a plain throw is masked to the client as the generic 500 "Internal error" — throw `fail(message)` (`ActionFailure` in `lib/server/api.ts`, painted from the 422 `{errors}` shape; `failUnknown` in `lib/auth.ts` maps an unknown catch value) or a declared `Schema.TaggedError` to surface the real message.

## Bounded actions

**Actions are bounded, and must stay that way.** `src/middleware/01-timeout.ts` (15 s JSON 504; `*/stream`, `/storage/*`, `*/archive` exempt) answers a stuck action before the edge's 30 s timeout — Void has no action timeout, so the bound lives in-repo. The app-detail and admin-page stalls were oxidejs defects on Cello, fixed in oxidejs 0.5.6 ([ROADMAP: Design history](../../ROADMAP.md#design-history), 2026-09-27) — history, kept; the instance admin page is now covered by `apps/noite/e2e/admin.spec.ts` (release suite).
