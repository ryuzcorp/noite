---
title: Environment variables
description: Every runner env var with its default, effect, and owner.
---

Defaults below are what `docker/compose.yaml` applies when the var is unset. The runner refuses dev secrets off a `localhost` base. A set-but-malformed numeric value refuses the boot instead of falling back: the runner exits naming each bad var, its value and the expected form — unset (or empty) still means the default.

Ownership: **runner-owned** (read by the runner) vs **worker-passthrough** (handed to the control UI worker untouched).

These are install-level variables (Compose, the image environment). Per-app values live in each app's Settings → Environment instead: they reach the app's install, build, release command, fleet, and Worker code (`env.NAME`), and a change applies from the next deploy. See [Configure](/apps/configure).

## Bounds

| Var | Default | Effect | Owner |
| --- | --- | --- | --- |
| `RUNNER_MAX_APPS_PER_USER` | `10` | Per-account app quota, enforced on create | runner-owned |
| `RUNNER_MAX_ENVIRONMENTS_PER_APP` | `5` | [Preview environments](/apps/environments) per app, enforced at create | runner-owned |
| `RUNNER_MAX_ENVIRONMENTS` | `25` | Preview environments per instance, enforced at create | runner-owned |
| `RUNNER_ENVIRONMENT_TTL_H` | `168` | Hours without a deploy before a workspace preview is swept (7 days); `0` disables the sweep | runner-owned |
| `RUNNER_FLEET_MAX_RSS_MB` | `0` | → `CELLD_MAX_RSS_MB` when non-zero; container-wide shed threshold by design (celld measures container-scale working set), never per-fleet; `0` = celld default (80% of container memory) | worker-passthrough (fleet) |
| `RUNNER_FLEET_MEMORY_MB` | `512` | Per-fleet `memory.max` in MiB (own cgroup per fleet); per-app override in Settings → Limits; needs the multi-only cgroup grant (`docker/compose.multi.yaml`) — without it fleets share the container cgroup | runner-owned |
| `RUNNER_FLEET_MEMORY_MAX_MB` | default cap | Ceiling for a per-app memory override in MiB; in `multi` a tenant can only lower its cap, never raise it past this. Single installs ignore it | runner-owned |
| `RUNNER_FLEET_IDLE_EVICT_S` | `120` | → `CELLD_IDLE_EVICT_S`; idle seconds before a fleet hibernates cells | worker-passthrough (fleet) |
| `RUNNER_FLEET_LEASE_TTL_MS` | `60000` | → `CELLD_TTL_MS` on every fleet and the control node; a storage or disk stall longer than two thirds of it restarts every app. Minimum `10000` | worker-passthrough (fleet) |
| `RUNNER_FLEET_DEPLOY_POLL_S` | `300` | → `CELLD_DEPLOY_POLL_S`; covers missed `/reload` only | worker-passthrough (fleet) |
| `RUNNER_FLEET_ASSET_CACHE_MB` | `64` | → `CELLD_ASSET_CACHE_BYTES`; per-fleet on-disk asset cache | worker-passthrough (fleet) |
| `RUNNER_FLEET_LOCAL_CACHE_MB` | 1/16 of detected memory, clamped `64`–`512` | → `CELLD_LOCAL_CACHE_MAX_BYTES`; per-fleet hibernated-DB cache (celld's own default is 2 GiB per node) | worker-passthrough (fleet) |
| `RUNNER_CONTROL_MEMORY_MB` | 1/4 of detected memory, clamped `256`–`1024` | Control fleet (`fleet #0`) cap in MiB; its own cgroup leaf when the install has writable cgroups, else the container-wide shed threshold | runner-owned |
| `RUNNER_FLEET_SPAWN_BATCH` | `1` on ≤ 2 cores, else `2` | Cold fleets started per reconcile pass, so a boot or upgrade does not stack every celld at once; restarts are never batched | runner-owned |
| `RUNNER_BUILD_CONCURRENCY` | `1` on ≤ 2 cores, else `2` | Concurrent tenant deploys; one slot covers install, build, release and the `celld deploy` | runner-owned |
| `RUNNER_BUILD_MEMORY_MB` | detected memory minus a 1 GiB resident floor (a quarter of bigger boxes), split across build slots, clamped `512`–`4096` | `memory.max` of each deploy's `build` cgroup leaf, which runs install, build and release; `0` leaves builds uncapped. Over the cap the leaf may swap up to `RUNNER_BUILD_SWAP_MB`, then the step is killed alone with a log naming both budgets — fleets and the runner keep serving. A Vite 8/Rolldown build of a Void app peaks around 1.3–1.5 GiB: on a box that cannot spare that in RAM the swap carries the overflow, and a box with no swap or a build that fills both still fails with the budget named. The leaf also gets a hard CPU quota (one core less than the box, split across concurrent build slots) and a low I/O weight, so a build cannot starve the runner, RustFS or SSH | runner-owned |
| `RUNNER_BUILD_SWAP_MB` | the host's swap split across the build slots, clamped `0`–`4096`; `0` when the host has none | `memory.swap.max` of each deploy's `build` leaf. The overflow past the RAM cap, so a build larger than the box's spare RAM finishes (slowly) instead of thrashing at the cap until the step timeout; the watchdog only fails it once RAM and swap are both full. Fleets keep zero swap. An explicit `0` restores the old zero-swap behavior | runner-owned |
| `RUNNER_PRESSURE_PCT` | `85` | Container memory percentage that triggers pressure parking of idle apps; `0` disables | runner-owned |
| `RUNNER_PRESSURE_IDLE_S` | `300` | How long an app must be idle before pressure may park it | runner-owned |
| `RUNNER_PRESSURE_SWEEP_S` | `30` | Pressure check interval (minimum `10`) | runner-owned |
| `RUNNER_OTEL_FLUSH_MS` | `30000` | → `CELLD_OTEL_FLUSH_MS`; bucket-flush + ingest tick cadence (min `1000`); dashboards lag ~40 s | worker-passthrough (fleet) |
| `RUNNER_DUCKDB_MEMORY_MB` | 10% of detected memory, clamped `128`–`1024` | Memory cap for every telemetry DuckDB pass (ingest and compaction); DuckDB's own default is 80% of the machine, which on a small install is larger than every resident fleet together | runner-owned |
| `RUNNER_DUCKDB_THREADS` | container cores, capped at `4` | DuckDB worker threads; the scan is short-lived, so the memory cap — not the thread count — is what keeps it off the fleets | runner-owned |
| `RUNNER_DUCKDB_TEMP_MB` | `1024` | Cap on DuckDB's spill directory (`<work_dir>/duckdb-tmp`); `0` leaves DuckDB's default (90% of free disk) | runner-owned |
| `RUNNER_BUILD_CACHE_MB` | `1024` | Per-app persistent build cache cap (package managers and their caches); `0` disables | runner-owned |
| `RUNNER_TELEMETRY_RETENTION_DAYS` | `30` | Days kept in bucket prune, metric tables, glob floor (min `1`; a non-integer or `< 1` value fails boot validation) | runner-owned |
| `RUNNER_TIP_SWEEP_S` | `60` | Fallback S3 tip sweep per app; covers out-of-band bundle writes | runner-owned |
| `RUNNER_DEPLOY_PROBE_PATH` | `/` | Pre-activation canary: after staging, the deploy asks the staged generation for `HEAD <path>` through `celld invoke` before the one activate serves it; an answer below 500 moves the pointer, anything else fails the deploy with the old generation still serving. Empty disables the probe (a celld without `invoke`) | runner-owned |
| `RUNNER_DEPLOY_PROBE_TIMEOUT_S` | `30` | Seconds the canary waits for the staged generation | runner-owned |
| `RUNNER_FLEET_LOG` | `error,celld=warn` | Fleet `RUST_LOG` (runner's own filter stays separate) | worker-passthrough (fleet) |

## Void proxy

| Var | Default | Effect | Owner |
| --- | --- | --- | --- |
| `NOITE_VOID_EMAIL_DOMAIN` | _(empty)_ | Sender domain every Void `from` is pinned to (`<slug>[+tag]@<domain>`); required for email | runner-owned |
| `NOITE_VOID_SMTP_HOST` | _(empty)_ | SMTP relay host; email is enabled iff set | runner-owned |
| `NOITE_VOID_SMTP_PORT` | _(empty)_ | Relay port; unset = `587`/`465`/`25` by mode | runner-owned |
| `NOITE_VOID_SMTP_MODE` | `starttls` | `starttls`, `implicit` or `plain` | runner-owned |
| `NOITE_VOID_SMTP_ALLOW_PLAINTEXT` | _(empty)_ | `1` allows `plain` (the proxy refuses it otherwise) | runner-owned |
| `NOITE_VOID_EMAIL_ALLOWLIST` | _(empty)_ | Admission: comma/space-separated exact addresses or `@domain` exact domains (subdomains do not match); empty fails closed | runner-owned |
| `NOITE_VOID_AI_ENABLED` | _(empty)_ | `1` turns `/ai/*` on, else every AI call answers `501` | runner-owned |
| `NOITE_VOID_AI_MODELS` | _(empty)_ | Model-map JSON for `/ai/run`: `{ "<model>": { "endpoint", "model" } }` | runner-owned |
| `NOITE_VOID_AI_ALLOW_PLAINTEXT` | _(empty)_ | `1` allows `http` model endpoints, loopback sidecars only (the runner refuses `http` otherwise; inert in multi tenancy, where loopback endpoints never boot) | runner-owned |
| `NOITE_VOID_SANDBOX_MAX_CONCURRENT` | `4` | Max concurrent live sandboxes per Void fleet (`0` admits none) | runner-owned |

Unset means email sends and AI calls answer `501`; `/revalidate` needs no operator config. Per-app credentials (the SMTP login, the AI endpoint key) are tenant Settings, never operator config — see [Void email and AI](/self-hosting/operations#void-email-and-ai). Misconfigured values refuse the boot naming the var. In multi tenancy the relay host and AI endpoints must be publicly reachable — loopback, private, link-local, CGNAT and ULA addresses, and obviously local names (`localhost`, `*.local`, `*.internal`, single-label names), refuse the boot naming the var.

## Platform-only

Set by the platform, not by operators. Railway: `PORT` (listen port), `RAILWAY_DEPLOYMENT_ID`, `RAILWAY_DEPLOYMENT_DRAINING_SECONDS` (must exceed the stop budget + 5 s). `TINI_SUBREAPER` is set by the image's init. None of these go in `.env`.
