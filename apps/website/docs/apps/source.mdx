title: Source and history
description: Browse any branch, tag or commit, read history and diffs, compare refs, and edit and commit files on any branch in the browser.

The **Code** item under an app in the sidebar opens `/apps/<id>/source`; the **App** item beside it goes back to the app's overview. Everything there reads the push mirror, which holds every pushed branch — not only the deployed one.

Code mode is a light editor: the tree and the editor read the ref's files from the runner one blob at a time, your edits live in the page, and **Push** sends them as one commit. There is no in-browser workspace, no shell and nothing saved between visits — see [Browser edits](#browser-edits) for what that means.

## Layout

Code mode has one bar: the branch picker on the left, **History** and **Changes** on the right. The files take the page, and the two panes are resizable: the divider between the file tree and the editor, and the one between the editor and the side panel. Drag one, or focus it and step it with ← / → (`Home` / `End` to take a pane to its own limit), and each split is kept in this browser — a reload or a branch switch open where you left them. **History** or **Changes** opens a side panel on the right, an even share of what the file tree leaves to begin with, and opening and closing it slides the panel (and the editor beside it) into place. The side panel keeps what each tab holds: the commit form's draft, History's page and its scroll. Below the `lg` breakpoint the panel covers the page instead.

## Branch picker

Code mode opens on the default branch (`main`), where browser edits are committed by default. The branch picker is a dropdown that lists every branch. Once the app has deployed, the first entry is the commit production is serving, by its short SHA under a **Production deploy** badge (read-only), to browse exactly what is running. The default branch carries a **default** badge in the same spot. Each other branch shows how far it is ahead of or behind `main`, and has a **Compare** link. Admins also get a **Delete** button, except on the default branch; deleting the branch you are browsing returns to the default branch, and deleting any branch also deletes its preview environment and that environment's own data.

At the bottom of the dropdown, **Create** makes a branch from the ref you are browsing and switches to it. This needs the `push` role. A create or delete publishes exactly like a push: the tip bundle and manifest are written, and `main` moving deploys.

Switching refs re-points the panes in place, rather than remounting them: the file tree and the editor stay where they are, with a small **Switching to …** marker naming the ref on its way. A switch always ends — on the new ref, or on **Could not open** with its **Retry** button. **A switch while you have unsaved edits asks first**, since the edits belong to the ref they were made on and there is nowhere else to keep them ([Browser edits](#browser-edits)).

Browsing a tag or a raw commit sha (both work in `?ref=`) is read-only. Any branch opens editable while you have the `push` role, and a commit lands on the branch you are reading ([below](#browser-edits)).

## Files and diffs

The tree lists the ref's committed files with sizes; clicking one opens it in the editor. Binary files are detected and not rendered, blobs are capped at 256 KB, and a diff is capped at 1 MB. On a branch you can edit, the tree marks every file you have added, changed, moved or deleted but not pushed yet. The editor's own header shows the open file's change the same way — the same letter (A, M, R, D) beside its name — from the same unpushed changes, so it follows a discard or an undo.

Only committed files are rows: there is no local `.gitignore` filter and no dimmed rows, because nothing untracked exists in the page. Files a clone would not show (`node_modules`, `dist`, …) are simply not part of the ref.

## Shortcuts

- **Cmd/Ctrl+F** opens find in the open file, and **Cmd/Ctrl+Alt+F** adds replace. Both are the editor's own panel, not the browser's.
- **F2** on the selected row renames it, and **Delete** or **Cmd/Ctrl+Backspace** deletes the selected rows after the confirmation ([Browser edits](#browser-edits)).

## Repository limits

The tree lists up to **5000 files**; a larger ref is marked truncated and only its first files are browsable. One commit writes at most **100 files**, **25 MB** of file contents and **10 MB** per upload, and the commit route reads at most a 40 MiB request (base64 inflates by a third).

## History and commits

The **History** panel lists the browsed ref's commits newest first: subject, author, time and short SHA. **Newer** and **Older** page through them (`?skip=`), and are hidden while everything fits on one page. With a file open, **Only `<file>`** narrows the list to that file. A commit opens at `/apps/<id>/source/commit/<sha>`, with its metadata and parents, the changed files with additions and deletions (binary files flagged), and the patch against its first parent; the link back to the files returns to the ref and the open file you opened it from, and a parent link carries them onward.

## Compare

The compare page (`/apps/<id>/source/compare?base=&head=&ref=`) shows two refs: their commits, the three-dot diff, and whether a squash merge would apply cleanly. Open it from a branch's **Compare** link in the picker, or directly (`ref` is the branch you were browsing, so the link back returns to it). The **Open pull request** button starts one from the pair you are looking at ([Pull requests](/apps/pull-requests)).

## Browser edits

Opening a file reads its committed text into the page and shows it in the editor; the first keystroke starts a change. You can edit as many files as you like: each keeps its buffer while you open others. The **Changes** button shows how many files you have changed.

Right-click in the tree for **New File**, **Rename**, **Upload files…** and **Delete**. They act in the folder you clicked (the root for the empty space below the files). A new file is named in place and opens empty in the editor, ready to type. Delete asks first; Ctrl/Cmd-click selects several rows, and **Delete (N)** removes them all after one confirmation. Git cannot store an empty folder, so there is no New Folder. On a read-only ref the tree has no menu: right-clicking says the checkout is read-only.

Drag a row onto a folder to move it there; dropping onto a file moves into that file's folder, which is how you move something back to the root. A move onto a name that already exists is refused. The open file follows its move. Moves never read file contents, so binary and large files move too. **Rename** (menu, or F2) is the same kind of change.

**Upload files…**, or dropping files and folders from your computer onto the tree, adds them where you dropped them. Text files (UTF-8, up to 256 KB) become buffers you can edit; anything else is a binary file shown by its size. Uploading onto a path that already exists is refused.

The **Changes** panel shows every change as a diff against the committed text, and lists moved files (`old → new`) and deleted files, each with a **Restore** button. **Discard** throws one change away (an edit goes back to the committed text, an added file leaves the tree); **Discard all** resets everything. Both ask first. Its form at the bottom takes a commit message (left empty, it is built from the changes — `Add README.md` for one file, `Update 3 files` when they are mixed) and where to commit — a select of the app's branches, the one you are browsing first, then the default branch, then the rest newest-first:

- **A branch**, listed by name, which is where the commit lands: `main` deploys the app and wakes it if it was sleeping, and any other branch with an environment redeploys that environment.
- **New branch…**, with a name. The branch starts at the tip of the branch you are browsing and the browser switches to it. The panel then links to a pull request into the branch you were browsing — as it does for any commit that created a branch.

**Push** sends every edit, upload, move and deletion as one commit, with a validated set of paths, and the page then reads the branch's new tip. If the push fails, the buffers and the form are kept, so you can retry; the panel shows the reason the server gave, with the common refusals (a protected branch, a branch that moved during the commit, an invalid or taken branch name, an unreachable server) written as a sentence.

**Your edits live in this page and nowhere else.** A reload, closing the tab, or opening Code mode in another tab starts from the commit, and a page reload or leave with unsaved edits warns first. Nothing is written to the browser's storage and nothing is shared between tabs. Push or discard before you leave, or switch refs after the panel asks.

- **Any branch can be edited** while you have the `push` role. A tag, a raw commit sha, or a branch you may not push to stays read-only: the Changes panel says why and what to do, and hides the commit form, so switch to a branch you can push to edit.
- **Empty repositories work**, so you can seed a blank app from the browser.
- When a branch is **protected** — `require_pr` on, you are not an app admin, and it is the default branch — its entry in the target select is greyed out and only **New branch…** pushes ([Branch protection](/apps/pull-requests#branch-protection)).

Every commit Noite writes — browser edits, merges, template imports — is authored and committed as `<your name> <your user id>@users.noreply.<domain>`, never your email.

## Preview

Previews are deployments. A branch with an environment deploys every push to its own `<label>.<slug>.<base>` host on celld, from the same build pipeline as production and with its own storage; the app's environments are listed on [Environments](/apps/environments), where they are created. A push to a branch that has one redeploys it.

Code mode has no Preview panel and no in-browser preview: there is nothing to frame that the branch's own environment does not already serve. To see uncommitted work running, commit it to a branch with an environment (or open a pull request from a new branch) and watch that deploy.
